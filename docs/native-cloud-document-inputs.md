# 飞书云文档与上传文件只读接续

适用程序：1.110.0。用户在问题中提供飞书知识库、在线文档或知识库上传文件链接时，AgentOS 先用原提问所对应的机器人身份读取节点类型，不再把它一律当作普通业务网站或个人网页登录。

## 权限与范围

- 知识库节点：`wiki:node:read`。
- 在线表格：`sheets:spreadsheet:readonly`，沿用 `read_cloud_sheet`。
- 飞书在线文档：`docx:document:readonly`。
- 知识库中的上传文件下载：`drive:drive:readonly`。

这些都是应用身份的只读权限。文档仍须实际共享给对应机器人；个人浏览器能打开，不代表机器人能读。程序不申请编辑、上传、删除、转发或修改共享范围的权限，也不使用个人账号密码替代应用授权。

四个助手分别使用自己的 profile 和权限，不混用身份。新增助手也必须逐个核验上述 scope；缺 scope、文档未共享、平台网络/响应异常和文件格式未接入分别返回 `CLOUD_DOCUMENT_SCOPE`、`CLOUD_DOCUMENT_ACCESS`、`CLOUD_DOCUMENT_RESPONSE`、`CLOUD_DOCUMENT_FORMAT`，不能统一显示成“登录失败”。

## 读取与保存

`connection`只辨别当前明确链接的节点类型和元数据。`read_cloud_document`执行以下固定只读路径：

1. 在线文档按飞书 block API 完整分页；分页令牌缺失或重复时拒绝声明完整。
2. 上传文件使用同一机器人身份下载原始字节；结构化预览支持 DOCX、XLSX、PPTX/POTX/PPTM/POTM、CSV、TSV、UTF-8 TXT/Markdown/JSON/XML/YAML。PPT 预览列出部件文本、母版/版式/主题和动画存在性，不等于视觉验收或动画兼容性确认；所有编辑部件保留在原文件。宏不执行。
3. DOCX 中的 PNG/JPEG 内嵌图片同时按原任务和原机器人登记为不可变视觉输入。若图片是在调查中途才发现，下一次源码分析使用保留的任务上下文开启一个可携带图片的新回合；模型真正接收后才记录为已看，断线或重试不会把“已登记”误当成“已看过”，也不会在已消费后反复塞图。
4. 原始文件、视觉输入或在线文档 block 证据按 job、project、tier、originProfile、token 和 SHA-256 绑定，保存为当前任务不可变附件；拒绝符号链接、越界路径、租约变化和跨身份复用。
5. 同卡后续核验或修改直接复用已登记附件，不要求用户重复上传，也不把解析成功、图片已交给模型等同于业务结论正确或最终文件已交付。

接收与解析分离：所有获准下载的上传文件均先保留原始字节和摘要。未知格式（包括 PDF、旧版 XLS/DOC、压缩包等）返回 `parseStatus=raw_only`，损坏、加密或解析失败返回 `parseStatus=failed`；二者仍登记 `fileReceived=true` 的原始附件，但 `complete=false`，不把文件接收当作内容阅读完成。后续模型按附件和对应工具处理，不能执行用户文件中的宏或指令。无需为已保存的原文件重复索取权限或上传。图片型扫描件及在线文档中的复杂嵌入对象尚未承诺结构化解析；DOCX 当前只把 PNG/JPEG 媒体登记为视觉输入，其他对象仍保留具体格式缺口，不把空提取结果冒充完整内容。新增格式解析器需单独回归原始字节、页/表/段范围、视觉输入生命周期和实际生成文件。

## 安全发布与迁移

新增运行依赖 `mammoth` 与 `jszip` 随 `package-lock.json` 固定；发布包执行 `npm ci` 后须通过 `npm audit`、定向文档测试、完整回归和干净提取包回归。runtime/data 中的任务附件、原状态和投递回执必须随迁移保留。发布仅在没有活动任务、入站、导出和待投递时进行，不停止或覆盖旧 TPM 实例。

离线合成 DOCX/在线文档分页测试只证明解析、隔离和错误分类；真实应用 scope 生效、原文件下载、业务答案和飞书原卡投递必须分别验收。
