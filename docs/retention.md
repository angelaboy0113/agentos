# 本机记录与缓存自动清理

默认保留滚动30天的本机运行记录；按最近一次实际创建、完成或业务更新计算，不按“某个自然月”。控制面启动时执行一次，此后每小时检查一次。清理时会删除数据，旧问题不再可从本机管理台检索或恢复；飞书服务端消息/历史卡片仍按飞书的保留策略存在，不会撤回。

## 配置与检查

在启动AgentOS的环境中配置（默认值如下），修改后在无在途工作时重启控制面及配套Runner：

```dotenv
AGENTOS_RETENTION_ENABLED=true
AGENTOS_RETENTION_DAYS=30
AGENTOS_RETENTION_INTERVAL_MS=3600000
```

这是保留期限，不是任务耗时限制，不会因任务执行超过30天而中止执行。自定义部署可在controlConfig的retention传入enabled、days、intervalMs；只有明确的false关闭，天数与检查间隔必须是有效正整数。启动失败应核对配置，不静默采用另一个期限。

在你的AgentOS程序目录运行只读预演（Windows PowerShell和macOS均适用，Node22）：

```text
node scripts/retention-preview.mjs --data-dir "你的AgentOS数据目录"
```

预演只输出预计删除数量、受保护数量、状态JSON清理前/后估算字节，不删除记录或文件，不含原问题/业务数据。实时任务和文件投递可能使正式清理数量不同。`GET /health`的retention提供enabled、days、intervalMs及本次启动后的last（清理时间、cutoff、计数、文件字节、各缓存结果）；最近清理摘要也保存在agentos.json.retention.lastCleanup。清理失败显示RETENTION_FAILED，已完成部分保留效果，未完成部分下轮重试，不影响正常查询授权。

## 自动清理范围

- 已完成、失败、受阻、取消的过期任务，以及关联问题、已发送对话、卡片/文件投递状态、消息去重映射、旧Runner记录、已过期控制请求回执、回调诊断和本机设置审计。
- 无保留任务引用且实际文件时间已过期的`exports/<JOB>/`（含CSV和datasets）、`attachments/<JOB>/`、联系人PNG及回执、`lark-cli/reports/`和`images/`副本、`lark-cli-events/<profile>/messages/<messageId>/`资源、已轮转日志，以及旧`agentos.json.<PID>.tmp`残留。只扫描明确的托管路径与文件名，遇到符号链接不跟随、不删除外部目标。
- `memory.json`中的过期个人摘要/失去来源的摘录，已删除来源的遗忘引用；摘要按自身更新时间及实际来源时间核对，不将未知来源当成新内容。
- `codex-conversations.json`中已过期、没有仍在处理请求的本机线程索引，及对应空闲内存会话；这里不删除用户全局`~/.codex`中的会话文件。
- 团队知识SQLite按最近核验时间删除超过30天的所有状态版本（含active），清理检索索引、捕获记录和内存热点；通讯录SQLite删除超过30天未刷新的目录索引。读取/命中不会刷新知识核验时间；后续需要时重新核实或重建。SQLite实际删除后VACUUM回收空闲空间，不删除整个数据库。小型聚合计数保留，不含问题正文。
- 联系人进度记录、旧Runner心跳等内存副本随期限释放；状态JSON原子换版会替换旧缓存。Node随后正常GC回收对象，不强制承诺RSS立即下降，也不把清理机制当作所有内存泄漏已解决。

## 必须保留的例外

正在排队/执行/取消、待审批、待澄清及未知状态的任务，非终态对话、尚有租约的任务，正在发送的卡片/文件、进行中的控制请求和知识提炼受保护。沿实际ID、问题/任务链、父问题和消息引用保留必要依赖；较新问题引用较早结果时，必要旧结果可超过30天。保存的本机执行登记尚未解除时也保留其任务文件，不凭时间猜测工作进程已退出。活动依赖不再需要后，后续检查才可清理。

配置、凭据/Keychain、业务源码、Git工作树、analysis-sources源码快照、网站登录会话、待送达pending-card-actions、正在写入的stdout/stderr日志、人工备份不在自动删除白名单。它们由各自运维流程管理；本机运行记录清理不等于删除所有磁盘数据。待送达回调不可通过删文件冒充已处理；工作树不可按日期删除未提交业务改动。

历史效果/提示去重记录没有时间字段时，以首次被清理服务观察到的时间开始保留30天；不猜原始发生时间。坏时间的任务等记录保留待维护，避免误删；这类异常和活动引用是期限例外。

## 并发、恢复与迟到请求

状态清理进入唯一JsonStore事务队列，与创建任务、领取租约、回复登记串行。文件先扫描，再在同一状态写队列内复查当前引用、路径真实位置、符号链接及最新时间后删除，避免把新任务刚引用的旧文件移走。没有全目录递归清空，也不调用模型或生产数据库。内存/SQLite/线程索引分别使用已有队列或事务；清理周期单飞，关机时停止新周期。

配套Runner在每个持久状态POST中发送不可变的`x-agentos-request-created-at`（ISO时间），重试使用同一请求ID、正文和时间。控制面对于未知且超出本机保留期的请求返回410，缺时间字段返回426，要求升级Runner；不将已删除回执当成新操作再次执行。现存进行中的请求/回执继续原有恢复与租约核验，不添加任务总时限。显式包含创建时间的陈旧消息事件会被忽略；无时间字段的旧接口事件不能猜测年龄，现有事件去重规则仍适用。

## 上线与验证

初次启用前运行预演，确认无真实在途工作，按部署流程保存一次受控回滚备份。备份由维护者另行管理，不属于运行缓存；不要将备份、状态或导出正文提交到Git或手册。正式启用后核对health.retention.last、旧记录删除数量、近期任务/配置/执行状态及两SQLite完整性。恢复备份时先停控制面及Runner，并临时禁用保留策略，否则启动清理可能再次删除备份中的过期记录。

回归覆盖过期边界、活动链/消息父引用、待处理请求、路径/符号链接、实际SQLite回收、个人摘要和线程索引、单飞、只读预演及本机HTTP迟到请求。macOS已进行安装目录与现场清理验证后才可宣称该部署生效；Windows需在目标部署验收文件占用/删除权限，不能仅凭单元测试声称实际运行通过。
