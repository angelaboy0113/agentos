# 飞书动态执行卡片

用户确认范围：参考原生 Codex 执行卡片，重新设计聊天回复并显示真实执行动态；不更换模型、认证或任务权限。

- 普通对话：超过 3 秒显示蓝色处理卡；同一条消息更新为最终回答。短对话直接显示结果卡。排队、连接重试均如实显示。
- 实际任务：每个任务执行尝试一张卡，由对应角色机器人发送。当前操作为主焦点，下方展示耗时、实际工具调用次数、最近 3 项完成记录。完成、待确认、需补充、失败使用不同语义状态，不把阶段结束当作全项目验收通过。
- Card 2.0，默认宽度适配手机，12px 留白；所有角色终态首屏显示独立 summary（2–4 句，最多360字），详情默认折叠并在同一卡内分页。禁止自动纯文本续发长报告；原 finalMessage 保留，不丢弃证据。
- 来源仅为 Codex JSONL 的工具开始/结束事件和 Runner 验证状态，不公布 reasoning、原始 stdout/stderr、工具参数或凭据。常见固定验证命令可显示，其他命令只展示类别，避免命令中夹带密码/数据。
- 每张卡串行更新，进度最多约每 3 秒一次；结束优先刷新。消息 ID、目标机器人身份、最新内容和重试状态持久化。发送使用稳定幂等键；更新失败只重试投递，不重新执行 AI 或任务。
- 群聊终态卡成功投递后，另用原生文本回复原消息并 `@` 对应提问人。任务只在最终完成、受阻、失败或取消且没有后继 Job 时提醒；使用原任务的 `originProfile`、`senderId` 和不可变 `originMessageId`，避免补充消息或跨应用交接覆盖原发起人和原消息。提醒与卡片共同进入持久化 outbox，使用稳定幂等键；提醒失败不重发卡片、不重跑 Codex。
- 不显示虚假百分比。任务卡增加状态驱动按钮：刷新状态、停止/取消、真人批准下一阶段、填写并提交补充信息。普通对话不产生开发任务按钮。

## 交互约束（2026-09-05 用户确认）

- 回调通过各机器人独立身份的 `card.action.trigger` 长连接进入本机认证接口；需要每个应用在飞书后台启用「卡片回传交互」。消费者 ready 不等于后台已配置，真实点击才能验收外部链路。
- 按真实 message_id、群、机器人 profile、执行尝试版本匹配本地已发卡片；不信任按钮里的任意任务编号。审批仅真人管理员；停止/补充为该身份下的任务发起人或真人管理员。不同应用 open_id 不混用。
- 事件 ID 幂等、状态变更原子检查；旧卡及重复操作不得重复推进。补充重新排队当前阶段，不跳过审批，旧卡标记已提交，不重复运行旧结论。
- 运行中停止先进入 cancelling，Runner 通过租约绑定的控制轮询得知取消，终止本任务创建的子进程树（含验证命令），退出后才确认 cancelled。只停止自己的进程，不杀其他 Codex，不回滚已修改文件。无法确认退出时保持停止中/提示错误，不宣称停止成功。
- 排队及等待输入/审批的取消直接结束，不再被领取；迟到的完成、日志、旧租约不得使已取消任务复活。执行租约过期不再盲目重新排队，防止旧进程与新尝试并发写代码。
- 回调仅变更任务状态，不调用 AI 推断按钮含义。后台业务操作成功后由持久化卡片投递机制更新同卡；消息更新故障不重放业务操作。

验收：普通对话更新同卡、多个角色不串卡、执行事件去重计数、失败不显示成功、终态不被迟到进度覆盖、更新失败可恢复、超长文本不丢失、敏感命令/推理不外发；本地测试不得冒充真实群聊端到端验收。

## 统一结果展示（2026-09-06）

- 根因：原发送器按3500字符截断卡片后，将剩余 Markdown 作为普通文本续发；摘要仅取前850字。开发及负责人汇报均走此公共链路，其他角色也受影响。
- 通用布局：角色与状态标题 → 简短结论（含未验证/阻塞项）→ 耗时/调用数 → 默认折叠的完整详情；执行中仍展示真实最近动作，终态不重复堆工具记录。保留原审批/取消/补充按钮与权限。
- task-result.schema.json 增加 summary；共享执行提示词规定大白话结论、风险及下一步，负责人不得复制开发全文。旧结果没有 summary 时仅作有界摘录，不伪造AI摘要。
- 详情 result_page 按页更新原卡，无 Codex/任务执行；只允许原应用身份下发起人或管理员，校验群、消息、终态、内容版本、已发布按钮及页码。回调幂等，展示事务与重试不改变 Job；共享卡翻页对群内其他读者也可见。
- Markdown 本地文件链接变为可读文件/行号标签；移除冗长机器路径；兼容旧HTML转义，安全处理@标签；代码围栏跨页补齐。原始证据保留在本地任务结果中。
- 重启后不续发旧 outbox 的纯文本 overflow；不撤回已经发送的旧消息，也不自动重跑旧业务调查。新任务和新聊天使用统一格式。
