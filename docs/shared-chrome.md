# macOS 日常 Chrome 登录态复用

## 配置与使用
Mac 默认 shared-chrome 后端，使用 Apple Events 接管日常 Google Chrome 的对应应用页面。不复制 Cookie、不读取页面里已有的密码值、不打开远程调试端口、不关闭或重启 Chrome。登录过期时可以本机手动登录，也可以由网站负责人直接回复等待登录的任务卡，授权固定程序填写。其他平台默认 isolated；设置 AGENTOS_BROWSER_MODE=isolated 并空闲重启可恢复独立 Playwright 浏览器。

激活日常 Chrome，从 Mac 屏幕顶部选择“查看 → 开发者 → 允许 Apple 事件中的 JavaScript”。全屏时把鼠标移到顶部。系统首次询问运行 AgentOS 的宿主可否控制 Chrome 时，由本机使用者确认。该开关允许获准本地自动化程序执行网页 JavaScript，应只对信任的程序开启。未就绪返回 `BROWSER_BRIDGE`，不应解释成网站账号无权限。

macOS 会分别判断前台终端/Codex 与后台 LaunchAgent 的 Apple Events 授权。用户已经在日常 Chrome 登录业务网站，只能证明 Cookie 和账号会话有效，不能证明后台 AgentOS 已获准控制 Chrome。macOS 自启脚本把服务限制在当前用户的 Aqua 图形会话并标记为 Interactive；升级后需要重新执行 `./scripts/install-autostart.sh` 使 plist 生效。若系统再次弹出自动化授权，应在本机允许。任务此时显示橙色“等待本机浏览器授权”，不会标红结束；桥接可用后轮询器自动恢复原问题和已有证据，无需重新登录网站或回复“继续”。

登录管理控制台后可调用 `GET /api/v1/admin/browser-health` 做最小健康检查。成功只返回 Chrome 是否运行及窗口数量；失败只返回 `BROWSER_BRIDGE`，不会读取或展示标签页正文。

## 执行与权限
环境计划批准后才接管。每个命令重查任务授权，按完整入口匹配 origin 和应用路径；不读取无关标签页正文。每任务固定一个标签，多个任务不共享活跃标签，操作串行。找不到匹配页时在日常 Chrome 当前窗口新建已批准入口；多 profile 用户宜先在目标 profile 打开业务页面。任务结束不关闭用户页、不退出浏览器。人为切到范围外页面时拒绝读取。

提供脱敏可见正文及筛选后的查看、搜索、分页控件；对于没有单独“详情”文字、而是由稳定 `data-row-key` 承载跳转的常见数据表，整行会以“行详情”只读引用开放，模型可继续钻取已有记录。不读取 Cookie、localStorage、密码输入值及隐藏 noscript 提示。工具使用固定脚本，不接受模型脚本。引用按任务和快照隔离，控件标签或链接变化时失效。包含保存、删除等写入文字的行不会开放，写入按钮及跨应用链接同样不开放。受控只读页面查看自动授权，登录态不会扩大项目、环境或写操作权限。

## 任务卡凭据登录

当原问题卡显示“等待网页登录”时，卡片会同时写出当前缺少登录的网站完整入口。当前网站环境在对应机器人 profile 下配置的负责人直接回复该卡片或同一问题话题即可，例如：

```text
admin / 123456
```

也支持 `账号：… 密码：…`、空格、换行、斜杠、逗号等常见写法，不要求记住命令模板。任务卡或同一话题是网站归属依据；没有回复等待登录卡片时，群消息不采用无标签的“两个值”猜测。控制面在普通对话入库和模型处理之前识别该消息，先按飞书事件中的 mention 元数据去掉机器人显示名与 mention key，再解析账号密码，避免把 `@项目负责人` 等称呼写入账号。随后核对发送人、机器人 profile、待登录任务及网站范围，将凭据写入当前 Mac 用户 Keychain，再用固定登录脚本填写账号、密码并提交。模型不能选择字段、读取凭据或调用这一入口。成功后原问题自动继续；以后会话失效时可从 Keychain 自动尝试一次，不反复提交错误密码。新凭据覆盖该网站原凭据。

群聊回复正文对群成员可见，并受企业飞书消息留存策略管理；AgentOS 不声称删除飞书服务端记录。AgentOS 本机不会把正文写入任务、模型上下文或长期记忆，也不会在回复中复述账号密码。部署团队若不允许在群内出现共享凭据，应继续本机手动登录。提交后若页面仍显示账号密码输入框，任务明确提示账号或密码可能未通过；只有同源认证页已不再显示密码框时，才提示验证码、短信或扫码。硬件密钥、强制改密和复杂跨域 SSO 不会绕过，页面出现这些步骤时由负责人在本机 Chrome 完成。

凭据只用于当前已登记网站环境的认证，不授权读取其他标签页，也不开放保存、修改、执行、审批等业务操作。只有 `ownerOpenIdsByProfile` 中当前网站环境的负责人可以提交；普通成员即使知道账号密码也不能替换共享网站凭据。

## 与独立浏览器的区别
日常 Chrome 正常加载网页请求，不再全局拦截登录、菜单或权限初始化。此模式不是网络层只读沙箱：控件筛选不能证明网站自身事件处理器无副作用，也不能隔离同一 profile 的后台网站行为。要求严格网络拦截的部署应选择 isolated；本次没有扩大 AgentOS 保存、删除、提交或执行任务的权限。

此后端仅支持 macOS Google Chrome。Nacos 专用配置读取浏览器不走通用网站后端，本变更不迁移其登录态。仅读取顶层应用，跨域 iframe 或复杂自绘控件仍可能不可读。

## 排障与验证
BROWSER_BRIDGE 检查 Chrome 是否运行、Apple Events JavaScript 开关和系统自动化权限；BROWSER_SCOPE 检查是否关闭或离开原应用。网站可见 no-access 保留为事实，但不能仅凭它认定账号权限根因。

测试使用模拟传输和本地页面，覆盖授权重查、独立标签关联、过期及跨任务引用拒绝、带稳定行键的表格详情、写入及跨域控件过滤、可见文本、密码不读、任务卡归属、负责人校验、机器人 mention 清理、自然格式解析、Keychain 适配、固定登录脚本、登录表单拒绝与二次验证分类。模拟测试不代表真实业务账号接通；每台机器仍需启用系统权限后只读验收。没有向业务群发送测试凭据或点击业务操作。
