# 卡片回调兼容与过期查询恢复

## 入口与行为

点击已发送卡片的批准、刷新、取消或详情翻页按钮，控制面根据本地持久化的卡片消息ID、机器人profile、群、操作者、当前任务及按钮版本校验。CLI返回的`card_content/user_dsl`是可选展示信息，不作为授权凭据，也不因其为空丢弃有效点击。

没有本地卡片记录、跨群、跨profile、身份不符或旧按钮版本仍不放行。详情翻页同样校验本地版本与身份，不执行任务。普通发起人可刷新和重新申请；批准仍由该环境负责人完成。

## 申请过期

等待批准期间到达`expiresAt`，后台调度刷新已发送卡片，展示“查询申请已过期”和“重新申请本次查询”。手动刷新也按当前时间重新渲染。点击旧的批准按钮不会延长授权，会更新卡片并提示过期。

“重新申请本次查询”只在申请已过期、任务仍待审批、环境配置指纹未改变时创建同一环境/模板/参数的新申请；有效期按现有15分钟规则生成。清空批准人，保持待审批，随后必须核对新卡并再次批准。不会借发起人或管理员身份自动执行。配置改变时要求重新发起排查，不能悄悄采用新范围。重复回调保持幂等，旧版本不能批准新申请。

## 观测、存储与升级

`data/agentos.json`新增`cardCallbackAudit`，最多保留最近200次处理记录：时间、profile、事件/卡片ID、是否带有卡片内容、accepted/ignored/rejected/delivery_failed及原因。不保存Token、原始卡片内容或表单正文。审计是本机排障数据，不进公共仓库。

正常动作失败在已验证的原卡关联上下文提供提示；未知卡片等不可信回调只留本地记录，不向不明目标发消息。HTTP/投递失败仍沿用持久队列重试；业务变更按事件幂等。

无需新配置。更新代码、运行`npm run check`后，在无执行中任务时重启。待审批任务应保留；启动后的调度会更新过期卡片，不批准或执行它们。涉及本地数据修改应先备份。Windows/macOS使用同一业务逻辑，本次只在Mac进行部署验收。

## 验收

回归覆盖空`card_content`下刷新、取消、续期、批准与幂等；未知卡、跨身份/群/profile和旧版本拒绝；过期卡刷新不续期；重新申请不批准。真实验收还需在群内点击“刷新状态”，确认卡片变化与accepted审计一致；如需验证执行，应由真人另行批准真实查询。测试通过不代表已完成真实按钮验收。
