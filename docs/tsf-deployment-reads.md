# TSF 部署与运行版本只读调查

用途：核对当前应用的部署记录、成功或失败状态、部署组配置版本及实际运行容器镜像。与 CNB 构建历史、固定提交源码一起关联，回答发布内容和当前版本；不执行构建、发布、回滚、重启、扩缩容或写业务数据。

## 配置与使用

维护者在 `config/environments.local.json` 登记 `kind: "tsf"`，参考 [配置示例](../config/tsf-deployment.example.json)。`tsf` 固定 HTTPS 登录、控制台与 API 来源、主账号 ID、区域及平台时间的解释时区；`credentialRef` 指向本机加密凭据库。不要把密码写入配置或 Git。每个项目、环境单独登记 `queries.investigate.applications` 的实际应用 ID、名称、部署组和命名空间 ID。目录返回的配置不是线上证据。模板按原环境审批和成员读取规则授权，不因同一云账号能看到全部应用就扩大模型范围。

按实例维护流程，在用户任务、接待、文件和消息投递自然空闲时备份并重启。无需新增机器人；工具通过现有环境目录、批准计划和查询执行器暴露给助手。登录过期时用已保存凭据恢复，只重试当前幂等读取；验证码/MFA、明确认证拒绝或协议变化保留具体错误，不循环提交登录或要求用户重复提问。

工具流程：

1. `applications` 查看配置范围，`connection` 核对认证。
2. `groups(applicationId)` 读取全部已授权部署组；实时核对命名空间。配置组缺失明确列出，不用旧版本代替。
3. `deployment_history` 指定完整的当地时间起止（`YYYY-MM-DD HH:mm:ss`），按 `nextOffset` 读完所需范围。空起止不能交给平台隐式默认，以免错误返回空记录。示例与实测配置单页20行（可由维护者按实际接口支持配置页大小），分页没有整个任务的行数、次数或耗时截止；`sourceTotal` 是该应用原始页总数，`excludedByScope` 表示本页排除其他部署组的条数，不能将原始总数当作本环境总数。
4. `current_version` 核对部署组配置镜像和副本状态；`instances` 读取真实 Pod、各容器镜像标签和摘要。区分业务容器和 sidecar；多副本版本不一致不能选一个冒充全部。
5. 关联镜像构建号、提交或其它权威映射，再与 CNB 构建记录、对应提交源码比较。镜像标签包含短提交不代表所有部署均采用这种命名，不能凭外观补造映射。

## 时间及完成语义

- `TaskTime` 在该接口的控制台展示为“变更时间”，和成功状态一起作为成功变更记录时间。接口未提供独立精确完成时间时，`exactCompletionTimeAvailable` 为 false，不能改名为精确完成时间。
- 部署组 `UpdatedTime` 是配置更新时间，Pod `CreatedAt` 是 Pod 创建时间；二者都不自动等于整次滚动发布完成时间。
- 构建成功、历史成功、组配置及当前实例是不同证据。输出应说明已确认的版本、观察时点、成功记录和未提供的时间精度，不因没有精确结束秒数就丢掉其它已确认结果，也不能把有缺口的部分宣称全部完成。
- 各请求保留 `fetchedAt` 与配置时区，不冒充同一事务快照。时间格式、跨月、闰日和无效范围由工具校验。

## 权限与数据边界

执行器只实现四个 TSF 原生读取动作：`DescribeContainerGroups`、`DescribeContainerGroupAttribute`、`DescribePodInstances`、`DescribeContainerTasks`。虽然云 API 的传输方法是 POST，这些动作均为查询；模型不能选择 URL、HTTP 方法或动作。登录 POST 单独用于正常子账号认证。

只返回明确字段投影；丢弃环境变量、YAML、访问凭证、日志、镜像认证和任意嵌套配置。账号本身可能有管理权限，`accountReadOnlyVerified:false` 如实保留，程序通过固定接口和范围执行只读。每次动作重新验证批准计划，获取实例前重新核对组与命名空间；跨应用、跨环境、已移动或不可见部署组拒绝复用。

原始工具结果投影后存入当前任务的 `tool-results`，跨阶段和重启用 `list_tool_results` / `read_tool_result` 复用，保留取证时间，不能把历史证据称为新鲜运行状态。迁移随任务数据和加密凭据库一起保留，不把真实配置或任务数据放入代码包。

目前适配的是容器应用。未登记的虚拟机部署、发布计划流水线及精确 rollout 结束事件不能据此声称已接通。增加其它平台时也应提供审核动作、范围验证、字段投影及时间语义，不复制某个项目业务规则。

## 验证与故障处理

用合成接口验证多系统/环境并发隔离、组移动、分页缺页、混合版本投影、登录恢复、撤权和结果保存。真实平台验收需逐环境读取一组实际当前版本、运行实例和完整历史页，再用真实用户原题检查目录发现、证据关联、原卡表格、投递与完成提醒。测试主题标明维护自测，结束无论成功失败均撤回；离线通过不等于原题或性能通过。

`TSF_AUTH` / `TSF_LOGIN_PROTOCOL` 表示认证或协议；`TSF_SCOPE` 表示实际范围变化；`TSF_NETWORK` / `TSF_HTTP` 表示连接；`TSF_API` 保留安全平台代码和具体只读动作；`TSF_PAGINATION` / `TSF_RESPONSE` 不把缺页当无部署。已有证据保留，修正后原任务接续。macOS 本机已验证范围以部署记录为准，未经实测的其它操作系统和完整迁移应单独标注。

## 同任务跨来源接续

TSF 投影结果按原环境指纹保存在任务自己的 `tool-results`，返回目录保留 applicationId/groupId。切换到同一项目、同一运行分级的 CNB 等来源后，`list_tool_results` 可列出这个任务以前已交付的引用，`read_tool_result` 可恢复原始投影；每次读取校验当前配置指纹、任务目录边界、内容摘要及来源范围，标注 provenance。配置删除或变更、不同任务、不同系统或测试/生产结果不会因此隐式共享。旧文件兼容，但仍须同时通过任务历史引用和实际文件指纹核对。

该路径只读取已保存证据，不重新调用 TSF，也不把历史结果当实时刷新。模型无需把21个镜像清单反复转述给源码阶段再搬回 CNB。多应用的已知独立参数可用现有 `batch_read` 或 `execute_read_plan` 一次规划；仍逐项授权和执行，失败保留成功项，不重放成功查询。只新增固定只读平台工具到批量目录，不加入部署、回滚、重启或触发构建。

完整迁移应保留任务 context 的结果目录、来源指纹和 exports/JOB/tool-results 文件，两者缺一不能声称结果可恢复。本功能已做隔离跨来源执行器回放；真人同题最终结果与耗时须以部署后的维护记录为准，不由回放推断提速比例。

## 平台限流恢复

批量计划不代表平台没有频率限制。固定元数据 GET 语义的 TSF POST 读取遇到 HTTP429 或 RequestLimitExceeded 时，按原动作和原参数退避重试，最多增加三次尝试，等待1/2/4秒并尊重 Retry-After；相同公司云账号共享冷却时间，但登录 Cookie 仍按项目/环境隔离。等待前后重新校验原授权，登录本身、权限错误、参数错误、业务写入和模型执行不自动重放。成功结果的 readRetries 明确记录恢复次数。

Retry-After 超过现有单次读取窗口或仍持续限流时，返回独立 TSF_RATE_LIMIT 分类，保留先前成功结果并提示只接续缺失读取；不终止整项问题、不缩短取数范围、不把限流说成凭据失效。没有新增整任务耗时或工具总数截止。

## 按部署来源发现数据库目标

维护者可在已审核TSF查询模板中增加`configurationApplications`，内容必须是该模板applications的子集。不配置则不开放。模型可调用`data_sources(applicationId, groupId)`，程序先核实实时部署组及命名空间，再完整分页读取该组当前已发布配置，只读取这些配置ID并前后复核发布绑定。结果只包含配置ID/版本/发布时间/摘要及MySQL主机、端口、库名；原始配置、用户名、密码、令牌不会进入模型、任务或日志。支持properties、YAML及平台base64编码；重复冲突、缺失引用和并发发布不能被当作有效单一目标。

发现地址不等于账号只读、连接成功或新增数据授权。缺少数据库入口时先使用已登记同系统/环境的配置发现能力；将真实目标交给受控接入准备，由维护者确认范围、将凭据存本机加密库并验证原传输通道，再登记数据库。不得让模型自行连接新地址或扩大TPM/其它系统权限。共享配置/环境注入未覆盖时明示缺口，不把空发现说成没有数据库。配置读取不包含修改、发布、回滚、运行环境变量或日志。
