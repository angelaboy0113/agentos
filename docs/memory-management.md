# 可追溯记忆与项目台账

**模式说明：本文描述兼容模式。** 开启 `conversation.local.json` 的 `groupSessions` 后，群受理采用 Codex 原生持久会话，不再调用本文摘录摘要链；私聊不变。详见[群共享会话](group-question-cards.md)。

实现版本：`scoped-extractive-memory-v1`，2026-09-15。当前交付第一期：近期上下文预算、持久摘录摘要、相关历史检索和台账入口。**不是无限上下文，也不是自动发布长期偏好/团队规范。**

## 用户会看到什么

超过近期窗口的消息不删除。用户问起旧问题时，AgentOS 会在当前项目、群、机器人和提问人范围内检索已发送的历史对话及关联终态任务，把来源、当时时间、结果缺口和版本证据提供给聊天模型。回答准确率仍依赖模型与检索匹配，不能保证找全；含糊的“那个事情”可能需要澄清。

正式规则仍由管理员维护 `config/roles/`、`config/harness.json` 和项目版本化规范，权限仍由程序核验。“以后记住”不会自动授予权限或发布团队规则。跨机器人同人共享、自动偏好提炼、候选知识审批、语义向量检索和自然语言删除入口尚未实现。

## 一轮消息的执行链

1. `ConversationService.buildInput` 读取当前 `agentos.json`，实时解析身份、绑定项目和任务状态。
2. `MemoryService` **先过滤可见性再排名**。会话范围为 projectId + chatId + profile + senderId；关联任务经原发起消息和原 profile 匹配。管理员不因身份而看到其他人的个人摘要。
3. 从原记录按本轮问题检索：英文/编号词项和中文双字 n-gram，按命中词长度加分，分数相同取较新项。第一版每次读取可见原记录，不维护第二份全文索引，没有外部向量服务。
4. 读取 `data/memory.json` 的持久摘录摘要。首次使用、摘要来源发生修正/删除、累计新增记录达到阈值、或近期文本超预算时刷新；每条摘录最多600字符，最多12条，保存来源 ref、SHA-256、记录时间与证据属性。接单回执不入摘要，但仍可作为历史对话检索，带 receiptOnly 标记。
5. 摘要是最近来源的**限量原文摘录**，不是模型做出的完整语义压缩。旧记录即使滑出摘要，仍可被问题检索；没有额外摘要 AI 调用、后台业务 Job 或通知。阈值名 `summaryEveryTurns` 兼容“轮次”的使用习惯，实际计数包含已发送对话和关联终态任务；新增记录下一次对话读取时整理。
6. 上下文打包保留当前输入、实时权限及规范，依次裁剪旧近期消息、旧任务、摘要和检索项。当前输入本身过大时报告调用失败，不悄悄截掉授权条件。
7. 启用记忆时每轮新建临时只读 Codex 线程，从受控上下文包接续，避免复用线程残留过期权限或停用资料。仍复用 app-server 进程。关闭记忆时保留原线程复用路径（最多20轮）；这不是记忆保存年限。
8. 决策仍走现有 typed action 和管理员门禁；需要当前源码/台账事实时创建新的 analysis，由 Runner 同步后只读调查。

## 配置与预算

复制 `config/memory.example.json` 为 `config/memory.local.json`，按需修改，空闲时重启整个本地服务。文件不存在时使用以下默认值；错误类型或不合理预算会阻止启动，不能静默忽略。可通过 `AGENTOS_MEMORY_FILE` 指定配置位置。

```json
{
  "enabled": true,
  "recentTurns": 20,
  "summaryEveryTurns": 10,
  "summaryItems": 12,
  "retrievalItems": 8,
  "historyBudgetTokens": 12000,
  "inputBudgetTokens": 24000,
  "systemReserveTokens": 6000,
  "outputReserveTokens": 4000
}
```

20是近期对话软上限，不是历史保存上限。预算使用保守的 UTF-8 字节计数作为 token 估算，**不是实际 tokenizer、模型窗口探测或 Codex 内部压缩阈值**。输入总配置预算24000，预留系统6000、输出4000及统计元数据512；派生历史最多12000估算单位。更大的长问题可能被拒绝，需要拆分。模型系统上下文/图片的实际消耗并不由这个文本估算精确覆盖；不能据此承诺不会达到模型限制。

## 存储、重试与降级

- `agentos.json` 仍是唯一业务真源，本功能不删除或改写历史记录。JSON原子写不等于支持多个服务进程并发写；仍只运行一个 AgentOS。
- `memory.json` 是派生摘要缓存，独立版本1；`scopes` 保存每个范围的来源指纹、条目与更新时间，`tombstones` 预留来源停用记录。缓存文件权限0600（Windows需用部署用户ACL保护）。不得提交Git或发到公共文档。
- 当前范围内写操作串行，先原子替换缓存成功，再推进摘要来源指纹；失败下次请求重试。直接从持久原记录重新检索，因此崩溃恢复无需回放任务、审批或消息。没有两个数据库的假原子事务。
- 缓存损坏/读写失败时保留原文件，不覆盖潜在停用记录；该轮不加载历史对话或旧任务，仍保留当前问题及权限。`memoryStatus=degraded`，模型应说明不能核对旧历史。修复磁盘/权限或从可信备份恢复后，下次读取自动重试。
- 内部 `forget` 提供持久来源停用与关联摘要失效，测试覆盖重建不复活；目前没有面向用户的操作入口，不宣称聊天“忘记”已落盘。关闭增强记忆回到原近期上下文路径，原始数据仍保留；不等于数据删除。
- 首版按请求扫描可见历史，CPU和读取量随记录增长；尚未做大规模负载/中文语义召回评测。没有声称“所有历史已搜索完整”的接口承诺。

## 台账怎样进入调查

在 `config/projects.local.json` 的单个项目对象中配置 **明确的相对文件路径**：

```json
{
  "repoPath": "/absolute/path/to/your/project",
  "knowledgePaths": [
    "AGENTS.md",
    "progress.md",
    "docs/spec/project.spec.md",
    "docs/decisions/index.md",
    "delivery-ledger.xlsx"
  ]
}
```

不要把这个片段覆盖整份配置；保留管理员、身份映射、群绑定、分支和验证命令。`knowledgePaths` 可为空；缺省为前三个入口。最多12个，不支持glob和目录递归。允许 md/txt/xlsx，禁止越界路径、凭据目录、私有配置和指向项目外的符号链接；每文件最大5MiB。文字入口最多2000字符，Excel只提供路径、大小、SHA-256和 `contentLoaded=false`，**不自动解析单元格**。

执行链：Runner 完成 `sourceSync` → 在真实工作区只读读取入口 → 将文档摘录/元数据提供给开发分析 → 开发按问题读取相关过程记录、Spec、ADR或Excel → 对照源码/分支/提交 → 负责人汇报。Excel必须有本机可用的只读解析工具，读不了要报告缺口。结果 `ledgerEvidence` 保存入口哈希、读取时间和仓库上下文，不保存整份摘录。

入口文件的哈希是本次本地内容身份，不证明它被Git跟踪、已同步或部署；分支/commit只是所在仓上下文。仓外/缺失/过大的入口带 unavailable 原因。台账缺失不自动把所有问题阻塞；核心证据不足仍按现有 blocked/partial 门禁处理。提示词要求引用台账不等于模型每次都正确读取，需用真实任务检查证据。

分析不写台账、不推送、不访问有副作用的外部同步接口。当前不自动读取飞书远端台账；需另行配置可用工具与文档授权。

## 发布与验证

1. 先 pull，保留本地修改，`npm run check`。
2. 对历史做只读预检：`node scripts/memory-check.js [你的data目录]`。只输出数量、范围数与SHA-256，不输出内容或身份，不写缓存。脚本本身不要求服务停止；运行中的摘要数字只是快照。
3. 部署时确认无在途任务，停稳服务；保存 `agentos.json`、已有 `memory.json` 和 local 配置只读副本，记录SHA-256、Job/Conversation/Mission/卡片数量与ID集合。不要手工改状态文件。
4. 启动单一实例；增强记忆在各范围第一次对话时按需构建，无需导入/重播历史。`/health` 应有 memoryPolicy=scoped-extractive-memory-v1；首次检索后memoryStatus应为ready。
5. 对比备份与启动后的原记录ID/数量；确认消费者无重复。真实群测试旧问题追问、跨20轮与重启接续、当前源码重新调查、普通成员权限、台账证据与最终@。不要用单元测试替代这些验收。

回归包括50轮及重启检索、范围隔离、源码版本与partial缺口、批量刷新/来源纠正、停用与缓存损坏、并发重试、输入预算、恶意历史越权、台账路径/链接边界和Excel元数据标识。现有同步、审批、卡片和提醒回归一并运行。
