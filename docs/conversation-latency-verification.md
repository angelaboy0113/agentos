# 对话延迟修复验证 · 2026-09-05

## 根因证据

- 原实际问候：从入队至 AI 完成约 124.0 秒；其后飞书发送约 1.33 秒。旧实现还存在每条消息启动独立 CLI、等待进程关闭、所有角色全局串行的问题。
- 同机独立 Codex 测试出现 `Reconnecting... (request timed out)`。禁用桌面 MCP 后仍出现，因此不能把 120 秒 MCP 启动设置认定为根因。
- 官方域名无凭据 HTTPS 直连：15 秒超时，TCP 尚未建立；通过已运行 VPN 的本地代理，约 1.24 秒得到 HTTP 响应（未登录网页为 403，这里仅证明网络连通，不证明账号权限）。
- 同模型、同 ChatGPT 登录，通过已验证出口的 Codex app-server 问候：首轮 4.431 秒，连续第二轮 2.412 秒，无连接重试。

## 最终实现验证

`scripts/smoke-ai-conversation.mjs` 使用虚构项目，不发送飞书消息，不执行研发任务。

| 输入场景 | AI 环节耗时 | 复用线程 | 模型 | 重试 |
| --- | ---: | --- | --- | ---: |
| 问候、角色与所属项目 | 5.548 秒 | 否 | gpt-5.6-sol | 0 |
| 连续追问职责，明确只讨论 | 4.239 秒 | 是 | gpt-5.6-sol | 0 |
| 结合虚构登录上下文授权“照刚才说的办” | 6.865 秒 | 是 | gpt-5.6-sol | 0 |

前两轮均为 reply；第三轮正确生成 create_task 决策及完整边界，不实际落研发 Job。以上不是飞书端到端耗时，也不是代码开发完成时间。

- 新增覆盖：stdio 复用、按线程隔离事件、完成即返回（不等退出）、超时中断、不自动重放、断线恢复、审批请求拒绝、代理仅影响子进程、跨会话并发/同会话顺序、慢回复提示、outbox 隔离和开发进度脱敏限频。

- 重启前无运行/排队任务；原三个任务及问候历史全部保留，没有重跑旧任务。旧日志备份在 `data/logs/before-latency-fix-20260905-170041/`。

## 边界与待确认

VPN 需保持运行；迁移电脑或升级移除 Codex 旧版本目录后应更新本地运行配置。网络或订阅限额故障仍可能影响回答，不能承诺固定秒回。真实群聊发送/接收体验由用户下一条消息验收；未把合成性能结果记成业务开发效率或完整 AgentOS 交付验收。
