# AgentOS 会议纪要与 PRD 初稿试点

已启用的群可配置多个系统助手，各助手使用自己的飞书应用权限处理会议。会议纪要会把明确结论、业务规则、待办、未定口径分开。用户审阅后可以单独发布一份能直接交给群里 PRD 助手的需求初稿。

## 群成员怎么用

1. 进入已开始的飞书会议，请主持人打开「AI 总结」。在启用群发送 `@对应助手 会议号 123 456 789` 或 `@对应助手 记录会议 123 456 789`。也可以在「记录会议」后粘贴以九位会议号结尾的飞书入会链接。助手会核对发起人是当前在会的企业成员。
2. 如果提示等待 AI 总结或主持人放行，处理后等待助手自动再试。同一个助手对此会议的重复指令会去重，纪要发给原发起人。
3. 散会后到和助手的私聊查看纪要。飞书文档无法写入或无法验证权限时，助手尝试私发 Word。转写范围有限时纪要会说明，待办的负责人和日期没有明确时会标为待确认。
4. 如果私聊收到会议初稿预览，可以先确认拟共享的文字。确认后回同一个群发送 `@TPM助手 发布会议初稿 mtg-…`，把编号换成私聊里给出的编号。助手生成独立的飞书需求初稿，核实原群编辑权限后把链接私发给发起人。
5. 回到群里发送 `@TPM助手 我要做一个PRD` 加该链接。现有 PRD 卡片继续使用明确的已确认规则，冲突和缺失的业务口径仍按其原流程追问。

试点接收飞书会中转写和会议状态事件。共享屏幕和会中打开的文件不会自动成为纪要材料。会议助手当前以旁听模式工作。

## 部署配置

将 [配置示例](../config/meeting-pilot.example.json) 复制到私有部署目录。填写飞书群 open chat ID 和团队飞书文档域名。`allSystemAssistants: true` 会为该群里明确绑定项目且在群使用范围内的各系统助手开启入口。旧版单助手配置仍可使用 `profile` 与 `projectId`。试点群须已启用 PRD 工作台。独立实例将配置保存到本实例的 `runtime/meeting-pilot.local.json`，启动器自动选用此文件。直接启动控制面时，可以将 `AGENTOS_MEETING_PILOT_FILE` 指向私有配置文件的绝对路径。配置验证完毕后改为 `enabled: true` 并按现有实例流程重启。配置缺失或明确关闭时，试点不运行。每个部署配置一个群，各机器人仍需分别获得飞书平台的会议权限。

需要用同一个飞书应用身份实测会议号查询、会议详情（含当前参会人）、机器人入会和转写读取。飞书会议读取接口使用本应用的 open ID 和会议信息权限，通常会提示 `vc:meeting:readonly` 或对应的细粒度权限。私聊须覆盖普通群成员。飞书在线交付额外要求文档创建、正文读写、权限核验及协作者更新能力。组织密级策略导致写入失败时，纪要会尝试私发文件。初稿需要飞书文档才能接入现有 PRD 工作台。

## 值守与验证

- 会中每页转写和游标写到私有数据目录的 `meeting-sessions/`，每个文件权限为 0600。按句子编号与事件时间保留转写修订版。进程重启后继续同一场会议；结束状态记录后会等待并补读最后一批迟到的发言。飞书会后转写有平台宽限窗口，长期停机可能导致最后一段取不全。
- 纪要私聊和初稿预览成功后，从活动会话记录删除原始转写和私有纪要摘录，保留发起人、任务状态以及可以发布的初稿。中断的记录和待重试交付会保留在同一目录。运维应将该目录视作私密运行数据。
- 如果群里提示无法核实身份，先检查机器人 profile 和会议读取权限，然后用普通群成员账号开一场短会议验证。主流程验收应包含重复指令、普通群成员、私聊确实送达、只在明确确认后共享的飞书初稿及 PRD 原卡接续。真实会中语音播报及飞书原生邀请入口属于后续范围。
- 交付异常时查看会话记录的 `phase`、`lastError` 与文档检查点。若文档创建响应已丢失，先按飞书侧文档核对结果，避免再次创建或把私聊正文手动分享给群。
