# AI 对话入口与执行边界

每条实际投递给机器人的用户消息（@、私聊、可关联的回复）调用 Codex 理解和回答，不通过词表识别问候、任务、确认或补充。机器人身份由应用 ID / profile 确定，与显示名称无关。

对话采用独立只读执行环境，不能直接修改项目代码。将当前角色、已绑定项目、同会话历史、附件和本群任务真实状态交给 AI，输出结构化决定：回答、创建任务、补充任务、审批、取消或绑定项目。程序只校验结构、身份、群范围与任务状态，不替代语义判断。

- 普通对话、方案讨论、身份/项目问题：直接回答，不建立 Job。
- 明确授权的工作：生成包含上下文的完整任务说明；缺少影响执行的事实时先提问。不得把“如何修改”当成“立即修改”。
- 测试/审计被要求修改业务代码：转项目负责人；单独分析、测试、文档工作不能自动进入开发流水线。
- 审批仅真人管理员有权限；机器人角色不等于管理员；跨群任务不可操作。
- 对话保存在本地 store，模型窗口使用最近 20 轮；队列先持久化再确认接收，重启恢复未处理消息，重复事件不重复执行。
- AI 不可用时如实报错，不退回关键词模板，不产生研发任务。
- 任务完成消息必须包含真实结论和阻塞原因；失败/待补充不能显示为已通过。

验收：问候/身份/当前项目均调用模型；多轮指代可以创建完整任务；自然语言确认仍通过权限校验；同事件重复投递无重复任务；AI 错误无任务；仅 @ 对应机器人应答；重启保留上下文。

性能与运行约束见 `conversation-latency.spec.md`。对话使用常驻 Codex app-server，同群/用户/角色/项目复用线程；不同会话有界并发，同会话严格顺序。模型和订阅登录不变。3 秒慢响应提示只陈述接收事实，真正回答仍由 AI 产生。超时失败不创建任务，发送重试不再调用 AI 或重复应用动作。
