# 显式报表维度补全

用途：完整主对象来源之外，原问题明确要求展示“未归类”“未分配”等报表分组，即使该分组当前没有发生记录，也应保留一行。`extend_dimension` 只扩展任务内的展示维度，不插入业务库，不制造金额或数量，不把标签冒充数据库记录。

参数为 datasetRef、keyColumn、members（仅本来源已有字段及非空唯一文本键，标签为文本/null）、scopeEvidence。来源必须完整、非草稿且不含已声明数值分量；新成员碰撞或未知字段/参数报错，不静默覆盖或去重。原行顺序和原值保持，追加行未提供的字段保持null，不补零。配方单独标明新增维度及用户/源码依据，取数时间沿用原来源。

数量、金额仍来自独立完整业务来源，`compose_report` 按扩展后的population左关联；missing=zero只用于已经证明完整来源且确认无发生额的分组，不用于未知/范围外/错误格式。扩展维度不能充当独立金额基准。最终完整对象核验允许追溯到原始范围的显式维度配方，但每个新增键、原行及实际文件必须重放一致。

保存恢复、配方重放、refresh_report集中刷新和inspect_report实际CSV核验使用同一版本配方。迁移须保留原始来源、派生数据集与核验回执；旧版本没有新模块时不能继续处理新配方。未使用扩展功能的旧配方保持兼容。compose_report对未知参数（例如尚未支持的appendRows）明确报错，不能悄悄忽略后生成缺行草稿。

运行配置接续：控制面、源码CLI子进程和环境模型统一按显式options.file → AGENTOS_CODEX_RUNTIME_FILE → 随程序默认私有文件选择模型、推理档位和代理配置。迁移或隔离验收指定配置文件时不回落全局旧模型。不支持的模型单独标记MODEL_UNAVAILABLE，不当成数据库/权限故障，不擅自更换模型。真实消息来自机器人时，正式事件入口仍忽略；维护自测采用明示的隔离入口，不伪称真人原生入站。

原文件文字备注：`revise_report_file.annotations` 可使用 `[{label:"新备注列", constant:"用户明确给出的文本"}]`；省略columns时自动保留全部原列并追加。columns中显式kind=annotation的v3旧配方也可重放。列名和值都必须逐字出现在任务保存的原始用户要求内；不能覆盖原表头、替换原金额、执行公式或把备注当新取数。普通from列仍按原文件逐格投影，原行序在没有排序/筛选时保持。新配方version=3，实际文件审阅重放全部原单元格和备注；旧version=1投影、version=2补列继续兼容。新业务字段或计算仍走实际完整来源与原金额核验。

已交付文件接续：输入报表与本轮新交付报表分别核验。源码阶段引用当前任务已绑定、同项目/机器人/群/环境且哈希有效的旧报表时，只登记为report-input证据，不能当新输出验收，也不因其属于上一任务而阻断后续受控工具申请。需要新文件的任务仅凭旧输入不能ready。交接失败与任务阶段不允许是不同原因，不应以INVALID_STAGE掩盖实际工件缺口。

浏览器自测边界：macOS的Chrome自动化许可与网站凭据是两回事。BROWSER_AUTOMATION/BROWSER_EXECUTABLE按实际异常单独保留在等待登录诊断，不再一律归为“访问范围检查失败”；不要求重复密码、不自行关闭浏览器安全开关。许可/运行环境恢复后仍由原范围登录轮询接续。隔离验收进程失败不等于正式LaunchAgent身份必然失败，应分别验证。
