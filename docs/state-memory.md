# 状态存储、内存与执行检查点

适用于1.98.2。无需新增私有配置、权限或依赖，不增加整项任务时间、轮次或调用次数上限，任务/对话并发保持部署配置。

## 数据路径

事件/工具结果 → 串行事务 → 对实际访问的JSON分支建立惰性草稿 → 仅复制改变分支 → 复用未变记录编码 → 流式写临时文件 → 原子rename → 更新缓存。

源码缓存回收器在同一受信状态上完整核对引用，只复制引用路径和忙闲摘要；删除前仍在源码锁和状态写入栅栏内重新核对完整最新任务，不削弱在用或待投递保护。

无待接入任务时，环境发现轮询先筛选少量元数据，不读取完整历史。

此前一次小事件更新也会复制、序列化并重新解析完整历史。新实现保留完整历史、金额精度、文件与配方，避免中间多份大图同时存活。对话和报表选取当前问题及祖先链，不复制无关任务结果；此选择不是授权，原发送者、助手、群、项目和文件范围校验继续执行。

仍是单文件JSON存储：每次有变化的提交仍写完整快照，记录级编码复用不是增量数据库。单条巨型记录、浏览器、模型子进程仍可能占用大量内存，不能承诺永不OOM；需要持续按实际负载测量。未改历史保留/备份整理策略，未靠删业务证据换内存。

事务回调使用普通JSON对象和数组，可structuredClone；提交后外部输入及返回值均隔离，异常回滚不污染缓存。公开read保留兼容的完整分离副本，热点路径应使用select先选后复制。内部snapshot/inspectExclusive仅供受信只读代码，不能对缓存原对象写入或长期持有。

## 已确认进程退出后的恢复

仅本机登记的owner PID与整个worker进程组均不存在、原租约匹配时考虑恢复。仅持续只读源码调查，固定提交、源码边界和岗位规范真实复核成功，且仍是原发起人/助手/群/项目下的最新未关闭问题、无新输入待处理，才排队进行源码检查点审阅。

保留原提交、数据集、结果和文件；撤销旧environmentAccess与lease，记录executorRecovery。模型先审阅已有结果及最后未完步骤；数据库/网页补取仍须当前目录和新授权。不能直接重放已签名查询、业务写入、外部发送或整个业务任务。取消/撤回/身份不符/规范变更/源码损坏/仍有进程等不满足条件时保留原故障和证据。Windows未提供同等进程组退出证明，保持原拒绝行为。

## 验证与维护

运行`npm run check`；定向使用`node scripts/test.js test/state-draft.test.js test/empty-memory-exit.test.js`，不直接继承运行实例的环境配置。测试运行器并发2只影响维护回归。提取代码包仍须干净npm ci回归及verify-capability-package。

`GET /health`的processMemory包括rssBytes、heapUsedBytes、heapTotalBytes、heapLimitBytes、externalBytes、arrayBuffersBytes；stateReads包括完整/选择读取、惰性事务、无变化事务、分支及编码计数。RSS不等于活对象：V8可能保留已空闲堆页，任务结束后RSS不立刻归零并不等同泄漏。比较相同输入的峰值与后续稳定值，同时记录其它任务和浏览器进程，不将强制GC隔离基准当作生产自然回收。

真人回归须真实账号、原题或显著标记合成数据，不绕过入站身份；核对答案、文件、投递及前/峰/后内存，成败均撤回自测。隔离基准只能说明该存储路径，不等同整体业务调查提速。

## 发布、迁移及回退

遵循实例空闲守卫；停稳唯一服务完整进程树，备份data/config/secure，校验包和原数据保持后启动，验收所有消费者及health。状态格式未变，整包保留原data、数据集、文件和配置/加密凭据；新增模块随代码包核验。

回退前同样自然空闲并备份最新状态，使用专用分支revert验证发布，不回灌旧agentos.json。已自动排队的检查点应待其结束或由兼容版本接续，不让旧代码复用已撤销授权。macOS为当前维护平台，其它OS及完整跨机路径需在目标平台另验；外部飞书手册按团队实际入口同步，缺入口不能声称已同步。
