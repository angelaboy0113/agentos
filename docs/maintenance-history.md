# AgentOS 维护与版本记录

本文保存从飞书实施手册迁出的版本流水和历史验证基线，供维护者在升级、迁移、回滚或排查历史回归时查阅。

首次部署不要根据本文推导当前配置。当前行为以 `main` 的代码、`README.md`、`docs/getting-started.md`、配置示例、脚本和测试为准。历史提交、旧测试数量、旧部署路径、旧机器状态和旧任务编号都不是新部署要求。

来源：飞书《通用工作流的 AgentOS 设计（基于飞书版）》原第 15.1 节和第 14.3 节；迁移时读取 revision 903。

## 文档与产品版本历史

### v3.57.1 · 操作说明与实时验证分级（2026-10-09）

对应 AgentOS v1.8.3。用户询问“怎么创建、在哪里配置、如何提交”等操作方法时，只要本轮同步源码已经确认入口、表单字段、保存和提交流程，系统会先交付可执行的操作说明；当前页面、当前账号权限或提交后状态因浏览器不可用而未实测时，结果显示为黄色“部分分析完成”，并明确列出待核实范围，不再把整张卡片判为红色阻断。用户明确要求打开当前环境实测、验证当前账号权限或真实提交时，实时访问仍属于核心要求，失败会继续标红。新增正反回归并完成 365/365 全量检查；规则只影响升级后的新任务，不重算历史卡片。

默认strict-readonly仍要求数据库账号只有读取权限。确实只能使用现有业务账号时，管理员在Mac本机MySQL接入向导选择业务账号，并输入USE BUSINESS ACCOUNT确认。程序记录accountPolicy=business-readonly及本机管理员确认时间；凭据仍在Keychain，不写群聊或配置文件。已有入口不自动改变策略。
此模式仍核验权限信息、设置时限、开启只读事务；只开放基础表结构、绑定参数及筛选条件的受控SELECT。固定SQL仅允许内置库名/时间连接检查，拒绝自定义模板。多语句关闭，PRD成员审批不变，不提供写入工具。账号自身可能有写权限，不能把程序限制宣称成数据库只读账号隔离。TLS校验独立保留。
更新后旧终端向导必须退出并重新打开，过期申请重新发起；真实账号连接须在本机完成。模型不能启用模式或自动取Nacos业务密码。前述“必须专用只读账号”是默认策略，本段为显式管理员例外；主流程确认、认证、验证和原身份续跑节点不变。
数据库连接接续：不再手工搬运地址（v3.10.0）
用户在配置排查后说“连接一下”：已有对应MySQL入口时发起受控检查；未接入时，程序优先从本问题及父问题链的已完成结果取得主机、端口、库名，唯一候选直接预填申请。多个数据库请用户选库名。没有候选时自动从唯一同环境Nacos入口发起受控发现，完成后生成接入申请；旧版本没有结构化地址的结果也通过重新查询补齐。
流程：要求连接 → 复用地址或受控发现 → 管理员确认入口 → Mac本机录入专用只读账号和表范围 → 测试MySQL连接及只读授权 → 按原发起人权限继续查询。程序不会把Nacos配置里的业务账号拿来自动连接。普通成员PRD发现和查询继续按范围审批；首次凭据录入仍需本机真人配合。
实现：connection-endpoints.js只保留连接元数据，按同群、项目、profile、问题祖先链、24小时和证据范围匹配筛选；不把账号密码或原配置注入共享记忆。环境发现完成由持久轮询衔接幂等申请，接入后使用独立续跑键，避免被原发现任务去重。无完整地址不宣称已连接，多个Nacos入口先确认来源。现有流程图的确认、认证、验证、原身份续跑节点保持不变，本节补充其地址来源。

### 原第 10.0 节“按问题隔离的原生会话与记忆”
## 10.0 按问题隔离的原生会话与记忆
### 只读排查自动授权
#### 什么时候不审批
查看源码、日志、Nacos配置、数据库只读数据和业务网页等排查操作，在通过项目、环境、模板、参数和只读工具边界校验后自动执行。UAT与PRD使用同一规则；同一问题从源码继续到配置、数据库或网页时，不再让用户逐次回复“同意”。
#### 什么时候仍审批
修改代码、数据、配置、权限、部署状态，或在页面执行保存、提交、审批、启停、执行、删除、上传等写操作，仍需管理员审批。首次接入新环境、保存本机连接配置或凭据，以及接受单目标非TLS例外，也仍需管理员明确确认。
#### 程序如何守住只读边界
数据库仅运行参数绑定SELECT和只读事务，并限制库、基础表、字段、筛选、行数和超时；网页网络层阻断写请求；Nacos仅开放已登记命名空间和脱敏结果。Runner领取和每次工具调用前仍核验配置指纹、项目、模板、参数、有效期和租约。自动授权不会把账号、Cookie或写权限交给群成员。
#### 升级和验证
启动时重新校验旧版遗留的待只读审批任务；有效任务自动进入执行队列，无效或已删除范围保持暂停。271项完整回归通过，覆盖PRD/UAT自动执行、连续排查、网页登录恢复、参数修正、旧任务迁移及写操作阻断。模拟测试未访问真实业务环境。
### 按问题复杂度自然回答
#### 回答原则
AgentOS不再把所有回复统一压成2—4句。问候、状态、审批、接单回执和单一事实继续简短；业务分析、影响评估、方案讨论和原因解释应直接给出判断，并按需要展开主要影响、成立前提、风险、未验证项和下一步。
信息不足但仍能形成有用判断时，先给条件化分析，再追问真正会改变结论的少量信息。只有缺失信息导致任何可靠判断都不成立时，才只做澄清。
#### 卡片展示
普通对话和任务摘要的主卡片最多展示1200个Unicode字符。复杂业务结果通常为300—900字，简单结果不要求写满。超过1200字符时，主卡片保留一段完整、可独立阅读的主要回答，其余内容进入“详细结果与证据”分页；完整finalMessage仍被保留。
#### 权限和边界
本次只调整回答深度与展示，不改变问题隔离、环境审批、成员权限、只读限制或任务完成判断。需要当前源码或实时数据时仍发起受控调查，不用更长的文字代替核验。
#### 验证
回归覆盖旧360字边界以内和以上的业务回答、真正超长回答的折叠、完整详情保留、1200字schema上限，以及先分析后澄清的策略。发布测试不访问业务环境。
### 查询未执行后的具体诊断与自动修正
#### 使用行为
源码调查提出追加环境查询时，参数不合格、相同查询重复和自动收敛暂停会给出不同诊断。参数或模板错误显示“本次查询未执行”及具体约束；相同核心目标在证据未变化时重复申请，显示“AgentOS 自动暂停”，并明确这不是用户拒绝、不是权限拒绝，也不需要用户重新授权。此前取得的环境证据继续保留。
参数错误和自动暂停都回到同一问题、同一开发会话自查。模型依据诊断缩小范围或切换已登记的数据库、网页、日志、配置、源码证据路径；新证据支持的定向补查不会因已经完成三轮而被拦截。新申请仍执行现有项目、模板、参数和环境授权门控，既有授权不会转给新范围；相同证据下仅改写文字仍不能绕过重复检查。
同类申请错误连续三次、期间未取得新的环境证据时，暂停重复尝试并展示原因。这是无进展纠错保护，不是整个业务排查的固定工具调用上限。配置、身份或未知错误不会自动扩大权限；卡片提示维护者需要处理的条件。
#### 实现和排查
src/shared/environment-access.js 生成不含参数值的结构化校验信息；src/shared/query-repair.js 将已知错误映射为允许公开的 code、reason、correction、retry、attempt。未知异常不直接回显错误文本，避免泄露凭据。queryRejection 保存在结果及后续上下文；query_plan_repair_requested 事件关联修正任务。
server 将可恢复拒绝交给 store 原子派生只读源码任务，保留原问题、身份、附件与已有上下文，不携带环境授权。重复旧租约事件不会再次派生。修正任务的提示要求读取前次诊断和当前环境目录，仍需模型正确生成下一次申请；不能把机制存在等同于所有错误必能修复。
本次仅覆盖源码提出 environmentQuery 后的申请规划校验。浏览器入口准备失败、真实数据库查询超时等有各自处理流程，不宣称已由本补丁统一解决。旧版本已覆盖掉的具体错误无法从笼统摘要还原，升级不自动重放历史结束任务。
#### 部署与验证
无新增配置，备份运行数据后在空闲时更新并重启。Mac 已运行回归与健康检查；Windows 未实机验收。回归通过真实本机HTTP模拟参数超限、同一任务原子接续、原目标与图片保留、重复事件拒绝、修正后仍等待审批、反复失败暂停，以及敏感参数不进入诊断。没有借发布验证访问真实业务数据库。
### 数据库端点去重与完整配置来源保留
同一个环境和数据库 URL 可能先由 database_endpoints 得到地址，再由 investigate 得到配置文件及命名空间来源。候选去重优先保留有有效 connectionSource 的完整记录；多个完整记录取最新任务记录。来源证明、任务 ID、配置指纹和授权范围必须来自同一条证据，不拼接不同任务的凭据来源。后续仅有地址的结果不会覆盖完整来源。同批结果使用同样规则。
相关问题、项目、群、机器人身份、24 小时有效期及范围摘要校验保持不变；不会把所有卡片的临时证据变成共享记忆。成功登记的环境连接仍通过项目环境目录复用。
对旧版本已标记处理、仍提示“尚未取得完整数据库地址”的等待卡，仅当它仍是原问题最新接入步骤、现在已有唯一完整候选、且从未创建接入请求时，允许自动恢复到管理员确认。不会自动批准、登录或查库；已有请求、用户已转入其他步骤的卡片不会重放。新安装无额外配置，空闲更新并重启。
回归覆盖地址先到/来源后到、倒序结果、更新的裸地址不降级、多个完整来源取最新且保持来源绑定，以及旧等待恢复后重复轮询只产生一次审批。发布验证不访问真实数据库。
### 补充网址不替换原问题与交付自查
同一 questionId 下新建只读分析或环境子任务时，持久化层保留首次任务的 originalQuestion、missionId、已有证据与附件，证据去重且仅限相同项目、群和问题。补充的网址仍可用于当前子步骤，不能把预算影响等业务目标改写成“确认数据库地址”。接入会话及环境查询后的源码续查都继承目标清单；完成检查发现历史目标被遗漏时，结果保持 partial，卡片不能显示绿色完成。
对话上下文增加 questionOriginalRequest，提示模型将网址、库名、登录完成等视为补充条件。提示词负责理解用户意图，持久化与目标完整性检查负责防止目标丢失；目标是否真正被证据验证仍需模型复核，不能保证所有错误结论都被结构校验识别。仅询问地址的独立问题可正常完成。跨问题、项目或群不继承此链路数据。
回归重现“原预算问题尚有缺口 → 用户补充网址 → 端点查询成功 → 返回源码”的链路，验证原目标、图片、证据保留、环境授权不外溢、缺失目标不能变绿，以及真正补齐证据后可以完成。升级不重放历史已结束任务。
每次交付前自查已写入仓库AGENTS.md：复现实际故障、验证任务接续及完成判断、核对权限和卡片状态、运行回归、部署后核验健康及数据保留，并同步手册。模拟测试不等于真实业务验收。
### 缺少环境接入时等待补齐并接续
#### 使用方式
源码调查发现仍需核对环境、但缺少连接时，不应以“需要管理员补齐”结束任务。开发结果可提交 environmentSetup（kind 为 nacos 或 mysql，tier 为 uat 或 prd，url 为不含凭据的入口或空字符串），outcome 为 needs_clarification。网站继续使用已有 websiteQuery 流程。
已知入口优先复用。确实缺少 Nacos 网址时，在原话题明确询问对应环境的网址；用户回复后继续原任务。需要登录时通知维护者在运行 AgentOS 的电脑上登录，卡片保持等待状态；接入流程检测完成后自动继续，不要求重复描述业务问题或回复“继续”。需要接入确认时，指定管理员可回复“同意”；这不是授权任意用户访问全部环境。
#### 实现与权限
源码结果经 server 校验，在 store 的同一事务内生成原问题的接入会话，保留原发起人、使命、图片和已取得的证据。重复租约事件不能重复接续。environmentSetup 只启动补齐流程，不代表已经连接数据库。
Conversations.apply 先复用项目、环境、地址一致的受控连接。只有数据库地址、没有配置来源时，先通过已登记的同环境 Nacos investigate 查询 discover/read_config，取得 namespace、group、dataId 和内容摘要，再进入既有管理员确认与本机凭据接续流程。不得将 PRD 连接用于 UAT，也不要求把密码发到群里。
有多个候选库时询问目标库；没有唯一 Nacos 入口时询问环境入口。接入会话使用 setupPending 保持橙色等待卡片，抑制“任务结束”提示。登录轮询完成后按原发起人的身份重新规划查询，继续遵守 membersRead、环境负责人及本次范围审批；管理员接入确认不会替普通成员获得查询授权。
#### 配置与部署
沿用 config/environments.local.json（或 AGENTOS_ENVIRONMENTS_FILE）中的 environments、projectId、tier、membersRead、ownerOpenIdsByProfile、queries.investigate。Nacos 工具查询还需受控 namespaces。复用已有 Keychain/本机凭据存储；无新增密码字段，无需把私有配置加入 Git。更新程序需在无执行中任务时重启；已结束的历史任务不会因升级自动重放。
Mac 使用原有本机登录接入能力；Windows 部署继续依赖对应平台现有凭据与浏览器能力，本次未进行 Windows 实机验收。通用业务网站与 Nacos 专用登录流程仍有区别，不能假定所有登录态自动共享。
#### 验证和排错
回归覆盖原问题/身份/附件保留、HTTP 重复事件拒绝、含凭据 URL 拒绝、未知网址补充后恢复、接入完成后恢复原发起人、已知连接复用、裸地址先查询配置来源，以及恢复查询仍需环境审批。使用模拟配置和本机 HTTP 测试，未借发布验证访问真实数据库。
排查时查看 setupTurnId、setupSourceJobId、setupPending、setupTargetUrl 和 environmentEnrollments 状态；不要输出凭据。等待登录、缺网址、等待审批应保留可恢复入口；真实网络不可达、账号无权限、接入失败仍需显示具体原因，不能靠无限重试或绿色卡片掩盖。此变更补齐接续机制，模型仍须正确选择环境、工具并判断证据是否足够。
### macOS 日常 Chrome 登录态复用
#### 配置与使用
Mac 默认 shared-chrome 后端，使用 Apple Events 接管日常 Google Chrome 的对应应用页面。不复制 Cookie、不读取密码、不打开远程调试端口、不关闭或重启 Chrome。登录过期仍需本机配合。其他平台默认 isolated；设置 AGENTOS_BROWSER_MODE=isolated 并空闲重启可恢复独立 Playwright 浏览器。
激活日常Chrome，从Mac屏幕顶部选择“查看 → 开发者 → 允许Apple事件中的JavaScript”。全屏时把鼠标移到顶部。系统首次询问运行AgentOS的宿主可否控制Chrome时，由本机使用者确认。macOS会分别判断前台终端或Codex与后台LaunchAgent的Apple Events授权：网站已经登录只证明Cookie有效，不代表后台AgentOS已经获准控制Chrome。未就绪返回BROWSER_BRIDGE，不应解释成网站账号无权限。
#### 任务卡凭据自动登录
原问题卡显示“等待网页登录”时，会明确写出需要登录的网站名称和完整网址。发起人可以直接回复这张任务卡或同一话题，无需私聊；只有一个网站等待登录时，可直接发送 admin / 123456 这类“账号 / 密码”内容，也支持全角斜杠、逗号、分号、竖线、换行或“账号：… 密码：…”等自然格式。控制面按飞书事件中的 mention 元数据先去掉机器人显示名和 mention key，再解析账号密码，避免把 @项目负责人 等称呼写入账号。
群内发送的原消息仍会被飞书展示和保留；AgentOS 不把账号密码写入任务、模型上下文、日志或长期记忆，也不会在回复中复述密码。通过校验后，凭据只写入本机 Mac Keychain，由固定登录程序填写页面并自动续查。提交后若页面仍显示账号密码输入框，系统提示核对账号或密码；只有进入不再显示密码框的同源验证页时，才提示验证码、短信或扫码。
控制面在普通对话入库和模型处理之前识别凭据消息，核对发送人、机器人 profile、待登录任务与网站范围，将凭据写入当前 Mac 用户 Keychain，再由固定登录程序填写表单。账号密码不进入模型、任务卡片、AgentOS 日志或长期记忆；登录成功后自动继续原问题，以后登录态失效时从 Keychain 自动尝试一次。
凭据必须直接回复对应等待登录任务卡或同一问题话题，不能作为无上下文的普通群消息提交。只有网站环境负责人可以更新凭据，普通成员不能替换；登录不开放保存、修改、执行或审批等业务操作。AgentOS 无法删除已发送的飞书消息，原消息继续受企业飞书留存策略管理。
#### 执行与权限
环境计划批准后才接管。每个命令重查任务授权，按完整入口匹配 origin 和应用路径；不读取无关标签页正文。每任务固定一个标签，多个任务不共享活跃标签，操作串行。找不到匹配页时在日常 Chrome 当前窗口新建已批准入口；多 profile 用户宜先在目标 profile 打开业务页面。任务结束不关闭用户页、不退出浏览器。人为切到范围外页面时拒绝读取。
提供脱敏可见正文及筛选后的查看、搜索、分页控件；不读取 Cookie、localStorage、密码输入值及隐藏 noscript 提示。工具使用固定脚本，不接受模型脚本。引用按任务和快照隔离，控件标签或链接变化时失效。写入按钮及跨应用链接不开放。原成员权限与 PRD 审批仍保留，登录态不等于群成员授权。
#### 与独立浏览器的区别
日常 Chrome 正常加载网页请求，不再全局拦截登录、菜单或权限初始化。网页工具开放有明确只读标签的查看、搜索、分页控件；对于没有单独详情按钮、但使用稳定 data-row-key 承载记录跳转的常见表格，整行会作为“行详情”引用供继续钻取。包含保存、删除等写入文字的行不会开放。此模式不是网络层只读沙箱：控件筛选不能证明网站自身事件处理器无副作用，也不能隔离同一 profile 的后台网站行为。要求严格网络拦截的部署应选择 isolated；本次没有扩大 AgentOS 保存、删除、提交或执行任务的权限。
此后端仅支持 macOS Google Chrome。Nacos 专用配置读取浏览器不走通用网站后端，本变更不迁移其登录态。仅读取顶层应用，跨域 iframe 或复杂自绘控件仍可能不可读。
#### 排障与验证
BROWSER_BRIDGE检查Chrome是否运行、Apple Events JavaScript开关和后台AgentOS的系统自动化权限；登录本机管理后台后可请求GET /api/v1/admin/browser-health，成功只返回运行状态和窗口数量，不读取页面正文。桥接缺失时任务显示橙色“等待本机浏览器授权”，放行后自动续跑，不要求重新登录网站或回复继续。BROWSER_SCOPE检查是否关闭或离开原应用。网站可见no-access保留为事实，但不能仅凭它认定账号权限根因。
测试使用模拟传输与真实本机 Chromium 页面，覆盖授权重查、独立标签关联、过期及跨任务引用拒绝、写入及跨域控件过滤、可见文本、页面密码不读、任务卡与同话题归属、负责人校验、机器人 mention 清理、固定登录表单、账号密码拒绝及二次验证分类。v1.3.2 的开发副本与部署副本完整回归均为 304/304；真实等待登录任务在凭据修正后自动接续。Windows 本轮未实机复验。

### 原问题自动自查与续查
#### 使用方式
群内一次提问后，已有权限内的只读调查自动继续，不需要每轮回复“继续”。新分析使用一个持续开发 Job；结果仍为 partial + continue 且没有外部阻碍时，本轮结果写回原 Job，并恢复同一个 Codex thread 自动补查。父问题链按“最早原问题 → 环境或范围补充 → 当前追问”组成完整任务要求；即使“PRD环境”等短回复第一次创建 Job，存储层也保留这条完整问题链，不再把任务退化成只有短回复。环境查询仍经现有目录和范围门控；登录仍在运行 AgentOS 的电脑上完成，不扩大权限、不变更业务数据。
#### 完成与暂停
源码分析输出 investigation：status 为 complete/continue/wait，goals 为稳定 id、verified/open、evidence，attempts 为实际尝试，nextStep 为下一步，blocker 为外部阻碍或 null。绿色完成要求所有声明目标 verified 且证据非空，不能遗漏前序目标，仍需原有源码、工件和交接检查通过。负责人能够用同目标的新证据关闭旧缺口，避免永久继承 partial。
有证据推进就继续。同一环境已经调查两轮后，新证据给出业务主键、更小范围或新的状态线索时，可以继续绑定未完成核心目标补查，不设置固定总轮数；目标和证据摘要不变时，改写查询目的不会绕过收敛检查，程序显示“AgentOS 自动暂停”，而不是“用户拒绝”。同一 Job 的源码自查最多自动增加两轮，相同目标证据重复一次即停止空转。用户明确要求深度或彻底排查时，查询命中条件和中间状态不能替代上游形成原因；仍写“为何形成尚未核实”的因果线索会重新打开核心目标。等待外部配合必须写清具体登录、授权、必要输入或工具不可用及实际阻碍证据。卡片不能为了绿色虚构结论；结构检查也不能保证复杂问题必然解决。
#### 实现与部署
config/task-result.schema.json 提供可空 investigation，并允许环境查询用 goalIds 声明定向补齐的核心目标。源码执行器负责原因证据与深度调查完成门；store 原子保存 partial 续查上下文，Runner 通过 continuous-analysis-continue 在原租约、原 Job 和原 Codex thread 内继续，不派生新的“开发 → 开发”任务。问题关联层将飞书根话题回复解析到最近问题分支，并把父链原文拼接为任务原始要求。实施类任务不适用。
更新程序和 schema 后空闲重启，无新增私有配置。已经结束的历史问题不会自动重跑，须在原话题重新要求继续。原生 Codex 和 AgentOS 的工具可用性仍不同，本变更解决续查调度和自查机制，不声称能力完全相同。
#### 验证
回归包含完整目标、遗漏目标、旧缺口关闭、无新增证据暂停、新证据继续、明确登录阻碍、同问题原子续查、身份保留、不携带环境授权、重复事件拒绝和真实本地 HTTP 事件路由。使用模拟证据，未查询真实数据库或向业务群发送测试消息。Mac 运行实例部署；Windows 未实机验证。
### 用户确认的业务域名与旧入口更正
入口验证与 HTTPS 跳转排障：业务入口应保存完整的 HTTPS 应用路径，例如 https://uat.example.com/tpm/，不能只凭根地址返回 302 判定可用。检查每次重定向的协议、主机和路径，以及最终 HTTP 状态和页面内容；若根地址降级到 HTTP 并返回 503，应登记已验证的 HTTPS 应用入口。不要为此放开跨域请求限制。仅返回 HTML 200 仍不代表登录完成或业务数据已核实。
本次部署勘误（2026-09-18）：已验证原根地址跳转到 HTTP 后返回 503，完整 HTTPS 应用路径直接返回 200。私有 environments.local.json 新增正确入口，websiteAliases 将精确旧入口直接映射到该入口；避免链式映射。配置按请求读取，无需重启；已打开的旧页面和已签发旧任务不会自动改址，新查询才使用新入口。相同项目、环境和 HTTPS origin 保留同一浏览器会话目录；未复制个人浏览器凭据。此次仅修改私有配置，没有新增程序发布，未验证登录后业务页面。
业务网页优先采用对应项目、UAT/PRD下用户确认的域名，不用DNS解析结果、后端API地址或旧联调IP代替浏览器地址。源码Agent仍先搜索配置、部署和文档，找不到可靠入口才询问。IP页面资源加载不完整不能直接证明前端故障。已确认域名不代表已登录或业务数据已核实。
#### 本机配置
在私有 config/environments.local.json 顶层可保存 websiteAliases 数组：
```json
{"websiteAliases":[{"projectId":"your-project","tier":"uat","from":"http://192.0.2.10/mp-runtime/","to":"https://uat.example.com/"}]}
```
示例地址必须替换为该团队确认的真实入口。只进行项目、环境和完整入口路径的匹配（末尾斜杠等价），不将一个IP上的全部应用重定向；Nacos、数据库和XXL-JOB地址不随业务站点更正。禁止含凭据/查询串的网址、重复、循环或链式映射。
目标网站应按既有website环境结构登记。新websiteQuery可按更正后的URL自动登记；已有环境ID生成新计划时，目标尚未登记会明确拒绝，不能回退到旧IP。目录隐藏已被更正的旧入口，展示目标域名。目标网站的成员策略与审批人用于新计划，不能继承旧网站的批准。
旧环境记录及其配置指纹保持不变，不改写已批准/运行中的任务；旧任务需停止后重新发起才能改用域名。更新程序和本机配置后空闲重启。域名与IP是不同origin，原IP登录Cookie不会复制给域名，首次使用域名可能需要登录；后续有效域名会话可复用。
#### 维护与验证
真实域名和映射保存在部署电脑的私有配置，不硬编码到公开代码。配置应在无运行任务时备份后修改。发现域名有误，核实后更正私有映射与目标登记，不通过关闭TLS验证解决。
回归覆盖精确路径、不同项目/环境、其他服务不受影响、目录、新计划使用目标权限、旧批准不被静默重定向以及非法映射。模拟测试不证明真实业务网站可登录。Mac实机可额外检查根地址HTTP响应；302仅表示重定向，不是业务查询成功。Windows本次未实机验收。
### 环境子步骤完成与原问题完成
#### 行为
“核对实际单据”不是“找到数据库地址”。环境工具的 ready 只表示当前读取步骤成功；结果写回同一个 continuous_analysis Job 后，原开发 Codex thread 必须继续按原问题核对源码、单据和对照证据，直到形成结论或遇到真实外部阻碍。用户不需要为成功的中间步骤回复“继续”。
如果用户只问连接地址，后续分析可直接回答；若要求核对单据，则尚未查到单据时不能宣称完成。后续访问仍需匹配已有查询范围和审批；没有接入能力时明确待解决项，不自动扩大权限或沿用环境授权到源码执行器。
#### 实现与边界
控制面按原环境、原问题和现有配置验证每次受控查询；store 在当前租约内保存环境计划与结果，清除已完成的 environmentAccess 后恢复原 Job。Runner 继续同一个 Codex thread，不创建 analysis_review 后继任务。重复范围、旧租约和迟到事件不能再次执行；未配置源码分析仓库时明确阻塞并要求维护者补充 analysisRepositories。
环境子步骤 ready 不能单独充当业务问题已解决的标志。原开发会话根据原始目标继续选择源码、数据库、Nacos 或网页证据；多个独立证据收敛时按“确认 / 高度支持 / 尚不能确认”作答，不能为了变绿编造完成。
#### 卡片
有业务解释时优先展示该解释，即使工具结果是host/port/database。数据库坐标和原始记录放在展开详情。没有业务解释且属于直接地址查询时保留地址展示。解释要求说明真实已确认、尚未确认和下一步，不照抄无关的记录数、超时或根因提醒。
#### 部署与验证
更新后空闲重启，无需新增配置。已结束历史问题不自动执行；在原话题重新要求继续后走新流程。回归通过真实HTTP事件验证ready环境子步骤派生、原身份与问题保留、不携带授权、重复事件拒绝；卡片测试验证业务解释优先、地址仍在详情、直接地址查询兼容。使用模拟数据，没有为发布验证访问生产或UAT数据库。Mac部署，Windows未实机验收。
### 网站目标识别与应用路径隔离
#### 行为
查询活动审批页面不能复用定时任务管理台，仅同属UAT或同一IP端口不是正确入口的证据。源码Agent必须从当前问题、对应环境源码、部署配置和文档找到实际业务入口，并在调查详情说明来源，不能删掉XXL-JOB路径猜测业务根地址。
#### 实现
websiteKey按项目、环境、完整规范化入口URL（含路径）登记网站环境。旧版本仅按origin登记，会把同源不同应用映射到第一次登记的baseUrl；本次新增路径键，保留旧配置及任务，不原地改旧授权。已有键的baseUrl不一致时拒绝复用。
网站目录scope包含entryUrl与origin，避免模型只看到主机却不知道是哪种应用。websiteSessionKey沿用旧项目/环境/origin哈希，只用于本机Chromium配置目录；同源有效登录态仍可复用。页面与动作引用按Job隔离。路径登记不等于Cookie或网络权限按路径隔离，网页请求仍受原同源策略与任务授权约束。
网页登录后，规划器先核对标题与菜单。若明显不是目标系统，选择report_wrong_site；该动作不访问网络、不改变权限，产生websiteMismatch和partial证据，结束错误页面调查。配置了源码分析仓库的原问题按现有接续规则返回源码阶段，重新找入口，再提出websiteQuery。新的网页访问仍走原审批规则。
应用语义判断与重新找入口是模型行为要求，不是保证能识别所有网站的确定性校验。找不到可靠地址或环境有歧义时仍需要说明具体缺口。不能把登录失败、请求受限都误称为找错网站，也不能把找错网站直接归因于用户权限不足。
#### 部署与排查
更新程序后空闲重启，无须改私有配置。旧任务记录、旧网站登记及登录会话保留；已结束任务不自动重跑。新网站登记使用web-entry前缀，私有环境文件可能同时包含旧web登记。
查看任务websiteQuery.url、目录entryUrl、实际网页内容和websiteMismatch。入口正确但读不到数据，再检查登录、授权和请求兼容性；不要反复批准错误网站。管理员无需通过扩大权限修复入口选择错误。
#### 验证
回归覆盖同源不同路径登记、旧origin配置兼容、目录精确入口、同源登录会话键保留、错误站点partial证据；既有测试验证网页审批及浏览器会话。全部使用模拟数据和本机站点，未访问真实活动审批页面。Mac为本次部署环境，Windows未实机验证。
### 网页登录后的任务接续
#### 行为与故障
网站任务首次打开登录页后暂停，用户在 AgentOS 所在电脑完成登录，原任务自动排队继续。已授权范围、原发起人、问题卡片和证据检查点不变。此前登录轮询已能恢复 queued，但环境领取接口把原 startedAt 误判为重复执行，造成登录后立即 SCOPE_LIMIT、0次查询。
#### 实现和权限
登录检测器只对 awaiting_clarification 且 browserLoginRequired 的 website 任务生成 browserResumeClaim，绑定当前 scopeHash 与原 startedAt。领取时仍检查运行状态、当前租约、授权有效期和配置指纹；只有有效的一次性接续记录允许已启动的网站任务继续。记录在同一持久化事务内消费，并产生 environment_query_resumed 事件，保留首次 startedAt。旧租约、重复或并发领取不能重复消费。
授权过期或配置改变时仍重新申请批准，不因登录延长授权；取消任务不恢复。接续状态写在本机任务存储中，进程重启不丢失。Runner不能通过请求参数自行声明接续。普通数据库和Nacos已执行任务不因此允许重试。
#### 诊断与部署

### Nacos 调度平台入口发现与网页接续
#### 目标与使用
用户在原问题中询问报表刷新、定时任务是否成功等问题，不必先找管理台网址。源码阶段定位 Handler；环境调查在已批准的 Nacos 命名空间中 discover，再对相关 task 配置调用 read_runtime_config。找到可信入口后，源码调查接收入口证据并通过 websiteQuery 申请网页调查，查询实际 Cron、启停状态和近期执行记录。网页登录和批准沿用 [网站调查说明](query-driven-websites.md)。
不自动重新执行已经结束的历史问题。更新程序后，可以在原话题说明“继续核实定时任务实际执行情况”，新调查将使用新工具。这不是每一轮都需要回复继续。
#### 提取范围和证据
新增工具只接受本轮 discover 返回的 ref，不能指定任意 URL、Data ID 或跨命名空间。支持 YAML、properties，同文件占位符解析；不读取系统环境变量、不执行配置、不展开 YAML 别名。只返回以下已知字段：
- xxl.job.admin.addresses：一个或多个无凭据 HTTP(S) 入口。
- xxl.job.enabled / xxl.job.enable：布尔或 0/1 开关。
- xxl.job.executor.appname：执行器名称。
例如 `xxl.job.admin.addresses=https://jobs.example.com/xxl-job-admin`。这些是应用已有配置，不是要求用户新增 AgentOS 网站清单。`accessToken`、密码、原始配置正文不会作为本工具输出。含用户名密码、查询串、片段、敏感占位符或禁止地址的入口被拒绝；缺少、循环、跨文件占位符记为 unresolved，不猜测。
runtimeDiscoveries 保存提取值、namespace/group/dataId 和内容哈希。该结构进入后续源码阶段，独立于最多6000字符的自然语言报告，避免网址被截断。只有配置证据，不能证明网站能访问、任务已启用或执行成功。没有入口不代表平台不存在；多个入口需要结合原环境判断，仍有歧义才询问用户。
#### 执行、权限与限制
read_config 保持原数据库端点用途；read_runtime_config 专门处理调度配置。新工具仍受原问题目的、命名空间、授权有效期和租约约束；不会直接请求提取的网址。后续网站任务按原项目、UAT/PRD 和原发起人登记和批准，不继承 Nacos 登录凭据，不把配置发现当成网页授权。模型选择下一步，程序负责工具范围和批准校验；提示词不是确定性保证。
有效网站会话会复用；未登录或失效时在 AgentOS 所在电脑等待登录。个人浏览器会话不自动导入。启动、停止、执行一次、修改 Cron 等不包含在查看权限中。通用网页请求策略的兼容性和限制见网站说明。
#### 部署、排查与验证
Mac 和 Windows 均更新程序并在空闲时重启，不需要新增环境配置字段，也不改现有私有配置。新增目录能力提示明确暴露调度入口发现；旧查询描述可能仍写数据库解析，以本次目的和实际工具记录为准。
排查时查看 read_runtime_config、runtimeDiscoveries 和后续 websiteQuery/网站任务：没有入口检查字段名与占位符；有入口未接续检查源码阶段是否提出 websiteQuery；网页受阻检查批准、登录、网络和请求策略。不能因为无数据库地址就结束调度调查。
回归包含 YAML/properties、非敏感字段白名单、敏感引用及带凭据网址拒绝、多入口、配置来源、作用域引用、调查结果跨阶段保留；既有网页回归验证本机模拟网站的登录复用与变更拦截。测试未访问真实 XXL-JOB，不能将其等同于真实 UAT 调度已核实；Windows 本次未实机验收。

### 按问题发现业务网站与登录接续
交付状态：GitHub main 9505bfb 已发布，Mac mini 运行实例已在无执行中任务时更新并重启；健康接口正常，11 个飞书消息与卡片回调消费者就绪。旧的已取消登录任务卡已自动修复并成功送达：卡头显示“已取消 / 已停止”，取消与刷新按钮均已移除。以下为当前版本说明；自动登录验证不代表所有真实业务网站均已验收。
#### 用途与入口
群成员直接提出问题，例如“核对 UAT 报表定时任务最近是否成功”。不需要维护网站白名单，也不必先提供 URL。负责人创建原环境的源码分析，开发从问题、当前环境源码和文档查找实际入口，返回 `websiteQuery: {url,tier,purpose}`。找不到可信入口或存在环境歧义时才需要补充线索，禁止猜地址。
控制面建立 `kind=website` 环境，复用原问题、原发起人和当前审批规则；网页证据不足时继续返回源码调查。此次接入没有给源码 Codex 开放任意联网、桌面控制或个人浏览器 Cookie 读取权限。
#### 部署
依赖仍为 Node 22、`npm ci`、`npx playwright install chromium`。更新后在空闲时重启 AgentOS。使用当前登录桌面的操作系统账号运行；无图形会话的服务器不能弹出可见浏览器。网页不需要逐个填写配置。
系统在私有 `config/environments.local.json` 自动登记：项目、UAT/PRD、站点入口、`kind: website`、查询目的模板和当前管理员映射。入口必须是无账号密码、无查询参数的 HTTP(S) 地址；不允许 localhost、回环或链路本地地址。自动登记不表示已连接或已登录。PRD 成员查询仍需环境负责人批准；UAT 成员按成员只读规则执行。首次发现入口保存在当前项目，不能跨项目借用授权。
`data/website-sessions/<项目+环境+origin的哈希>/` 保存独立 Chromium 用户配置（Cookie、站点存储）。目录权限 0700，不进 Git，不发群、不送给模型；这不是 Keychain 加密文件承诺。不要共享整个 data 目录。删除对应目录可清除会话，需先停止 AgentOS/浏览器。不同项目、环境、origin 使用不同配置；同一站点的各问题使用不同页面和随机操作引用。
#### 登录与自动恢复
1. 已授权网页任务打开可见的独立 Chromium 窗口，有效登录会话直接复用。
2. 检测到密码框或登录 URL，卡片显示“等待本机登录”，不要求群成员复制 Token 或输入长确认词。
3. Runner 释放当前任务，其他问题继续。页面由控制面维护，不因 Worker 退出而关闭。
4. 运维人员在运行 AgentOS 的电脑登录。检测到离开登录页后自动恢复原任务、原问题、原发起人和已收集证据，无需回复“继续”。
5. 登录期间原查询授权过期或配置变更时，重新展示审批卡；登录成功不等于延长 PRD 授权。取消的任务不会恢复。
6. 控制面重启后可从持久会话恢复等待中的任务。会话被服务端撤销或过期仍需重新登录。
登录状态以常见密码框及 login/signin 路径识别，并非每个网站都支持；二维码、跨域 SSO、复杂 MFA 页面可能需要额外适配。个人 Chrome/Safari 中曾登录，不代表独立 Chromium 已登录。
#### 查看与操作边界
模型只能选择页面实际返回的引用：打开、读取页面、查看链接/详情/日志、翻页、填写查询条件、选择筛选项。不接收任意 JavaScript、任意 URL 跳转或坐标点击。页面文字按凭据模式脱敏；不能保证任意网站自定义字段全部可识别，因此仍需按项目控制群内信息展示。
程序按同源、请求方法、路由和动作特征限制请求，阻止已识别的保存、删除、执行、启动/停止及未知 POST；允许常见 pageList/query/logDetailCat 等查询请求。跨域请求、WebSocket、Service Worker、下载和弹窗默认阻断。**这些是通用保守规则，不是对所有网站“绝对只读”的形式化保证**：非标准 GET 副作用、同名接口语义仍需站点核验。未知接口受阻会作为缺口反馈，不能自动放开所有 POST 或把点击文字当充分依据。修改操作本次没有新增执行器；应走独立管理员审批的实施流程，不能借查看权限执行。

MySQL单次查询超时后销毁旧连接，向规划器返回可恢复错误；调整筛选条件或换证据路径后继续，重新校验账号权限、只读事务和表结构。同一条已超时查询不原样重跑。连续3次业务查询超时且没有成功业务查询，或连续3次未调整超时请求才暂停。总工具次数不设固定上限。单次时限仍为已批准模板的timeoutMs，不自动延长；连接、登录、浏览器、权限和范围错误不适用此恢复。每次工具调用仍检查授权有效期，最终汇总阶段不允许再查询，不能把此时零剩余调用解释成额度耗尽。
### 批准按钮反馈与回调故障排查
环境负责人可直接点击“批准本次只读查询”，无需再发送文字批准。程序校验操作者、原卡片版本和授权范围后将任务排队，立即请求更新原卡片，移除批准按钮并显示排队或执行状态。任务和消息更新异步进行，不能承诺点击后零延迟；未获成功状态时不要认为仅点击确认框就已批准。
回调由各机器人自己的 card.action.trigger 长连接进入，写入 data/lark-cli-events/对应profile/pending-card-actions 后送达控制平面。传输失败保留记录并稍后重试，继续处理其他按钮；单次请求最长10秒。停止时清理重试计时器，重启后重放未送达事件。业务操作继续按事件去重，管理员身份、卡片版本与生产环境范围校验不变。
飞书CLI去重标识最长50字符；超过长度时统一转换为确定性48字符标识，重复发送仍使用同一值。此前旧刷新操作发送错误提示时超过此长度，触发无限重试并堵塞同一机器人的后续按钮。修复同时覆盖文本提示和卡片发送。有效旧标识保持不变。
排查顺序：确认飞书控制台启用卡片回调和消费者就绪；检查pending-card-actions、cardCallbackAudit、cardCallbackChecks，再对照environment_approved、卡片deliveredRevision与expiresAt。CLI可选card_content缺失不再阻断本地已发送卡片的有效按钮。SDK收到点击、监听进程存活和模拟测试均不等于真实批准成功，必须区分accepted、ignored、rejected与delivery_failed。

### 从消息到结果
1. 接收消息，识别当前真人与项目；新提问创建独立questionId，关联回复复用原问题。
2. 接收消息并确定questionId；按问题、群、profile、角色和项目选择独立Codex线程。历史、附件与Job仅取本问题及明确父问题链。每轮按当前真人重新校验权限；派发任务仍遵循原审批门。角色交接更新原卡，结束提醒原提问人。
3. 首次用非ephemeral的thread/start，保存返回的thread.id；引擎重启后用thread/resume恢复。成功恢复不重复注入history。
4. 问答更新主卡片；需要代码调查/实施时经程序权限门创建独立Job，由Runner执行。普通成员只能只读分析。
5. 角色交接持续更新原卡；全链结束才@原提问人。源码同步受阻同时@对应管理员，不能自动解决冲突。
### 记忆到底保存在哪里
data/codex-conversations.json以0600原子保存线程引用、规则指纹、待定请求与最近决策；真正对话内容依赖当前用户的Codex本地会话文件。只保存一个session ID不能独立恢复，不复制Windows登录缓存。自动上下文压缩由Codex处理，AgentOS没有自设“固定20轮就忘记”规则，也不保证逐字永久记忆。
初次开启或规则变化，会从有预算的近期记录建立新线程，不自动导入全部旧聊天。原生模式的群对话不调用旧memory.json摘录链；旧文件保留，私聊/兼容部署仍可使用。memory.local.json的输入预算仍限制本轮上下文包，recentTurns只影响首次建立线程的历史种子，不是Codex内部压缩阈值。
### 恢复、权限与边界
- 当前用户的administrator每轮重算；历史中的“同意”不授权其他人。卡片发起人、当前Job和按钮版本由程序检查。
- 已完成决策先保存再返回，重复请求不重复做模型决策；上次pending结果不确定时建立新只读线程，业务效果仍按消息去重。损坏映射或恢复错误保留原文件并报告，不静默覆盖。
- 原生会话不把“以后记住”自动发布为正式团队规范。旧摘录模块的停用接口不能擦除Codex原生线程；需要清理时必须按对应存储处理，不能声称跨模式删除已完成。
- 没有台账也能运行；项目文件仍是可选证据来源。当前源码问题仍交给Runner同步后只读核查，不把历史答案当作最新源码。
- 停机备份agentos.json、已有memory.json、codex-conversations.json与local配置，并保护本机Codex会话存储。关闭开关不会删除数据；已建立问题卡仍需要支持questionId的程序处理。
