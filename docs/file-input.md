# 从飞书上传文件并分析

## 使用方法

在已绑定项目的普通群或话题群中先发送文件，再**回复这条文件消息**并 @ 对应机器人，例如：

> @项目负责人 读取这份明细，核对所有行的金额合计，并列出重复记录。

回复文件是明确关联依据；机器人不会从同群其他人的文件中猜测本题附件。群内单独发送、没有提问或关联的文件不自动创建任务。机器人私聊可先发文件，再说明目标，但创建任务仍须有现有项目绑定。多文件可在同一问题中明确关联后选择，本次修改不支持任意扫描整个群或自动扩展文件夹/合并转发资源。

Excel/CSV、PDF、Word、文本等文件以原始字节交给执行程序，保留原文件名、扩展名、MIME、大小、SHA-256和原消息归属。这里的上传能力是接收文件并让本机Codex读取，不是把所有格式直接塞进聊天模型。聊天阶段只看到元信息，不得声称已经读完；读取需求通过requiresFileInspection=true和attachmentIds创建analysis任务。普通成员可发起只读文件分析，写入或执行上传程序不因此获准。

纯文件分析采用analysisScope=attachments，不要求选择UAT/PRD、同步业务Git仓库或配置analysisRepositories。文件与源码对照时同时requiresSourceInspection=true，沿原有项目/环境范围分析。任务仍使用现有进度卡与完成提醒，原有私有投递规则不变；原始群文件的可见范围由飞书管理，私有结果不能追溯隐藏原文件。

## 接收与读取链路

1. 当前机器人使用其bot身份获取本消息或用户明确回复的原消息，通过lark-cli im +messages-mget --download-resources接收资源；复用现有消息/资源只读权限，不新增通讯录或网盘范围。
2. 只采用本次返回的resources，不遍历目录把旧文件或元信息JSON冒充附件；校验消息/群归属及本机消息资源目录。部分下载失败保留attachmentErrors，不能说成空文件或读完。
3. 任务按已选择附件ID通过原租约认证接口读取，流式写入data/attachments/<JOB>/<附件ID>.<原扩展名>，校验接收摘要。相同摘要的完整本机文件可复用，损坏副本重新取文件；不重跑业务查询，不新增大小或行数门槛。
4. 固定提示词向执行程序提供实际完整文件路径、格式和摘要，图片仍作为图片输入。非图片文件由现有只读工具实际解析，不能仅凭文件名或预览回答；续查也带文件清单。文件-only任务的空工作区位于data/attachments/<JOB>/workspace，不占业务源码工作树。
5. 原文件、工作副本和结果按任务归属管理，现有30天策略保护活动任务并清理过期无引用资源。纯文件分析不自动提炼为团队共享知识；需要读本次文件时历史知识不能替代实际读取。

本次不增加文件总大小、任务耗时、轮次或调用次数限制。实际可读取格式取决于运行机现有解析工具，Codex应按文件真实格式选择文本、Office、PDF或图片读取方式；遇到加密、损坏、扫描件/OCR或缺解析器时说明具体缺口，不伪造结果。没有自动运行宏、上传脚本、安装依赖或访问文件里所写外部地址的授权。无需新增配置/依赖，控制面、事件消费者和Runner成套升级并空闲重启；自定义对话决策端需返回新增requiresFileInspection布尔字段，旧持久决策仍兼容省略。

## 验证与排查

回归使用合成消息和文件，覆盖明确回复文件、其他机器人不接单、原名/格式保留、失败资源、跨群拒绝、超过5MiB的完整CSV流式接收、摘要损坏恢复、任务初轮/续轮文件清单、普通成员纯文件任务不要求源码环境，以及真实任务准备到合成Codex执行程序读取两行CSV得出完整合计。另用当前配置gpt-6.1-sol对合成CSV元信息实测，正确选择文件-only只读分析和附件ID，没有要求源码环境。文件执行程序为合成进程，真实模型未读取文件字节；不声称所有Office/PDF解析器、Windows或真实飞书客户端均已验收。没有向真实群发测试消息、读取用户真实文件或查询生产。

若无响应，检查是否回复了文件且@正确机器人、群项目绑定及角色配置；若只有元信息，核对requiresFileInspection/attachmentIds与任务清单；若下载失败，核对机器人对原消息的可见性和im:message:readonly等已需权限。若格式读不了，检查本机解析器和文件本身，不让用户反复发送同一份完整文件。若摘要不一致，保留旧证据并重新获取原文件，不能以旧文件结果冒充新版本。
