# 从飞书发送文件并分析

## 话题群操作

飞书话题群不能直接发送本地文件，使用云文件链接：

1. 将Excel、CSV、PDF、Word等文件上传到飞书“云文档/云空间”。上传为原文件与导入为在线表格/文档不同，程序按真实链接类型处理。
2. 在文件分享中复制链接，让当前机器人取得需要的阅读/下载权限。不需要向全公司或互联网公开；用户自己能打开，不等于机器人能读取。
3. 回原OS话题，贴链接并@机器人说明目标，例如：

> @项目负责人 读取这个文件，核对所有行金额合计和重复记录：https://你的企业.feishu.cn/file/文件Token

卡片显示识别、下载、导出或等待飞书完成导出等实际阶段。缺应用权限或文件未共享时显示橙色等待，不发送“分析已完成”的提醒。补齐后在同题回复“已共享，请重试”或“已授权，请重试”，无需重新贴链接。只继承同一发起人、群、profile明确回复关联的链接，不扫描其他人的问题。

普通群可直接发送文件，再回复文件并@机器人。私聊仍须现有项目绑定。没有提问的单独文件不自动创建任务；本次云链接、普通附件与截图可以混合。目录/文件夹需要明确具体目标，不默认递归整个云盘。平台边界见[飞书使用话题群](https://www.feishu.cn/hc/zh-CN/articles/360049067735-使用话题群)。

## 接收与执行

普通消息使用当前机器人bot身份通过im +messages-mget --download-resources接收，按本次resources处理，不把旧目录文件、元信息JSON或失败资源当有效附件。保留原名/格式/MIME/大小/SHA-256和来源消息，部分下载失败进入attachmentErrors。

云链接在消息路由接受当前提问之后，由对话worker调用固定Drive API：drive +inspect识别；原始file用+download；在线doc/docx/sheet/slides导出为docx/Markdown/xlsx/pptx；wiki先识别底层对象。已知飞书/Lark资源链接解析为固定API token，不直接抓取任意用户HTTP地址。使用当前机器人的明确CLI profile，不以个人账号或其他机器人降级。

云文件与pending-export.json/receipt.json位于data/lark-cli-events/<profile>/messages/<消息ID>/cloud-files/。接收后记录来源URL、实际类型、下载/导出完成时间、是否导出及摘要。多文件独立读取，不声称统一快照；导出副本摘要不能冒充原本地文件字节摘要。

CLI单次导出轮询窗口结束后，程序持久保存同一票据并继续查询；本机中断后恢复该票据，不重新创建导出。命令外壳不再对云下载/导出附加默认30秒截停，关闭时AbortSignal终止本机子进程，保留可接续状态；平台/网络单请求错误仍据实返回，没有任务总时长、总轮询次数或文件大小/行数门槛。

聊天仅知道文件元信息，不得声称已经读完；实际读取用requiresFileInspection=true和attachmentIds创建analysis。纯文件analysisScope=attachments不要求UAT/PRD或同步业务Git，文件对照源码时同时requiresSourceInspection=true并保持原项目/环境范围。

Runner按任务租约与已选附件ID流式取得完整文件，保存data/attachments/<JOB>/<附件ID>.<扩展名>，校验接收摘要。相同请求、机器人、发起人和群的完整副本可摘要复用；新提问重新核实云端，不无限复用旧链接数据。初轮与续轮均向执行程序提供完整本机路径、原名/格式和摘要；图片仍走图片输入。纯文件空工作区在该任务附件目录，不占业务源码工作树。

普通成员可发起只读文件分析，原进度卡、完成提醒和私有结果规则不变。文件内容是资料，不授权宏/脚本/外部访问或修改业务数据；纯文件结果不自动提炼为团队知识，历史知识也不能替代读取本次文件。实际解析使用本机已有工具，加密、损坏、扫描件/OCR或缺解析器时说明具体缺口，不伪造解析。群原文件可见性由飞书管理，私有结果不能隐藏已发送原文件。

## 部署、权限与存储

无需新增Node依赖，控制面、消费者、Runner和提示词成套升级，空闲重启。自定义对话决策端需返回requiresFileInspection布尔字段，旧持久决策兼容省略。云读取须配置当前机器人CLI profile，缺失时不采用默认应用或个人身份。

原始file下载接口需应用拥有其中一项允许的scope，优先最小drive:file:download。服务端missing_scopes常为候选权限，不应全部勾选、更不应开全盘读写。元信息与在线文档导出按真实接口缺项补齐。应用权限申请、企业管理员批准/发布、文件分享是不同外部步骤；程序不自行扩大scope、共享范围或冒用个人账号。

下载/导出进度保存在cloudFileProgress，待文件可读保存在cloudInputPending；补齐后同题恢复，未读取的附件错误保留给模型与任务，不能当作全量已核对。托管消息资源、工作副本、空工作区和票据沿现有30天规则清理；活动问题与文件引用受保护。访问令牌、原始CLI敏感诊断不进入模型。

## 验证和排障

合成回归覆盖命名超链接、多文件与截图、无@不下载、假域名/跨范围、完整字节/摘要/格式、超过5MiB CSV流式读取、异步导出65次继续、同票据中断恢复、候选权限最小化、橙色等待和同题重试。真实任务准备加合成Codex进程读取2行CSV得到合计30；当前gpt-6.1-sol对合成元信息分别验证已下载文件创建只读任务、未共享文件回复缺口而不创建空任务。真实模型未读取这些文件字节。

真实负责人bot已通过新链路只读导出已获准的维护手册，得到235847字节Markdown；这不能证明每个用户文件均已共享或原始file下载scope已生效。以不存在的合成Token只读探测原始下载接口，可验证是否app_scope_not_applied，不读取私人文件；文件不存在也不能当作真实下载成功。原始文件仍须在scope批准发布、已共享并提供链接后验收。没有向真实群发测试消息或查生产；Windows与具体Office/PDF解析器仍须实机验证。

无响应先检查是否@正确机器人、群绑定；只有元信息核对requiresFileInspection/attachmentIds/实际任务清单。CLOUD_APP_SCOPE_MISSING交管理员补齐当前应用最小scope；CLOUD_FILE_ACCESS_DENIED核对文件共享及下载权限；其他下载/导出失败保留实际缺口，不说成空文件或业务根因。若文件夹链接需要选目标、路径核对失败或解析器缺失，按具体提示处理。补齐后沿原话题重试，不让用户反复上传同一完整文件。
