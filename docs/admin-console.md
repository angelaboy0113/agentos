# AgentOS 本机管理控制台

## 用途与入口

管理控制台是已经运行的 AgentOS 的本机管理入口，不负责启动 AgentOS。先按当前平台的方式启动一体化服务，健康检查通过后，在同一台电脑访问：

```text
http://127.0.0.1:8787/admin
```

如果 AgentOS 没有运行，页面不会打开。控制台随 AgentOS 仓库和服务一起发布，不需要额外安装桌面程序或单独启动前端服务。

## 可以做什么

- 查看控制服务、Runner、当前模型和最近任务状态。
- 查看执行任务与普通飞书回复的统一记录。
- 按类型、状态和关键词筛选记录。
- 查看原问题、最终回复、模型、推理强度、总耗时、工具调用次数和处理时间线。
- 修改 AgentOS 后续任务使用的 Codex 模型与推理强度。
- 查看模型设置变更记录。

页面读取 `data/agentos.json` 的脱敏投影，不会把完整运行态文件直接交给浏览器，也不会展示 ChatGPT Token、飞书凭据、数据库密码或环境查询结果中的私密连接信息。

## 模型设置

选择模型和推理强度后点击“保存模型设置”。后台校验后原子更新 `config/codex-runtime.local.json`，保留其中已有的 `proxyUrl` 和 `codexBin`。变更同时写入 `data/agentos.json` 的 `adminAudit`，记录修改时间与修改前后配置，不记录账号凭据。

保存后的生效规则：

- 新的普通对话线程使用新模型。
- 新的 Runner 执行任务使用新模型。
- 新的环境排查规划线程使用新模型。
- 正在运行的任务继续使用启动时的模型，不中断、不迁移。
- 已存在的普通对话会话在下一轮发现配置变化后建立新线程，避免旧模型继续复用。

“继承本机设置”表示 AgentOS 不显式覆盖该项，由当前 Codex 配置决定。列表中的模型是否可用仍取决于当前电脑登录的 ChatGPT 账号；切换 Codex 账号后，控制台不会复制或绕过原账号权限。

## 任务与耗时口径

“任务记录”同时展示 Runner Job 和普通 Conversation：

- Job 的耗时优先使用执行结果中的 `timing.totalMs`，旧记录没有该字段时使用创建与完成时间计算。
- Conversation 使用 `timing.totalMs`，包含排队、AI 处理和飞书投递。
- 工具次数来自环境调查证据或最后一次公开工具活动；历史旧记录无法还原时显示 0。
- 最近 24 小时成功率只统计进入终态的记录，不把仍在排队或执行中的任务算作失败。

页面是运维观察入口，不替代飞书中的业务卡片，也不直接修改任务状态、业务代码或数据库数据。

## 安全边界

- 管理页面仅在 `127.0.0.1`、`localhost` 或 `::1` 回环监听时提供；AgentOS 配置为非回环地址时返回 404。
- 首次打开页面建立随机、仅本进程有效的 HttpOnly、SameSite 会话。
- 配置写入同时检查本机会话、同源 Origin 和管理请求头。
- 页面使用严格 CSP，禁止第三方脚本、跨站连接和嵌入 iframe。
- 不要通过端口转发、反向代理或防火墙规则把 `/admin` 暴露到局域网或公网。将来如需远程管理，应另行增加稳定身份认证和角色权限。

## 验证与排查

启动后依次验证：

1. `http://127.0.0.1:8787/health` 返回 `ok: true`。
2. `/admin` 顶部显示“AgentOS 正常”。
3. 最近处理区能看到现有任务或普通回复。
4. 保存一次模型设置后页面提示成功，`config/codex-runtime.local.json` 中对应字段更新。
5. 新发一条问题，详情中记录实际模型与耗时；执行中的旧任务不应改变模型。

页面打不开时先确认 AgentOS 进程和 `/health`。页面能打开但显示连接失败时，检查浏览器是否禁用了同源 Cookie，或是否通过其他域名、代理地址访问。模型保存成功但新任务报模型不可用时，使用 `codex login` 检查当前账号，并选择该账号有权使用的模型。
