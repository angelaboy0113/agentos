# AgentOS 本机管理控制台

## 用途与入口

管理控制台是已经运行的 AgentOS 的本机管理入口，不负责启动 AgentOS。先按当前平台的方式启动一体化服务，健康检查通过后，在同一台电脑访问：

```text
http://127.0.0.1:8787/admin
```

如果 AgentOS 没有运行，页面不会打开。控制台随 AgentOS 仓库和服务一起发布，不需要额外安装桌面程序或单独启动前端服务。

## 可以做什么

- 查看控制服务、Runner 池总槽位、在线槽位、忙碌槽位、当前模型和最近任务状态。
- 查看执行任务与普通飞书回复的统一记录。
- 按类型、状态和关键词筛选记录。
- 查看原问题、最终回复、模型、推理强度、总耗时、工具调用次数和处理时间线。
- 修改 AgentOS 后续任务使用的 Codex 模型与推理强度。
- 查看模型设置变更记录。
- 通过受保护的 `/api/v1/admin/browser-health` 检查 Mac 日常 Chrome 桥接是否可用；接口只返回模式、运行状态和窗口数量，不返回标签页地址或页面正文。

页面读取 `data/agentos.json` 的脱敏投影，不会把完整运行态文件直接交给浏览器，也不会展示 ChatGPT Token、飞书凭据、数据库密码或环境查询结果中的私密连接信息。

## 模型设置

选择模型和推理强度后点击“保存模型设置”。后台校验后原子更新 `config/codex-runtime.local.json`，保留其中已有的 `proxyUrl` 和 `codexBin`。变更同时写入 `data/agentos.json` 的 `adminAudit`，记录修改时间与修改前后配置，不记录账号凭据。

保存后的生效规则：

- 新的普通对话线程使用新模型。
- 新的 Runner 执行任务使用新模型。
- 新的环境排查规划线程使用新模型。
- 正在运行的任务继续使用启动时的模型，不中断、不迁移。
- 已存在的普通对话会话在下一轮发现配置变化后建立新线程，避免旧模型继续复用。

“继承本机设置”表示 AgentOS 不显式覆盖该项，由当前 Codex 配置决定。列表中的模型是否可用仍取决于当前电脑登录的 ChatGPT 账号；切换 Codex 账号后，控制台不会复制或绕过原账号权限。

## 任务与耗时口径

“任务记录”同时展示 Runner Job 和普通 Conversation：

- Job 的耗时优先使用执行结果中的 `timing.totalMs`，旧记录没有该字段时使用创建与完成时间计算。
- Conversation 使用 `timing.totalMs`，包含排队、AI 处理和飞书投递。
- 工具次数来自环境调查证据或最后一次公开工具活动；历史旧记录无法还原时显示 0。
- 最近 24 小时成功率只统计进入终态的记录，不把仍在排队或执行中的任务算作失败。
- 连续只读调查的源码、数据库和网页步骤归在同一个 Job 记录中；时间线保留每一步证据，不再用多条“开发”记录拼接一次问题。

页面是运维观察入口，不替代飞书中的业务卡片，也不直接修改任务状态、业务代码或数据库数据。

## 安全边界

- 管理页面仅在 `127.0.0.1`、`localhost` 或 `::1` 回环监听时提供；AgentOS 配置为非回环地址时返回 404。
- 首次打开页面建立随机、仅本进程有效的 HttpOnly、SameSite 会话。
- 配置写入同时检查本机会话、同源 Origin 和管理请求头。
- 页面使用严格 CSP，禁止第三方脚本、跨站连接和嵌入 iframe。
- 不要通过端口转发、反向代理或防火墙规则把 `/admin` 暴露到局域网或公网。将来如需远程管理，应另行增加稳定身份认证和角色权限。

## 验证与排查

启动后依次验证：

1. `http://127.0.0.1:8787/health` 返回 `ok: true`。
2. `/admin` 顶部显示“AgentOS 正常”。
3. 最近处理区能看到现有任务或普通回复。
4. 保存一次模型设置后页面提示成功，`config/codex-runtime.local.json` 中对应字段更新。
5. 新发一条问题，详情中记录实际模型与耗时；执行中的旧任务不应改变模型。

页面打不开时先确认 AgentOS 进程和 `/health`。页面能打开但显示连接失败时，检查浏览器是否禁用了同源 Cookie，或是否通过其他域名、代理地址访问。模型保存成功但新任务报模型不可用时，使用 `codex login` 检查当前账号，并选择该账号有权使用的模型。

网页排查提示 `BROWSER_BRIDGE` 时，可在已登录管理会话中请求 `/api/v1/admin/browser-health`。`ok: false` 表示 AgentOS 后台进程尚不能控制 Chrome，不代表业务网站退出登录；先核对 Chrome 的 Apple Events JavaScript 开关和 macOS 自动化授权。恢复后，处于橙色等待状态的原任务会自动续跑。

## 网页加载与标签恢复

网页调查先核对标签地址与当前应用范围，再检查DOM是否就绪、业务加载遮罩和可读内容。新标签空白、网络错误、加载中或SPA空壳时，原Job持续等待并更新进度；没有整个任务等待时间或重试次数上限。正常DOM已就绪且业务内容可用时，不因尚未下载完图片等无关资源卡住。原来的单次调用超时、当前授权及用户停止检查保持。每次RPC只做短探测，等待在Runner中进行，不占用共享Chrome队列。

标签关闭会重新定位原入口；标签移到其他窗口按实际tabId寻找。用户已转到其他应用时不读取正文、不导航或关闭该用户页面，另开后台入口并保留原Chrome选中标签。程序自己建立的网络错误页按原批准入口恢复加载，不扩大到其他域名或应用路径。持续跳出范围时显示等待原因，维护者核对登记入口，不能解释为业务账号权限不足。登录页面就绪后仍沿原登录接续流程处理，加载等待不代替登录。

页面未就绪不执行点击/填写；恢复后引用失效则返回新快照，按新引用继续。操作已经发出后仅轮询结果，不自动再次点击；响应不确定时先核对结果，不宣称未执行。正常“0条记录”属于已加载结果。

无新配置或依赖；待活动任务自然完成后按原流程重启。真实macOS后台Chrome延迟页面验证通过，原选中标签和前台状态保持；这不等于已查清某个员工的报表权限。未模拟企业全网断网，未验证Windows实机。

空壳且确认启动script/link资源HTTP失败时，程序自建标签按原入口重载；普通慢空壳不反复重载。用户标签遇此错误改用后台入口，不刷新用户当前内容。外部验证记录区分“延迟页面真实恢复通过”与“PRD入口本次仍为空壳”，不能声称员工权限问题已经解决。

## 首末期间报表与排查

本版本无需新增配置、凭据、权限或依赖。normalize_period_dataset的fields指定column/as/unit（月month或日day）、nulls（error/keep），分列年/月可加yearColumn；新增标准列不覆盖原值，非法日期不当范围外丢弃。project_dataset的fields[column,as]只投影/改名、不改值去重。select_period_dataset指定真实keyColumns、periodColumn、unit、select=first/last、ties=all/error、nulls=error/exclude（exclude需nullEvidence）。返回全部选中原行和并列/空期间计数。

多来源末期集合先分别标准化和投影，再按有依据的业务键union。金额计算另用完整period_dataset网格，按对象+标准期间join，最后以完整主对象左关联保留无发生者。不要将全年网格最后一个月份当作每个对象真实最后业务月份，也不能默认财务调整、产生额、申请、上账全部决定同一个末期；由项目口径/原问题确定。

算术missing=empty显式传播未知，金额0保持0；最终文件逐行重算与草稿一致。无使用记录的末笔月份及结余可保留空白并说明，不补造零。最终核验仍要求独立范围与分量基准；证明只在当前核验内按不可变依赖复用，不跨操作缓存核验通过状态。

转换、数据集读取、关联、导出核验等本地操作不套数据库请求的固定时限；每步和处理过程中仍检查授权及取消。SQL与外部网络继续沿原单次请求规则，refresh_report包含实际数据库刷新，保留原数据库执行规则。慢本地计算不应误报网络故障。部署等活动任务自然完成后按现有流程空闲重启，检查健康、版本与运行数据；不强停业务任务。macOS真实只读报表及后续复用验收，Windows无实机验收。

## 完成表情包

负责人机器人配置了单聊接收、消息读取和机器人发消息权限后，管理员可在飞书私聊中从表情包面板发送原生表情。收到登记回执后，素材保存在本机，按机器人隔离，同一表情标识只登记一次。其他身份和群聊表情不入库。已收到的表情标识用于飞书原生 sticker 回复。

首次登记后，新提交的普通群问题在成功回答、完成通知及适用的报表文件送达后，从素材库随机选一张，发送到原消息或原话题。私有任务、审批等待、受阻和失败结果不触发表情。每轮固定选择和幂等键，表情投递失败独立重试。素材库为空时，完成通知按原流程送达。
