# AgentOS 本机管理控制台

## 用途与入口

管理控制台是已经运行的 AgentOS 的本机管理入口，不负责启动 AgentOS。先按当前平台的方式启动一体化服务，健康检查通过后，在同一台电脑访问：

```text
http://127.0.0.1:8787/admin
```

如果 AgentOS 没有运行，页面不会打开。控制台随 AgentOS 仓库和服务一起发布，不需要额外安装桌面程序或单独启动前端服务。

## 可以做什么

- 查看控制服务、Runner 池总槽位、在线槽位、忙碌槽位、当前模型和最近任务状态。
- 查看执行任务与普通飞书回复的统一记录。
- 按类型、状态和关键词筛选记录。
- 查看原问题、最终回复、模型、推理强度、总耗时、工具调用次数和处理时间线。
- 修改 AgentOS 后续任务使用的 Codex 模型与推理强度。
- 查看模型设置变更记录。
- 通过受保护的 `/api/v1/admin/browser-health` 检查 Mac 日常 Chrome 桥接是否可用；接口只返回模式、运行状态和窗口数量，不返回标签页地址或页面正文。

页面读取 `data/agentos.json` 的脱敏投影，不会把完整运行态文件直接交给浏览器，也不会展示 ChatGPT Token、飞书凭据、数据库密码或环境查询结果中的私密连接信息。

## 模型设置

选择模型和推理强度后点击“保存模型设置”。后台校验后原子更新 `config/codex-runtime.local.json`，保留其中已有的 `proxyUrl` 和 `codexBin`。变更同时写入 `data/agentos.json` 的 `adminAudit`，记录修改时间与修改前后配置，不记录账号凭据。

保存后的生效规则：

- 新的普通对话线程使用新模型。
- 新的 Runner 执行任务使用新模型。
- 新的环境排查规划线程使用新模型。
- 正在运行的任务继续使用启动时的模型，不中断、不迁移。
- 已存在的普通对话会话在下一轮发现配置变化后建立新线程，避免旧模型继续复用。

“继承本机设置”表示 AgentOS 不显式覆盖该项，由当前 Codex 配置决定。列表中的模型是否可用仍取决于当前电脑登录的 ChatGPT 账号；切换 Codex 账号后，控制台不会复制或绕过原账号权限。

## 任务与耗时口径

“任务记录”同时展示 Runner Job 和普通 Conversation：

- Job 列表、详情和概览的任务耗时使用原问题创建至当前任务终态事件的墙钟时间（含排队、等待和恢复）；无关联问题时退回任务创建时间。保留原始 timing 供诊断，但不拿最后一轮模型计时冒充整题耗时。
- Conversation 使用 `timing.totalMs`，包含排队、AI 处理和飞书投递。
- 工具次数来自环境调查证据或最后一次公开工具活动；历史旧记录无法还原时显示 0。
- 概览不混用接单回复和业务问题。每个机器人/群/问题卡按最新 Job 结果计一次；没有 questionId 的旧任务按独立 Job 计。任务记录列表仍保留所有执行和普通回复审计，分页不影响概览汇总。
- “完整完成”仅统计 completed 且 outcome=ready；partial、blocked、failed、结果未标明分别展示。“完整完成率”的分母为最近24小时结束的完整/部分/受阻/失败/结果未标明问题；取消、仍执行、等待补充/审批单列，不放入分母。标记依据程序结果，不等于人工逐项业务验收或附件送达证明。
- 滚动24小时按当前任务终态事件时间筛选，兼容旧记录 completedAt/updatedAt；创建在窗口外、刚完成的长任务仍计入。无效时间和未来时间不计，后续投递或维护更新不延后已有终态事件的时间。
- “任务耗时中位数”按上述已结束问题的原问题创建至终态计算，包含排队、等待和恢复；没有问题创建时间时用任务创建时间。没有有效样本显示“—”，偶数样本取中间两项平均，不使用最后一轮模型 timing 替代整题用时。普通回复耗时仍可在各自详情查看。
- 默认排除以“【维护自测…】”“【AgentOS维护自测…】”显式前缀或 isMaintenanceTest=true 标记的维护问题；可勾选包含，页面与API同步显示当前口径。普通正文提到自测、SIT测试环境或管理员本人提问不因此排除；未标记的历史测试无法可靠识别，不擅自推断。执行中指标及Runner占用始终保留真实自测活动。
- 受本机管理会话保护的 GET /api/v1/admin/overview 支持 includeMaintenance=true，返回 metricPolicy、分类 counts 与 performance.sampleCount。只读取现有留存数据，不后台回填，不改变历史保留、积分、任务或投递。每个助手各有一张卡的多@需求按各卡计，不冒称跨助手自然人问题去重。
- 连续只读调查的源码、数据库和网页步骤归在同一个 Job 记录中；时间线保留每一步证据，不再用多条“开发”记录拼接一次问题。

页面是运维观察入口，不替代飞书中的业务卡片，也不直接修改任务状态、业务代码或数据库数据。

## 安全边界

- 管理页面仅在 `127.0.0.1`、`localhost` 或 `::1` 回环监听时提供；AgentOS 配置为非回环地址时返回 404。
- 首次打开页面建立随机、仅本进程有效的 HttpOnly、SameSite 会话。
- 配置写入同时检查本机会话、同源 Origin 和管理请求头。
- 页面使用严格 CSP，禁止第三方脚本、跨站连接和嵌入 iframe。
- 不要通过端口转发、反向代理或防火墙规则把 `/admin` 暴露到局域网或公网。将来如需远程管理，应另行增加稳定身份认证和角色权限。

## 验证与排查

启动后依次验证：

1. `http://127.0.0.1:8787/health` 返回 `ok: true`。
2. `/admin` 顶部显示“AgentOS 正常”。
3. 最近处理区能看到现有任务或普通回复。
4. 保存一次模型设置后页面提示成功，`config/codex-runtime.local.json` 中对应字段更新。
5. 新发一条问题，详情中记录实际模型与耗时；执行中的旧任务不应改变模型。

页面打不开时先确认 AgentOS 进程和 `/health`。页面能打开但显示连接失败时，检查浏览器是否禁用了同源 Cookie，或是否通过其他域名、代理地址访问。模型保存成功但新任务报模型不可用时，使用 `codex login` 检查当前账号，并选择该账号有权使用的模型。

网页排查提示 `BROWSER_BRIDGE` 时，可在已登录管理会话中请求 `/api/v1/admin/browser-health`。`ok: false` 表示 AgentOS 后台进程尚不能控制 Chrome，不代表业务网站退出登录；先核对 Chrome 的 Apple Events JavaScript 开关和 macOS 自动化授权。恢复后，处于橙色等待状态的原任务会自动续跑。


## 使用统计（1.79.0）

在本机控制台选择“使用统计”。日期按 Asia/Shanghai 自然日过滤，结束日期包含当天；可选择上个完整周（周六至周五）、全部留存日期、助手、业务提问/全部公开互动、是否排除管理员、姓名合并/机器人身份分别展示。默认业务提问与追问、排除可信配置中的管理员。榜单相同次数并列，不作绩效评价。

数据来自现有 conversations 的用户消息，按 profile+chatId+messageId 去重，不把关联 Job、机器人输出、后台续跑额外计数。私聊、私有话题、敏感凭据消息不进入榜单或明细。环境补充、取消和常见闲聊通过显式模型分类/保守规则识别，不是模型重新分析历史；旧记录分类可能不全，不保证与人工审核的周报数量完全一致。切换“全部公开互动”可检查范围差异，仍排除私有和敏感消息。每个人行可展开其消息记录并打开现有任务详情；每页50条，有完整分页，统计不受分页截断。话题内引用标记为追问，不等同于新任务数量或完成数。

成员姓名使用各机器人现有群成员只读能力，缓存15分钟且并发合并；权限/网络失败显示姓名暂不可用，仍保留真实记录，不猜姓名。可信 humanIdentities 优先关联；选择按姓名合并时，仅用于统计展示，同名成员可能合并；可切换机器人身份分别检查，不用于鉴权。管理员排除依 ownerOpenIdsByProfile/ownerOpenIds 判定，不写死姓名。不新增权限、配置或依赖。

受本机会话保护的 GET /api/v1/admin/usage 提供 start/end（YYYY-MM-DD）、profile、projectId、chatId、person、page、scope、grouping、excludeAdmin、timeZone 过滤。统计返回只读脱敏投影，不返回凭据、原始配置、Token或执行器内部上下文。界面显示最早留存时间及保留策略，不把“全部留存日期”说成永久全量历史；保持原有历史清理机制，不后台回填或新取生产业务数据。不存在历史记录的日期不补造。

发布与控制台一起进行；修改后需在所有任务/消息/投递自然空闲时按部署流程重启现有唯一服务，不另启实例。验证：同一消息与Job不重复、多个助手/跨日、同名及缺姓名、管理员排除、敏感/私有隔离、并列排行、个人记录分页及本机会话授权。此菜单不发送周报、不启用定时推送。其它OS/跨机安装仍需目标平台验证。


## 有效提问积分与 Excel 导出（1.80.0）

每条纳入统计的有效公开业务提问或追问计1分（包括受阻或失败的业务提问，不把任务成功当成加分条件）。沿用profile/chat/message去重，机器人回复、Job、后台续跑不重复加分；闲聊、环境补充、取消/停止指令及无内容无附件的空消息为0分；敏感消息、私聊和私有话题仍排除。业务识别沿用既有模型标记与保守规则，是参与积分，不是人工审查的问题质量分。按积分降序排名，同积分并列；提问/追问次数保留独立字段。“全部公开互动”可显示0分记录，不将闲聊转为有效积分。积分仅由当前筛选范围及留存记录计算，没有永久累计账本；原历史保留策略不改变，过期记录不可从本页面还原积分。

点击“导出 Excel”下载真正.xlsx，不是CSV改扩展名。使用与页面相同的时间、助手、统计内容、管理员及人员合并条件；点选某个人后导出该人，清除人员选择则导出所有人。一次读取同一份状态快照，生成“积分榜”“提问明细”“统计口径”；完整导出匹配的所有记录，不受页面50条分页限制。积分和次数是数值单元格；用户文字始终按文本写入，不创建公式、宏、外链或图片。明细包含有效公开问题原文（不只页面240字符摘要），超过单元格长度的文本分为问题续文列，超过工作表行数的明细分表。Excel文件限制仍以标准格式/本机资源为准，不声称无限制。

GET /api/v1/admin/usage/export.xlsx 使用与统计API相同的本机会话及过滤参数，返回attachment、no-store；不对公网开放，不上传飞书，不写业务数据/任务状态。导出过程中health.adminUsageExports>0，维护发布须等待其回到0，不能在文件下载中重启。导出失败明确提示，可重新导出，无需重跑业务查询。

新增随程序可迁移依赖exceljs 4.4.0（MIT），package-lock锁定；仅其uuid子依赖覆盖为11.1.1以避开旧版公告，实际Excel读写回归覆盖。升级安装用npm ci（与程序同Node要求）；不依赖本机Python/桌面Excel/模型生成表格。测试覆盖真实XLSX解包回读、数字积分、公式样式文本不执行、长文本、跨页、个人/日期/管理员范围、空表和本机会话拒绝；Excel桌面各版本和其它OS未逐一实测。
