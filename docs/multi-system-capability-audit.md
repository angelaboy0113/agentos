## 源码版本与历史

配置沿用 `projects.local.json` 的 `analysisSourceMode=isolated`、独立 `analysisSnapshotRoot` 和 `analysisEnvironments`。新问题核对远端指定分支；失败阻塞，不用旧缓存冒充最新。同一问题在可信进度记录中保存 `analysisSourceSnapshot`、问题ID和环境，跨阶段接续保持原提交。新问题的新版本、远端回滚均另行按实际提交选择缓存。

模型先用只读 `git log/blame/show/diff`。浅仓无法回答历史时，结构化结果填写：

```json
{"sourceHistoryQuery":{"repositories":["service-a"],"reason":"核对规则引入提交及前后行为"}}
```

仓库必须来自本任务实际 `sourceSync.repositories`；不需要补取时填写null。Runner在跨进程锁内按清单固定SHA补齐祖先，不切换HEAD、不改源码/原清单；保存历史状态和原Codex线程，再在同一只读会话继续。多个仓库按需请求，没有全任务次数截止；重复完全相同且无新目标的请求会停止重复操作并保留缺口。认证失败、来源变化、来源不可用与不完整历史分别记录，仍保留有效源码证据。完整历史允许离线复用。

旧缓存的来源没有新指纹时，先与可信配置来源核对；有历史审计且已回收的版本可从相同origin恢复原提交。缺审计、缺对象、远端不再提供该SHA、跨机器绝对路径尚未迁移或来源变更时明确受阻，不能悄悄改用最新。旧任务不自动重跑。当前缓存独立复制，不使用共享objects/hardlinks；完整种子保留所选提交可达祖先，以供后续复用，避免反复下载。不同版本仍有独立对象占用，尚未实现跨系统共享对象池。

创建、核验、补历史、恢复与回收共用项目缓存锁。`.git`必须为当前缓存内独立目录；拒绝worktree、commondir、alternates/http-alternates、符号/硬链接和特殊元数据文件；清除继承的Git路径覆盖变量。锁辅助进程退出后禁止发布/删除。锁需要Python3/fcntl；Windows此路径未支持。只读模型的提示词不等于额外操作系统沙箱。

## 提交时间与上线时间

Git提交、分支tip、文件时间只能证明代码版本。已有授权的发布记录可通过现有读库工具读取成完整数据集，调用 `deployment_evidence`，明确系统、环境、应用、成功状态、提交或构建号及实际部署时间列。系统与环境由任务可信绑定，不能用别的系统记录证明上线。

时间戳须有明确秒/毫秒单位；无时区时间需要显式offset和时区依据，不猜本机时区。返回原取数时间、查询来源、筛选计数和实际发布映射；recordOffset/limit仅分段展示记录，按nextOffset续读，不重查数据库，offset仍专指时间偏移；无记录不等于未部署。配置示例见 `config/capabilities.example.json`。

这是一条已有记录的取证路径，不会创建CI/CD连接或扩大访问范围。当前实例没有独立发布平台/构建运行版本入口；需部署团队提供真实只读入口、应用/环境映射与权限后再验证。已有业务库若确有获准的发布表可以继续取证；不能凭字段名称猜测它就是部署记录。

## 期间、精确金额与旧配方

`period_dataset`使用完整主对象、实际复合键和多个完整来源；展开month/day或显式values期间，保留无发生对象。来源必须声明重复处理error/sum、范围外error/exclude及依据、无记录missing与真实空值nulls的zero/empty/error策略。可选statusAs输出known/unknown/no_occurrence，排除统计区分对象外与期间外。重复在规范化后检查，不能取第一条。

- 月来源统一支持 `202601`、数值202601、`2026-01`、`2026-1`、独立year/month列。
- 日来源支持YYYYMMDD或YYYY-MM-DD，验证跨年、闰日、实际日历；非法月日、空期间、带时间/时区歧义均拒绝，不能先排除再补零。
- 自定义values保持显式顺序和原字符串语义，不套用日历转换。
- 金额使用BigInt定点，最多40位整数/12位小数；浮点及不安全整数不能当作精确金额。
- 当期流量、从指定期间起点的逐对象累计、期初余额与期末余额分别定义。期初须另取真实来源，compose显式相加，不把流量自动称余额。

新派生配方记录calendar-v2；保存、恢复、集中刷新和文件核验使用相同版本。calendar-v1及正确的未标版本旧配方继续验证；未标版本且原始来源曾因年月格式不一致被漏掉时拒绝沿用旧零值，须重建期间数据、草稿和独立核验。旧错误文件不会因升级自动变绿或补发。

## 数据、文件与投递

保留完整分页/游标优化、复合键和受控两表一对多LEFT JOIN。唯一维度enrich不承担一对多展开。移除草稿数量、来源数、输出列数、维度步数/字段数及刷新依赖图深度等不必要固定障碍；循环、重复键、实际权限/配置容量与真实单次请求超时继续校验。读取/合成仍受物理内存磁盘约束，并未验证GB级合成。

普通select/group_count长字段超出模型单次展示预算时，完整脱敏字段保存在任务目录，返回evidenceRef；`read_dataset`按实际行/列及textOffset分段读取，无额外SQL。真实null保留null。有限行样本标complete=false，可恢复读取但不进入完整数据集目录，不能当完整对象范围参加报表。完整数据集沿用授权指纹、24小时寿命、SHA-256和目录边界。跨轮保留原取数时点，不伪称同一事务。

CSV草稿、finalize金额/范围核验、实际文件逐行检查、审阅接受、上传和消息投递是独立状态。期间数值必须核对独立原始来源展开的逐行当期/累计，不能只核年度总额；同一查询仅改输出别名或空白大小写不构成独立证据。查询身份防重只是保守检查，不证明两个不同SQL业务上独立正确。

普通Excel可打开需求可明确交付CSV；原生XLSX、多工作表/公式仍未实现，不能改扩展名冒充。飞书单文件上限依现有29,000,000字节分卷策略处理；文件失败只续发未送达分卷，不重查库。当前最终单文件交付流程保留，不把过程草稿批量发群。真实外部上传/业务口径仍须各部署自行验收。

## 登录、错误和恢复

Codex `account/read`仅对明确RPC临时超时恢复读取并显示进度；断线/永久错误不盲重试，thread/start、模型执行、业务查询和写入不随登录重试重放。迟到RPC回应安全忽略。原错误码、接口与环节保留；本机登录超时不能解释为DB超时或要求缩小整个问题。

先有有效源码结论、后续环境读取失败时保留结论和真实缺口，任务维持blocked；不会用不符合部分结果协议的旧环境证据二次保存而覆盖原错。旧等待/卡片、恢复授权和原问题范围仍由现有状态机验证；重启不自动改变任务版本或重跑旧业务查询。

没有新增整任务耗时、总轮次、总调用数截止。单次网络/数据库超时、用户停止、权限校验和既有重复无进展判断继续生效。Codex模型等待默认无隐式超时；本机登录读取有单请求超时和定向重试。

## 中断卡片的诊断信息

1.49.2将安全诊断贯通执行进程、worker IPC、连续调查收尾、状态保存与卡片。卡片提供中断环节、确认的错误类型、已记录的安全错误码/HTTP状态/退出信息，以及下一步建议；executionFailure随结果持久化，重启读取不丢失分类。源码调查、环境读取、模型结果返回和本机回执分别标明。

网络连接被重置、域名解析失败和连接被拒分别描述；模型回复流中途关闭只说明断流，不能自动认定是本机断网。进程退出信号不能单独证明内存不足。未分类故障明确原因待核实，维护者按任务编号看本机记录；旧卡没有原始记录时不能追溯补造。展示固定说明与白名单元数据，不把原始错误正文、地址、令牌或stderr发到群里。

错误详情不会把未完成的任务变为已完成，也不自动重跑整个任务或重放业务写入；已接受的完整交付与后续补充中断仍按原有规则分别记录。既有源码/数据证据和待核实目标继续保留。

## 维护、打包与验证

源码清理默认保留近期环境版本、活动/等待任务及未投递依赖；未知/修改目录、未提交内容、业务源码、开发worktree、配置、凭据、登录资料和报表不归此清理。删除前写轻量 `.snapshot-audit` 清单，不复制整套旧源码。30天问答历史机制保留，两者不按同一年龄回收。

预演：

```sh
node scripts/prune-source-snapshots.mjs --projects /your/agentos/config/projects.local.json --state /your/runtime/data/agentos.json
```

实际删除必须经运行实例的本机管理会话、同源及x-agentos-admin校验，并在权威状态事务中重新核对引用：

```sh
node scripts/prune-source-snapshots.mjs --apply --server http://127.0.0.1:YOUR_PORT
```

不要对停机状态副本使用apply、不要使用其他实例端口。此命令会执行清理，应先审阅预演；本次生产只预演，无候选删除。认证和批量状态锁不是可绕过的交互提示。

部署前检查活任务和未投递，备份本实例状态/私有配置，仅更新专用分支，等待原进程树自然退出后启动；不强制终止任务。回退使用专用分支revert提交、空闲停稳后部署，不reset/覆盖数据；先前合法源码与报表保留。

`node scripts/verify-capability-package.mjs`核查新增模块、schema、脱敏示例及文档。代码归档须含它们和package-lock；完整私有迁移仍按停稳后加密备份整个实例（保护datasets、source-manifest、.snapshot-audit、状态/回执及现有私有配置），排除依赖时在目标机npm ci。不会替用户复制真实凭据进公开包。macOS本机回归与历史CSV回放不等于Windows/Linux完整迁移验收；POSIX锁之外的SSH worker仍用原独立打包器。

本次最终测试数量、历史回放范围、服务版本和提交以 `docs/maintenance-history.md` 及实例私有部署记录为准。未获取当前多系统飞书实施文档地址，已同步本地公开手册；没有修改旧TPM手册或声称外部文档同步成功。
