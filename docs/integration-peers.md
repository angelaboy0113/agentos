# 关联系统数据库只读协查（1.59.0）

解决“上游提示成功、目标系统没有记录，但数据可能进入另一个已接入系统”一类问题。原任务、提问人、话题和机器人身份保持，关联数据库单独规划与核验，不把另一系统数据源改登记为当前项目。

默认关闭。管理员在既有 `projects.local.json` 的两个项目分别配置 `readOnlyIntegrationPeers: ["另一项目ID"]`，建议同时用 `integrationPeerEnvironments: {"另一项目ID": ["允许的environmentId"]}` 限定关联入口（配置后未列入的入口不可用），并确认两个机器人在同一个群有真实的 `chatProfileProjectMap` 绑定。参考[配置片段](../config/integration-peers.example.json)，须合并入完整项目配置，不覆盖仓库、规范、环境或管理员设置。还应修订部署自己的系统说明：纯另一系统问题仍请对应助手；本系统集成问题可通过明确授权的协查目录核实旁路接收/落库，不能混用业务口径。配置与说明变更按该实例维护流程加载、复核旧任务。

控制面与Runner共同核验：原任务必须是群内只读analysis，发起profile仍绑定原项目；双方显式互认，目标系统也绑定本群；仅已登记mysql/mongodb的reviewed investigate模板，运行分级与原问题源码分级一致。私聊、其它群、单向配置、未绑定系统、网页/调度/Nacos、固定模板、写入任务均不能借此跨系统访问。原有不同项目直接planQuery仍拒绝，不取消项目边界。

源码执行目录仅展示符合条件的关联数据库，并标记subjectProjectId/requestingProjectId。模型仍通过environmentQuery申请真实范围，控制面重新规划；目标plan的projectId为目标项目，原originProfile/senderId保持，不能冒用目标机器人用户或管理员身份。claim、续期、每次工具调用及容量恢复都复核协查权限，撤销后不重放旧查询。

目标系统按自己的环境、连接、集合/表和范围执行；凭据不进入模型。关联数据集使用目标projectId与环境scope，原系统源码/业务定义不会被当成目标库规则。关联读取的连接端点不得自动回填成原系统的新数据源。现有各系统知识库与源码缓存不因协查自动共享；跨系统文件关联/任意源码访问不在此能力范围内。

调查仍先分清接收方、接口标识、实际记录与回执来源。记录相似或时间一致不是完整流水关联；另一个IFNO/KEY/接口的失败不能压过更直接的落库证据。提交时间、配置发布时间仍不能冒充实际部署版本。结果应逐来源标注系统、环境、取数时间、实际范围与未核实项，不声称不同查询是同一事务。

验收至少包含双向配置/同群绑定、不同环境拒绝、原身份保留、目标scope、claim/续期/重启、运行中撤销、容量恢复和连接来源不串用；真实OS自主查询与维护脚本查询分别记录。仅单测或提示词更新不能宣称完整业务链路通过。本模块不新增整任务截止、固定轮次或总调用上限。

迁移需带本模块、配置片段、系统说明、完整原任务/各scope数据集与证据；目标平台和完整私有跨机须另测。回退前等待空闲并备份新状态，复核未完成关联读取，不将其静默交给不支持协查的旧版本。

## 1.88.0：同任务已验证数据集接续

一个问题在原系统与已授权关联系统之间切换时，可读取本任务目录中前序阶段已经完整保存的数据集，避免重新查询同一批门店、订单或期间明细。允许范围只含原任务项目和当前目标项目、相同运行分级、当前配置仍能对应到原环境指纹且 `completeDatasetCount > 0` 的证据；不在同一任务目录的数据、第三系统、测试/生产跨级或已变更配置均不进入候选。

数据集读取仍由 `TaskDatasetStore` 核验真实路径、符号链接边界、环境scope、分块数量和SHA摘要；关联读取权限仍在当前阶段的claim、续期和每次工具调用前复核。此能力只复用已经取得的不可变证据，不共享凭据、不把关联库登记成原系统数据源，也不允许从旧数据假装完成“最新”查询。迁移须保留整个 `data/exports/<JOB>/datasets/`，仅复制最终CSV无法恢复此接续能力。


## 1.73.0：目录诊断与原身份接续

`taskReadCatalog.integrationReadStatus`只列当前绑定群的候选系统及状态：available、relation_not_configured、reciprocal_relation_missing、no_registered_read_scope、source_runtime_tier_unresolved。系统已接入不等于本话题可访问；目录缺失不是密码失效或业务异常，不能反复要求用户提供已有凭据。先核对本系统已有上游接收记录与处理结果，证据不足且确需关联时，再申请明确允许的目标。状态不暴露凭据、目标机器人用户ID或未授权数据库端点，不自动改变权限。

数据库调查阶段的continue_environment使用原任务（continuationJob）核对关系，当前subjectJob仍保持目标系统数据集/口径隔离。已明确规则并保存有效证据后，可在同tier的本系统和已授权peer之间直接申请下一步；每次重新读取项目关系，控制面仍独立签发并在claim、续期及工具前核验。关系撤销、其它群、私聊、不同运行分级或目录外来源均拒绝；未解决工具失败仍不能靠切换系统跳过。旧没有关联配置的任务保持同系统行为。此功能只涉及数据库读取，目标源码/知识不会因此自动混入原系统。

历史membersRead字段不应被维护者当作当前实际审批证明：现行planQuery对已登记受控只读模板采用policy:read-only；实际保障来自明确登记的关系、环境/模板范围、原身份绑定和执行器只读。不得为“协查”借用目标机器人身份、修改数据库账号权限或宣称不存在的人工审批。部署方必须记录授权人及具体新增范围。

固定网站POST查询若对象名含操作单词（如taskExecutionSettings），旧版可能因拆词误判而拦截。仅明确审核的精确路径、方法和读型末端可以识别这种复合对象名；未审核路径、独立execute/delete等动作段、删除/重发末端与写操作请求体仍拒绝。验证器与运行时一致，不能通过给整个接口前缀放行来修复。新增路径须先核对Controller/Service真实读语义。
