# 空白页面、公共静态依赖与部署脚本取证

页面已打开却持续loading，不等于密码错误或站点故障。隔离浏览器在未就绪结果的diagnostic返回被拦静态资源、公共资源获取失败、脚本错误类别和在途读取数；不导出控制台原文、参数、cookie或隐藏应用状态。没有增加整任务超时/轮次/调用次数截止。

已提交到原应用的导航即使等待脚本超时，也保留同一标签及 `navigation-timeout` 诊断，不丢弃可用登录页；未能提交到批准来源的导航仍按失败处理。私有浏览器启动时只关闭自身未绑定任务的初始 about:blank，不关闭用户窗口或其它任务页面。

对实际HTML引用的版本化公共资源目录，可审核 `staticResourceRoots`：HTTPS、至少两段的明确目录并以斜线结尾，例如 `https://assets.example.invalid/releases/build42/static/`。也可核实并固定该应用独立的资源命名空间，让其正常版本升级继续加载，不能直接批准整个CDN域。仅匹配目录内对应资源类型的JS/CSS/字体/图片，以及XHR/fetch读取的公共JSON（如语言包）；查询、编码绕路、业务接口、重定向与认证头仍不允许。目录属于部署配置，不能由模型新增；来源或应用命名空间变化后应重新审核。`browser_assets` 使用相同目录规则，仍只能沿当前页面实际脚本及其依赖取证。

扫码认证可单独审核 query 的 `loginReads`，每项含精确 `origin`、`path` 和 `types`。路径末尾斜线表示该明确认证目录，非斜线为精确路径；只允许GET，且必须在同一任务的父页面已显示登录/验证提示时才生效。跨源扫码iframe、图片或登录轮询与公共静态资源分开配置：前者由浏览器完成正常认证，后者用无凭据独立客户端读取。回调目标只能回到原应用来源。此配置不提供任意跨域访问、写接口或自动完成扫码/MFA。诊断记录方法、资源类型与脱敏位置，二维码/登录状态路径的临时标识以 `[opaque]` 代替。

如果入口HTML实际引用了独立CDN上的公共JS/CSS，维护者可在当前网站审核后的调查query配置 `staticResources` 精确HTTPS URL数组。示例见website-read.example.json。独立来源仅允许HTTPS；原应用本身使用HTTP时，可审核同源精确静态文件（例如含create字样的库文件），不能跨HTTP域绑定。必须实际核对来源与每个资源，不能把占位域当作已接通。不支持通配、凭据、查询参数、重定向或整个域名的API授权；GET还要匹配script/stylesheet/font/image类型与文件后缀。由独立公共请求获取，不带浏览器cookie、Authorization、Referer、表单数据；不接受Set-Cookie。真实业务请求仍按原同源/方法/路径/动作/租约检查。共享Chrome沿用用户浏览器网络方式，不能把本节隔离网络门控承诺扩展到它。

网页目录新增 `browser_assets`：空对象返回实际页面外部JS目录；用本任务ref可沿offset/limit/contentHash分页，或find字面定位。程序仅跟踪外部script标签及读取代码中可静态识别的同应用ESM相对import/from依赖；拒绝模型URL、脚本、文件路径和其他任务引用。不读取内联脚本、任意目录或source map；不执行代码中的指令。源码完整脱敏后分页，保留原始内容摘要、读取时间与实际部署资源URL。默认一次结果至多10000字符是传输分页，不截断整体调查；沿nextOffset续读，依赖图与缓存只属于该任务当前页面实例，重启后重新取证并按摘要区分版本，不冒称恢复了旧部署快照。

用途：固定提交缺少部署功能时，从实际脚本定位请求路径和服务，再核对该服务已授权数据库结构/索引、必要实际查询。不要只在最先选的库查不到就宣告缺数据。部署资源与固定仓库并列保留，不能切换HEAD或把部署包反称为固定提交；前端路径不能单独证明后台物理表、完整写校验或上线时间。明确区分结构/索引验证、真实列表登录读取和写入业务联动。获取箱唛、重建预约、上传、删除、推送等仍是写操作，不因来自测试环境或按钮可见而开放。

配置修改会改变计划指纹，应按原维护流程复核/续接，不直接复用旧授权签名；凭据引用和原机器人身份保持。代码迁移包必须包含website-assets.js、本文和回归；公共配置仅占位示例，私有静态依赖由目标部署实际审核。公共GET、合成两环境隔离和真实已授权测试站部署资源已验证；本机共享Chrome Apple事件、其他操作系统及整套跨机迁移尚未验收。

较大的前端入口可用find按功能字面定位正文，同时筛选相应依赖URL，importsTotal/importsFiltered明确区分筛选结果与完整依赖图；不必逐个读取无关模块。部署脚本文本/摘要/依赖URL参与实际调查进展，随机ref变化不算新证据。

## 新页面继承已审核的网站规则

同一项目后续可能访问新的仓库或详情 URL。维护者应把已审核的登录和资源规则绑定到稳定应用入口，并设置 `applicationRoot: true`，而非只给一个深层页面加规则。程序仅在同项目、同环境、同来源和路径前缀内复用入口，不复制跨系统凭据或认证会话。新系统首次扫码仍需本人正常完成；构建历史 API 令牌与网页会话独立。

部署前使用 `websiteApplication` 遍历实际仓库与环境，核对入口及策略，并测试错误系统和相邻路径不命中。配置验证不等于所有系统均已真人登录，更不等于已取得线上实例版本。入口绑定变更仍须自然空闲后备份、部署并验收。
