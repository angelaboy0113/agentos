# 用户要求的文件格式与原话题交付（1.104.1）

普通分析任务可以在保持源码、网页和数据库只读边界的同时生成输出文件。源码只读不再等于禁止写任务自己的交付物。四类系统助手共用此通用执行器，无需新增飞书权限或凭据。

## 入口与格式

群内照常 @ 对应助手，明确目标及格式。支持实际 HTML/H5 离线文件、PPTX、DOCX、PDF、PNG、XLSX、JSON、TXT、Markdown、CSV、SVG、ZIP。依赖按需加载，仅生成对应格式时引入渲染器，不给每个常驻消费者重复预加载Office库。HTML不是公网托管地址；发布可访问的网站还需要真实托管入口及授权。本版本HTML允许CSS、表格与details等浏览器原生交互，不执行任意脚本、联网、表单或框架。PPTX提供可编辑文字和表格；不承诺任意动画。XLSX默认字符串保真，不冒充已有公式、透视表或图表功能。其它格式需安装并验证对应渲染器，不能仅改后缀，也不能把不支持伪称为无限支持。

模型在结构化结果中填写 `documentRequests`（没有新文件时为null），每项 `format/title/purpose/content`。文本/HTML/SVG填写正文；Office/ZIP填写JSON字符串，结构见 `config/document-artifacts.example.json`。用户明确要求原生格式时不自行降级CSV。输出支持多文件，按原问题的真实要求共同交付。

## 执行与核验

Runner将模型内容交给受信任渲染器，不授予模型任意shell、联网或全机写入权限。输出仅位于 `data/exports/<jobId>/report-<uuid>.<format>`；符号链接/错任务路径拒绝。实际文件重新读取并校验摘要、Office ZIP CRC及必要部件、PDF/PNG签名、JSON语法和HTML离线策略。PDF及用户明确指定HTML/H5截图的PNG在无网络独立无头浏览器中渲染；默认PNG图片创作走Codex原生生图，见 [原生图片生成](native-image-generation.md)，不以网页截图代替。每份文件保存版本2核验收据与生成配方。

结构核验不证明业务金额或口径正确。已有CSV金额、范围、独立基准的原有核验不变；业务报表转XLSX使用 `content={"sourceReportId":"已核验CSV引用","sheetName":"数据"}`，逐格复用原CSV，不重查或损失大整数。不能通过新增排版工具绕过原业务核验。

只有原问题完整、原handoff门控通过且文件通过实际核验时，才接受其投递。partial/blocked不能因有文件就自动ready。明确要求格式但没有实际核验文件时保留未完成状态和具体缺项。文件生成、程序核验、业务证据、上传送达是不同事实。

## 投递、恢复与修改

复用持久化ReportDelivery outbox，绑定原问题、generation、机器人、群、私有收件人及原话题。多文件均投递；失败重试沿用同一文件摘要与幂等键，不重查业务、不重做整题。超平台单文件容量时，CSV按记录分卷，其它格式按字节分卷并附拼接说明；分卷不能冒充可独立打开的原格式。

后续同可见问题链可读取已交付文件。控制面重新核验实际文件与收据，向源码模型提供哈希绑定的生成内容；派生修改生成新文件，原件保持。不是跨群、跨机器人或跨私有任务共享文件。既有CSV导入、补列和独立金额重算路径保持。

## 部署、迁移与回退

新增固定运行依赖pptxgenjs、docx；以package-lock执行npm ci，不依赖开发机全局Office。保留既有Playwright/Chromium安装要求。代码包包含模块、schema、测试、公开示例和此文档；私有迁移须保留exports文件、核验收据和reportDeliveries。不得把私有产物加入Git。

回退须先自然空闲并备份最新状态。旧程序不认识版本2文档收据，不能继续发送这些待办；需先保留并停止其投递，不能删除文件/伪造成功或倒灌旧状态。仅对已验收源码版本做正常维护回退，保持后续任务及凭据。

验证包含格式实际内容、摘要/路径边界、双系统并发隔离、追问读取、原话题投递失败重试及完整回归。真实群同题、其它OS、完整跨机迁移与客户端Office排版验收必须另列结果，不以单元测试代替。

1.104.1补充：实际executeJob返回必须保留exportFiles和documentFailure，控制面再次核对原请求格式；仅有“已提交生成请求”的文字不能成为完成依据。回归覆盖真实Runner结果投影到文件登记的边界，不只调用独立渲染函数。

源码中途接续到环境、继续源码自查及切换源码环境时，同样登记并验证文件引用；下一轮复用同一成果及实际核验资料，避免已生成文件丢失后重复制作。

终轮审阅可接受前轮已生成、当前实际inspect_report哈希仍一致的最近格式文档；无需模型再次提交生成请求。金额类统计仍保留原CSV独立核验作为主证据，排版文档不能替代它。

源码汇总所需的已存明细通过[source-saved-evidence](source-saved-evidence.md)读取真实内容，避免只有数据集名字却没有原始值，反复绕回环境查询。

## 批量原生文件构建（1.105）

调查 Runner 使用每任务 `exports/<job>/working` 作为唯一可写产物区；固定源码目录、私有配置、其它任务及最终核验文件仍只读。权限配置仅传给该次 Codex 调用，不修改用户全局配置。旧只读会话不直接复用不兼容沙箱；保留问题上下文、固定提交和已保存数据后启动兼容会话。

大文件优先用程序批量解析源码或已核验的数据集、构建实际文件，最终只返回 `content:{artifactFile:"interfaces.html",sourceFile:"build.mjs"}`，`sourceFile` 可为 null。无需将数千条目录在模型结果JSON里反复转写。相对路径、目录链接、硬链接和实际格式均检查；原生HTML仍执行离线隔离和真实渲染检查，业务CSV/XLSX不绕过独立核验。构建脚本仅作哈希绑定来源保存，导入器不会执行它；修改已交付文件时提供不可变原文件及脚本来源，派生新产物。

Mac本机验证包括真实Codex调用能写本任务产物、不能写源码/其它任务/配置；已有硬链接会在调用前拒绝，沙箱内创建跨边界硬链接和符号链接写入均被拒绝。其它操作系统的命名权限实现未实测，不能将Mac结果外推。

浏览器排版检查由运行器内置的可信渲染器执行；分析沙箱拒绝模型自行启动Chromium不代表交付格式不可用。提交实际文件引用即可让渲染器核验。文件生成或渲染失败保留 `documentFailure` 的分类与具体原因，并将原问题保持为可接续的未完成状态，修正文件后重试，不重查已有业务数据，不通过第二次结果协议错误掩盖原始失败。

## 部分范围文档交付

新文档已经生成且结构/渲染核验通过，但原问题有外部缺口时，程序先接续一次实际文件审阅，避免文件因整项未完成而永远卡在awaiting_review。模型必须显式填写reportAssessment：decision=deliver_partial、coverage=incomplete，deliverables逐份给出fileId与该文件准确完整覆盖的范围；其它尚缺输出记required_output。当前文件本身来源不实、范围错误或公式错误仍禁止发送。审阅资料绑定sourceJobId、fileId、SHA及verificationHash，文档使用contentAudit，不伪造业务CSV的calculationAudit。只有全是文档且非tabularDelivery任务才能使用此文档审阅路径；金额/业务表格保持原独立核验。文件投递仍走原身份/话题/幂等outbox，整项保持partial及黄色，不得借附件成功改成全部ready。

重启恢复仅重新核验模型已明确选择 `deliver_partial` 的已完成文档：原任务必须仍为当前同代、同机器人/群/项目/发起人，旧检查摘要与实际文件/收据须一致。只补验收元数据和文件投递，不改业务结果、不补造模型判断、不重查数据库；取消、撤回、换代、改来源或金额表格不适用。

接单区分技术文档与业务统计：接口/参数字段目录、服务架构、部署说明即使含表格，也不天然是需要CSV金额核验的业务报表。混合业务金额/对象统计仍保持原核验；旧任务既有业务表格约束不静默删去。


## 1.111.0：生成、核验与交付分开

部分分析首次提交 documentRequests 时，允许先生成本任务范围内的真实文件，再按相同交接规则校验工件、已通过检查和明确缺口；不会因尚未登记文件而提前拒绝生成。其它交接错误、失败的必需检查和业务缺口仍阻止完成；生成成功不等于投递成功。

可信 Runner 可选配置绝对可执行路径环境变量 `AGENTOS_OFFICE_RENDERER`（LibreOffice/soffice）和 `AGENTOS_PDF_RASTERIZER`（pdftoppm），示例见 config/document-artifacts.example.json。设置在实例服务环境，不能由模型/文件指定。重启须空闲发布。PPTX/DOCX经原有宏/外部关系/路径检查后，在任务exports独立预览目录转换PDF和逐页PNG；各调用单独网络/进程故障等待窗口180秒，不设整任务截止，不截断页数。预览目录与任务文件一起保留和迁移，按原任务保留机制清理。macOS预览用系统黑体替代缺少的微软雅黑，原文件不改变；其他系统字体替代需实测。

`contentAudit.preview`记录 rendered/unavailable/failed、原文件SHA、全部页路径与SHA、实际页数。模型须查看所有图片，再做布局结论；渲染完成不自动意味着视觉通过、业务正确或动画兼容。未配置或失败保留已生成文件并给出明确渲染缺口，不声称已预览，也不要求重查业务。无额外数据库/飞书权限，不运行宏、外部关系或用户指定命令。Office客户端动态动画、其他操作系统和任意专有格式仍须分别验收。

实例启动器会清除继承的部署环境，独立实例应在自己的 runtime/instance.local.json 成对设置 officeRendererPath 与 pdfRasterizerPath（可信绝对可执行路径），启动器验证后映射上述环境变量；不能只在外部shell或LaunchAgent设置环境变量期待其保留。未配置的旧实例保持兼容，不能继承其它实例的渲染器路径。1.111.1已增加真实启动脚本回归。

已登记文件的旧预览曾因未配置或临时错误失败时，inspect_report/控制面审阅会按同一原文件摘要重新预览，并将派生预览单独缓存；不改原文件或不可变verification回执。缓存逐页校验路径、文件摘要和源文件绑定；被修改的预览不能继续复用。恢复配置后不要求重新制作文件或重新查库。
