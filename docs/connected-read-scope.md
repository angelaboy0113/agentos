# 已接入数据库的长期只读授权

部署管理员已经批准某些系统、环境的业务数据库只读调查后，不需要按每个业务表或集合重复申请。授权由维护者写入可信本机策略，不能从模型输出、日志或群成员自述取得。

复制 `config/connected-read-policy.example.json` 到私有目录，填入项目 ID 及 `uat` / `prd`，运行：

```sh
node scripts/prepare-connected-read-scope.mjs YOUR_ENVIRONMENTS_FILE YOUR_PRIVATE_POLICY NEW_PENDING_CONFIG
```

命令只生成新文件，不改运行配置或现有任务授权。审阅输出后，在无用户活动时按本实例备份、停稳、安装配置、启动和验收流程应用。迁移时携带私有策略、配置及原凭据引用，不将凭据提交代码仓库。

准备器按系统、环境、数据库、账号引用和传输通道去重；已有全库只读入口直接复用，否则增加独立 `connected_read` 模板。MySQL `tables: ["*"]` 和 MongoDB `collections: ["*"]` 表示管理员批准的当前业务库范围。模型仍须先发现实际表、集合、字段，按问题选择必要证据。原精确模板及强制筛选保留，不修改旧授权，不跨库、跨环境或借用机器人身份。

Mongo固定远程协议仍拒绝系统集合、敏感名称/字段、任意命令、原始pipeline和写操作。原SSH跳板、账号策略、完整性及独立文件核验保持。admin、local、config及MySQL系统数据库不在此准备器扩展范围。不会授予发布、接口重放或第三方尚未授权账号的访问。

新数据库接入、网站端点审核及外部单点登录分别验收；本准备器不会凭空发现账号、复制浏览器Cookie、授权任意网站或补出未保存的历史。失败保留具体环节，不能将空结果当零值或只改卡色。

回归覆盖多系统/环境隔离、同库去重、精确模板保留、运行授权不变、全业务集合配置及写命令/敏感范围拒绝。真实登录和业务交付另行记录。回退旧版前应移除整个新connected_read模板，保留原精确模板；不得仅解除旧requiredFilters，也不得倒灌旧任务状态。
