# Memory headroom and durable waiting

The independent instance shell launcher reads `runtime/instance.local.json` before exec and sets only the control process `--max-old-space-size`. `mainHeapMiB` defaults to 6144 (6 GiB), accepts integer 512..65536. Use `sh scripts/run-system-instance.sh --start`; invoking the `.mjs` directly does not set a V8 startup flag. Existing task forks explicitly use `execArgv: []`, so the new 6 GiB flag is not copied into every worker. Node heap is not RSS, a physical reservation or a whole-computer memory limit.

`memoryAdmissionMiB` optionally sets the conservative resident-memory budget for this control process and its descendants; default is half physical RAM. Example `config/instance-memory.example.json` contains no real credentials. Changing these settings requires this instance's normal idle/backup/restart procedure. Never change another instance or global Node settings.

The shared admission check pauses only NEW model turns and NEW Runner leases when control heap usage reaches 75% of its actual V8 limit or descendant RSS reaches its budget. It resumes below 60% heap and 80% RSS budget (hysteresis). Running jobs, renewals, cancellation controls and ready-result delivery continue. No task deadline, query-size cutoff or automatic replay is introduced. The Runner ceiling is also checked atomically across all leases in the control plane, so additional concurrent lease requests cannot bypass the configured slots. Cancelling jobs still occupy slots until process exit is confirmed. Normal Runner pool concurrency and intake concurrency remain independently configured (this change does not increase either). Queued work is persisted, not loaded into a new model/worker until admitted. Excess queued intake receives one factual wait receipt under the existing bot/profile/topic; no speculative intent card or successful completion/sticker is created. Retry uses the same idempotency key; wait receipts are serialized to avoid a burst of messaging subprocesses.

On macOS/Linux the sampler reads PID/PPID/RSS only, once per two seconds with single-flight and bounded output. It includes browser/worker descendants. Shared pages may be counted twice. Sampling failure is shown in health, preserves the last RSS sample and does not disable the in-process heap check. Windows tree RSS sampling is unverified/unavailable: heap admission still works; do not claim the macOS process-tree test covers Windows. Other applications are not included and this budget does not reserve RAM.

`/health.memoryAdmission` exposes allowed/reason, heap/RSS current and high-water values, tree budget, last sample and sample availability. Peaks refer to this process lifetime. State/queue checks remain scoped; no full root clone is added per queued request. Wait receipts persist in the original conversation records and migrate with runtime data. New code, tests, docs and example are in capability-package verification.

Admission is preventative headroom, not a guarantee of unlimited work: an already-running single step can still allocate a very large object, and external/browser/worker heaps can fail independently. Persistent source datasets must stay chunked/streamed. Validate bursts and long tasks using isolated synthetic data, actual scheduling/persistence and post-task memory observations; record natural heap release separately from explicit-GC diagnostics and process exit. Never trigger 20 unauthorized production queries as a load test. User/card success and real model/business latency are separate from scheduler stress results.

Rollback: stop only when idle, back up latest state/config/vault, revert code on the dedicated branch using normal checks; preserve all queued work and newer results. Older shell launchers ignore the two optional instance fields; remove only those fields if rolling back and retain all other instance configuration. Do not restore an old agentos.json to roll back code.
