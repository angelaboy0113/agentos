# 投递待维护

## 范围与触发

仅控制结果投递，不限制模型、查询或整个业务任务的耗时/轮次/调用数。卡片及完成提醒、报表文件、网页截图、原生表情、私聊表情登记回执共用 `src/shared/delivery-retry.js`。默认同一内容连续失败至少12次且持续至少30分钟转入 `attention`，两个条件同时满足才停止临时故障重试。已确认HTTP 400/401/403/404/413/422、明确本地权限/文件不可用及已识别布局拒绝提前停止；平台表格布局仍沿用现有降级修复，新表示不继承旧失败。未知错误保守按暂时故障处理，不保存原始错误字符串。

历史终态投递无新诊断时，累计至少12次、原问题/投递创建至少30分钟且没有相关活动任务，转入历史待维护。历史计数不能证明每次失败的根因，如实标为历史传输/校验失败。不得标记delivered或重查业务。

内容指纹绑定机器人profile、目的地、问题代次、实际卡片或文件/素材。重复render增加revision不清零；新内容/新目标不继承旧暂停。迟到失败不能暂停新的payload。成功送达清除本轮失败诊断。

## 管理入口与提醒

本机 `/admin` 的「投递待维护」显示类型、机器人、问题号、次数和原因；概览同时显示数量。`GET /api/v1/admin/deliveries` 仅管理员会话可读，不含正文、文件路径、凭据；`POST /api/v1/admin/deliveries/resume` 还要求同源Origin和 `x-agentos-admin: 1`，提交 `{group,key,fingerprint}`。状态/指纹改变返回409。不开放群成员权限。

核对目的地、权限与已有回执后恢复原投递。原文件、分卷消息号、机器人身份、素材及幂等键保持，失败记录进入adminAudit，不重新执行模型或数据库查询。表情已触发平台去重窗口复核的记录不能用普通重试清除 `reconciliationRequired`，须先维护核对回执。

每份待维护payload按该机器人 `projects.ownerOpenIdsByProfile` 向管理员尝试一次私有卡提醒，不在群里公开业务内容。只包含类型和问题号。提醒失败/崩溃未确认留作 `deliveryMaintenanceNotices.status=unconfirmed`，不会自动再造通知风暴；后台仍可见。无管理员映射/发送能力时保留后台记录，不能声称私聊已送达。原消息正向API确认撤回时沿正常撤回逻辑收尾。

## 保留与回退

`deliveryRetry`、`deliveryMaintenanceNotices`、adminAudit、原文件及分卷回执随私有runtime/data备份/迁移。待维护是未送达，不是业务失败或绿色完成。没有worker且只有精确相同的待维护payload时，不阻挡空闲发布；新内容、活任务及投递worker仍阻挡。原文件依赖保留，不当垃圾清理。

旧版不识别attention：回退前保留最新状态/回执，对仍待维护的原消息安装精确人工暂停，不可让旧队列恢复无限重试或倒灌agentos.json。无需新增凭据/权限。其它OS及完整跨机未实际验收时须标注。
