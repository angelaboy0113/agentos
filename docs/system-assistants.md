# 多系统知识助手部署与迁移

程序版本 1.46.0，更新日期 2026-10-23；Node 22.13–22.x，依赖以 package-lock.json 为准。新实例须使用自己的专用分支和独立检出目录。本文不改变旧部署的配置或运维手册。

## 布局与启动

实例根目录含 `agentos/`（程序）、`systems/`（各系统规范总仓及微服务）、`runtime/`（私有配置、认证、快照、状态和日志）。真实路径、群 ID、应用 ID、群主 ID 在 ignored 的 `config/*.local.json` 或实例私有 runtime 中，不进公开 Git。

`projects.local.json` 中 `chatProfileProjectMap` 按群和机器人 profile 选择系统，`topicChatIds` 配置话题群。每个项目配置 `repoPath`、`assistantInstructionsFile`、`analysisSourceMode=isolated`、独立 `analysisSnapshotRoot` 和 `analysisEnvironments`。环境未指定不设置默认值。`analysisEnvironments.<环境>.unavailableRepositories` 记录远端环境分支缺失的仓库，查询相关范围时必须说明证据缺口，不拿其它分支替代。

`agents.local.json` 为各系统设置独立 profile、`systemAssistant=true`、`role=developer`、`projectId`、`allowedChatIds`。这是执行器内部角色，群里只展示各系统助手。系统助手只接受指定群内的 @ 消息，私聊及其它群消息在下载附件或进入对话前拒绝；私密导出投递不因此关闭。系统规范 MD 同时用于聊天和源码调查；写权限由程序管理员门禁核验。

先执行 `sh scripts/run-system-instance.sh --check`。只有机器人和本应用内群主身份、独立认证文件、源码目录全部就绪，才允许 `--start`。默认端口在私有 `runtime/instance.local.json` 配置，受保护端口禁止占用。启动器清除继承的 AgentOS/飞书实例变量，再显式设置独立 data、worktree、配置和 CLI 路径。Unix socket 对路径长度有限制，新实例的事件认证副本使用较短的 `runtime/cli/<profile>`；启动时检查过长路径并给出错误。macOS LaunchAgent 应使用文稿目录外的独立实例目录，避免受保护目录访问失败。新实例使用独立浏览器会话，不复用旧实例 Chrome 标签。

## 飞书接入

1. 为每个系统创建独立企业应用并启用机器人。配置所需消息/群信息/图片文件权限，提交企业审核；测试账户成功不代表全员可用。
2. 配置长连接事件 `im.message.receive_v1` 和长连接回调 `card.action.trigger`。权限申请、机器人发布和可用范围均逐应用核验。
3. 将新应用凭据写入本实例独立 CLI 配置目录。使用 `LARKSUITE_CLI_CONFIG_DIR=<实例>/runtime/lark-cli`，按 CLI 的 `config init --name <新profile> --app-id <新AppID> --app-secret-stdin` 配置；App Secret 通过本机隐藏输入送入 stdin，不能写在命令参数、聊天、日志或 Git。不得覆盖原 CLI 配置或降低 Keychain 安全设置。
4. 只将已经发布并入群的机器人放入当前生效的 `agents.local.json`；待审批的助手配置保存在实例私有待接入清单，不启动其事件消费者。批准后加入新群、将配置加入生效清单，再重新核验并仅重启新实例。发布后把新机器人加入新群，再运行 `node scripts/verify-system-bots.mjs`。脚本分别以新应用身份核验机器人和群主；同一个人在不同应用中的 open_id 不同，不能复制旧机器人的管理员 ID。
5. 通过预检后才启动；核对 `/health`、两个消息/回调消费者，以及新群中真实 @ 问答。

普通成员可查询测试和生产、分析文件和导出；数据库仍使用已有受控只读工具。管理员身份不是任意 SQL 写入工具已实现的证明，写入/部署请求仍受实际执行能力和审批边界约束。

项目 `environmentExportMaxRows` 可设置为 `all`，环境接入向导和Nacos来源的自动数据库接入据此为新建的 MySQL 调查模板开放完整导出；预览仍只展示少量行，完整数据须通过已有数据集和导出校验。该字段不放宽所选库、表或只读限制。团队知识在独立 `knowledge.local.json` 按项目/群/profile 配置，通用规则与实时数据分开，跨系统不共享。

## 首次环境接入

同一话题、机器人、系统、接入类型和环境重新提交入口时，会替换此前尚未批准的申请；旧记录保留为 superseded，不启动旧入口。已打开的接入窗口及其它话题、机器人、环境不被替换。批准绑定读取时选定的申请 ID，期间目标改变则拒绝执行。已有多个历史申请不会自动猜选，维护者须依据明确的用户更正撤销错误项，再让群主确认有效目标。

数据库、Nacos、网站按系统和环境独立登记；不复制旧部署的真实连接、浏览器 Cookie 或凭据。用户提问未指定环境时 @ 询问。缺少入口时由群主提供对应环境 Nacos/网站入口并确认接入，使用现有向导、钥匙串和原卡恢复流程。已有网页账号密码可按任务卡的既有流程由指定负责人提供；验证码、扫码等仍需真人完成。

Nacos 接入由群主在对应接入话题回复 `@助手 账号：你的账号 密码：你的密码`，也支持 `账号密码都是：相同值` 或在唯一等待话题回复 `账号 / 密码`。程序在消息进入模型、会话历史或任务存储之前识别凭据，值只送入本机钥匙串，状态仅记录消息ID及接收时间；飞书原消息仍属于群可见内容，程序不承诺自动撤回。凭据不授权未确认的新入口。已批准且等待登录的独立浏览器从钥匙串读取新凭据并自动填写、提交，目标仍受原Nacos网络策略限制；未显示凭据不等于已登录。验证码/扫码由本人完成，命名空间仍由本机向导确认。先前已批准但登录失败的同一目标，在群主重新提供凭据时建立新ID和钥匙串引用重试，原记录保留，存在另一接入窗口时不并发启动。其它话题、机器人、群、入口不匹配或多目标时拒绝猜选。此能力不提供数据库写入或配置发布。

接入等待卡保留问题持续时间（包含接入等待，不能当作纯执行耗时）及此前任务的累计实际工具调用。等待状态提供刷新及停止接入与接续按钮；只有本问题发起人或群主可以操作，按钮绑定当前申请及状态版本。停止后保留结果、禁止原问题自动接续，独立浏览器收到取消标记后关闭；向导在后续请求和环境配置保存前检查取消。已开始的单次网络请求可能先返回。新版向导的范围选择终端可能仍等待用户关闭，但不会保存取消后的环境或恢复原查询。旧进程不自动获得新取消逻辑。新版启动刷新已有接入卡，刷新只更新展示，不表示重试认证。

登录状态区分尚未提供凭据、已接收待认证、认证未通过；接收凭据不宣称登录成功。Nacos认证失败后可以在原话题重新提供凭据，验证码仍需本人处理。

代码改动需要重新加载本实例服务。已打开的旧登录进程不自动加载新代码；失败后在原话题提供凭据可建立新登录尝试。Linux/Windows 的钥匙串和首次本机接入未验证。

正式使用前核验：每个系统的测试与生产来源、普通成员只读问答、CSV完整导出、错 @ 提示重新提问、成员写操作拒绝、群主身份、登录等待与恢复、失败提示及原实例健康。合成测试不代替真实生产业务验收。

## 换电脑

新电脑准备 Node22、Git、lark-cli、Codex 登录、浏览器及内网/VPN/数据库白名单。先安装本实例相同分支和提交；业务仓可重新拉取。将私有配置中的旧实例根路径改为新路径，保留系统和分支映射。

在没有在途执行时停止旧实例，成套加密备份 runtime/data（任务、记忆、知识、回执、附件、导出）、私有配置和需保留的改动。不复制旧机器进程 PID/租约来认领执行，也不承诺 Codex thread 引用跨机即可恢复；跨机待续任务需专门核验。保持历史证据原文，后续源码调查重新获取当前远端快照。

新电脑重新配置 CLI/Codex 登录、Keychain 和浏览器会话；迁移后检查路径、群主、权限及网络。先停旧事件消费者再让新实例接管；验收前保留回退备份。不要让两机写同一个状态目录。

macOS 网页交互依赖登录的桌面用户；专用 Mac mini 可通过远程桌面维护，但重启登录和 MFA 仍要安排。新实例如配置自启动，必须使用独立 LaunchAgent 名称（例如 com.agentos.knowledge），不能执行旧的固定 com.agentos.local 安装脚本。服务配置保存在 `~/Library/LaunchAgents/com.agentos.knowledge.plist`，标准输出和错误日志放在新实例 runtime。仅停止本实例时使用 `launchctl bootout gui/$(id -u)/com.agentos.knowledge`；修改新实例配置后用同一个 label 重新加载，不能操作 com.agentos.local。Windows 的该独立启动器和本次迁移未实机验证。

## 接入生命周期与同环境复用

统一状态：requested（待确认）、opening（启动窗口）、login_required（待认证）、scope_required（认证成功、待范围）、complete、failed、cancelled、superseded、expired。消息绑定先核对当前话题、群、profile和项目；已识别的新话题不得因URL相同而把凭据交给旧话题。待范围阶段仍占用唯一接入窗口，不能再误判为待登录或另开窗口。

项目可在私有配置设置 `nacosEnrollmentNamespaces: { "prd": ["你的命名空间ID"] }`，将已核实的本项目环境范围交给首次接入向导；向导必须与当前Nacos实际返回的ID逐项核对，缺失则停止，不扩展为全部或其它环境。配置字段是可信本机设置，不由模型临时猜测；不能只因源码分支名相同就推导命名空间。未配置时在卡片明确显示认证成功及可选范围，再由本机选择，避免无提示的终端等待。

一个连接完成后，同项目同环境恰好只有一个可用Nacos调查源时，系统恢复仍在等待入口的当前话题；重新执行原权限规划，保留原提问者身份。多源、其它系统、更新后的问题或正在执行的任务不自动猜选或重复排队。修复须同时验证路由、状态、展示、进程互斥、幂等和恢复，而不能只替换提示词。

## 环境发现接续与受阻提醒

连续调查读取Nacos配置后，控制面在校验当前查询授权和证据后，单独保存脱敏的连接来源（主机、库、命名空间、配置内容哈希、原授权指纹）；不依赖模型最终回复或可能压缩的上下文。仅同群、同profile、同项目和关联话题的已完成读取可用于数据库接入；数据库连接仍须群主确认，重新读取配置并校验哈希，凭据只在本机处理。

任务停在部分完成或外部条件缺失时，提醒原提问人尚未完成，包含已确认结果、缺口和下一步。待接入标记不能永久屏蔽停滞提醒，需要群主确认接入时同样发送操作提醒，卡片保持等待状态；重复刷新不重复提醒。检查时分别核对执行是否停止、接入是否待确认、业务文件是否实际生成；不能以任务completed或Nacos已登录推断报表已交付。

## 最终卡片与成组文件交付

中途确认或进度询问不能遮住随后完成的任务结果：当任务结果晚于该回复时，原问题卡展示任务最终结论，并按任务状态提醒提问人。任务完成后的新回复仍可正常展示。

默认交付最新已接受文件；若多份文件共同满足原问题，`reportAssessment.deliverables`须明确列出每个`fileId`及分工依据，并包含主文件。模型审阅资料中的`relatedReports`提供其它登记文件的真实绑定、表头和逐行计算核验。程序要求清单内所有文件均有匹配核验摘要和通过的计算审计，记录`reportDeliverySet`后将整组加入持久投递队列。不得用“补充表包含主表”的文字替代实际文件；任一组件被认定有实质缺陷时整组不再投递。重复恢复沿用文件身份去重，不发送历史草稿。

验收需分别核对CSV数据、所需文件是否全部投递，以及卡片是否展示最终业务结论。程序核验是固定配方和数据一致性证明，业务范围仍须对照原问题和源码审阅。

数据源尚未登记、配置来源不唯一而还未创建接入申请时，也属于需要人操作的等待状态。卡片优先展示当前接入缺口，不被恰好同时结束的源码任务覆盖；使用橙色并提醒原提问人和群主，重复刷新去重。首次接入需要提供该系统对应环境的配置中心入口或明确接入方式，不能复用其他系统地址；环境已经确定时不重复追问环境。配置中心不是Nacos时说明平台类型，由实际支持能力决定接入方法，不假装已经支持任意平台。

## 没有登记数据源时自主发现

项目已配置独立源码环境、数据库接入又缺少已登记配置源时，控制面先创建对应环境的只读来源调查任务，保留原问题、原提问者及证据。调查包含配置文件、部署脚本、构建profile、注入链和配置平台识别；不能把所有平台当Nacos，也不能将注释或占位地址当作当前运行事实。不得输出凭据或用shell绕过受控查库。

来源调查的标记`connectionSourceDiscovery`与项目、群、profile、话题和环境一致；同一来源调查再次交回完全相同的缺口时，保留具体发现并提醒所需平台登录/运行态证据，避免重复调度同一路径。不同环境不共用完成标记；没有配置可用源码环境时仍明确提示配置缺口。此行为不新增整个任务的耗时或总轮次限制，也不代表已支持任意配置平台的自动接入。

## 多数据源目录容量与失败回执

对话和源码调查的环境目录使用`environments`及`queryProfiles`共享相同的参数、范围和导出能力说明；所有environmentId、queryId、环境和描述仍保留，不按截断丢掉数据库或混用其它范围。执行授权仍从原始本机配置校验，压缩目录不放宽权限。

输入预算检查失败须说明本机上下文容量问题，尚未调用AI或创建任务，不能归为数据库密码、网络或登录失败。AI调用失败、操作未执行的@提醒必须表述失败，不能统一说“本次回复已完成”。验收除逐库连接外，还须用真实多库目录和原问题验证对话创建任务，再核对查询与文件交付；数据库接通不等于整个问答/导出链路已验收。

MySQL调查工具`database_clock`使用固定只读SQL返回当前库名、数据库会话时间、UTC时间、UTC偏移和会话/系统时区，记录本机观察时间。工具不接受参数或任意SQL，不读取业务表；用于核实过去一周等时间窗口。数据库会话时区不等于DATETIME字段业务时区，仍需结合字段类型、JDBC及源码转换规则；不能仅凭会话时区改写业务日期条件。

源码续查每轮重新读取当前压缩环境目录及能力说明；新接入和新增受控元数据能力不依赖旧会话记忆。目录更新不会追认旧授权，执行仍校验当前配置指纹与范围。

基础表过滤支持固定`is_null`/`is_not_null`，value省略或null；与其它条件一样要求已读取的真实字段，拒绝非空值和任意SQL。此能力用于缺失值核验，不意味着应把没有下单时间的记录算作某个日期窗口内的订单，业务范围仍依据源码。

文件审阅与投递分工通过结构化delivery约定传给源码及文件审阅：模型核实内容并显式接受文件组，系统在任务completed+ready之后通过ReportDelivery持久队列发送。模型不需生成下载URL，未上传不能反过来阻止内容审阅，也不能由模型自行宣称已发送；发送成功由实际投递回执确认。

## 导出表头

中文业务问题默认导出中文（英文字段）双语表头；在compose_report.columns提供原始label和经源码注解、字段说明或业务定义核实的displayName，程序合成标题。完整中文label同样允许。列含义与依据登记在finalize_report.columnRules，expectedColumns按实际生成标题填写。纯英文字段表头在合成及定稿时拒绝并给出修正提示；用户明确要求原始/英文表头时保留。普通成员与群主相同，无需新增配置或权限，升级后重启新实例生效。

改表头复用当前任务的有效完整数据集，重新合成并核验，不更改既有已签核文件、不因翻译重新取数。验证新文件列名、行数、逐格数据与原核验记录，最终通过后由原话题投递。数值枚举不会按英文猜译，需要项目字典或源码依据；CSV列宽由查看软件决定，日期显示井号可加宽列。源码中文注解只作为含义依据，程序不会证明业务翻译正确。

## SSH远程MySQL只读通道

当数据库只能从跳板机访问时，在该MySQL环境配置transport，mode为ssh-remote-execution，host/port为已批准跳板机，credentialRef为跳板机独立钥匙串引用，knownHostsFile为已核验主机密钥文件绝对路径。数据库host/port/database/credentialRef仍描述远端数据库。示例：

```json
"transport": {"mode":"ssh-remote-execution","host":"jump.example.internal","port":22,"credentialRef":"jump_read_access","knownHostsFile":"/your/private/known_hosts"}
```

先核验跳板机主机密钥和远端Node/Python运行时，录入独立SSH及数据库凭据，再运行受控connection_check、database_clock检查。额外账号权限采用原business-readonly显式管理员确认；这不改变数据库账号授权，也不提供存储过程执行。数据库TLS设置依照已批准目标配置；非TLS例外必须单独确认，不能将SSH加密说成跳板机到数据库也已加密。修改私有环境配置后在无活动任务时重启对应实例。

程序只启动固定SSH远程执行命令：禁用SSH用户配置、转发及代理会话，严格核验已固定主机密钥。已锁定mysql2依赖通过stdin放到远端临时目录，远端缺少驱动不回退本机/隧道、不全局安装。凭据仅通过钥匙串及SSH stdin传入，不放argv、环境变量、源码或聊天上下文。连接保持同一个远端只读事务，现有表结构白名单、固定SQL、项目环境授权、精确数值、完整分页、CSV核验及投递流程继续生效；远端额外拒绝写入、CALL、多语句和SQL文件访问。关闭时回滚、断开、清理临时应用；SSH失败只报告该通道失败。

本地已在macOS/OpenSSH/Python3验证，远端Ubuntu/Python3/Node18验证。当前SSH二进制与钥匙串路径为macOS/Linux方案，Windows部署未验证，不能直接声称可迁移运行。成功连接不等于业务报表已完成；以原问题文件核验、真实投递回执和提问人提醒验收。

## 入口上下文预算

聊天入口只展示所有环境ID、tier、kind及共享querySets/queryProfiles参数目录，用于选择目标和填写参数。详细工具能力、全量表范围与授权配置在执行阶段按目标重新读取；不截掉环境、不跨环境借用、不扩大授权。预算错误记录各部分大小供本机诊断，不记录原始上下文或凭据。团队知识、助手规则及目录都要纳入真实请求复现，不能只以空模拟上下文验证容量。

## 宽表导出

预览select仍保持12字段，完整报表compose_report可生成128列；group_dataset与linked_group_dataset可按实际唯一主键及至多128个已核验字段分组保留原始记录。所有字段仍须先读取实际schema并通过白名单检查；分页顺序包含唯一业务主键，不依赖样本。宽表自动减小每页行数，减少远端响应体压力。原始字段与计算分量的核验规则不变；导出仍需独立完整对象范围，原始数值逐值保留，计算/标记合计列仍需独立合计核验。

文件审阅对全文件逐行重算后才生成摘要；宽表列定义过多时仅摘要分页，columnPaging给出总列数与columns详情分页入口，不删CSV字段、不跳过全文件校验。精简摘要不代表全部字段语义已自动核实，仍须根据原要求与源注解审阅。

宽表先以小页读取并按实际响应字节调整页大小；单页响应过大时在同一只读事务、同一偏移缩小页重取，不能跳行、截断或换成样本。SSH远端在发送前限制响应体，避免半截JSON破坏连接。

## 大明细游标分页

schema查询同时读取数据库真实主键及完整主键列数。仅已证明单列主键、所需字段同属该对象且包含该主键的分组可自动使用游标；主明细内连接且主表关联键为其主键时，优先按明细外键及明细主键继续读取，参数绑定，无OFFSET反复跳过。复合主键、混合维度或可能为空的右侧左连接不猜唯一性，保留原有查询方式。

原始记录分组已证明每组恰好一条，且聚合仅是COUNT(*)或非空主键COUNT时，等价投影计数1，避免重复GROUP BY。真实金额聚合和一对多主表分组不走此优化。每页仍在相同只读事务中先核验授权，完整导出仍需独立对象全集、计数/合计及文件重算。游标请求采用固定字段的分层比较，不接受任意游标SQL或表路径。自适应页最多5000行，样本工具仍20/12限制不变。

## 本地历史保留与自动释放

独立多系统启动器默认 `runtime/instance.local.json` 的 `retentionDays: 30`，按滚动30×24小时保留。启动时及每24小时执行一次，因此过期数据在下一次清理时删除。调整后仅重启本实例；`0`关闭自动清理。通用 `start:local` / `start:control` 默认关闭，可通过 `AGENTOS_RETENTION_DAYS=30`启用；非法值拒绝启动，不能误变成全量删除。此配置不影响另一检出目录启动的实例。

问题、补充对话、多阶段任务和直接依赖证据作为整体，以最近业务更新时间判断。到期删除本地问题/任务/结果/卡片索引、幂等映射和过期审计/控制回执；同步清理摘要、持久会话引用、知识SQLite和联系人索引，重写JSON状态并清除相关热缓存。知识按最后核实时间到期，不能只靠命中次数无限续期。只删除已过期来源的遗忘抑制条目，防止仍保留的来源被重新记起。

执行中、排队、待登录/审批/补充、尚未发送的回复、卡片或文件、私有旧卡待清理，以及仍被保留任务直接引用的证据，不强行过期或停止；完成/后续更新后重新计算保留期限。时间信息损坏或缺失的记录保守保留，需维护者核查。清理不是整个任务的执行超时限制。

文件只在允许的目录清理：过期导出CSV及核验/数据集、任务附件、消息资源、联系人图片、已结束接入临时材料、CLI报表/图片/下载副本、烟测/卡片预览、分析附件资源、历史控制回执和已识别的本机状态备份。仍被保留状态引用的路径及带有保留任务/消息编号的目录受到保护。配置中的独立源码快照根目录仅清理带程序清单的 `analysis-*` 容器；不跟随符号链接，不递归删除Git worktree，不触碰个人源码。残缺/损坏快照保守保留，维护者确认后处理。

新实例主程序输出按UTC日期写入 `runtime/logs/YYYY-MM-DD.stdout.log` 与 `.stderr.log`，过期整文件删除；启动器和原生日志仍可能写入原服务日志。历史开发检查日志及已识别状态备份也按过期规则清理。配置、原始AI访问提示词、钥匙串、机器人认证、企业服务端聊天/附件、开发worktree及未提交代码、系统级Codex会话、npm缓存和人工外置备份不属于自动清理范围；不承诺本机所有目录都有容量上限。

健康检查 `/health` 返回 `historyRetention.enabled/days/intervalMs/lastRun`。成功清理记录数量和时间，不记录问题正文或凭据；失败显示 `RETENTION_FAILED` 并在下一次重试。排查时先看本实例按日日志和运行账户的文件权限，不要手工改运行态JSON。删除后的本地问题详情不可恢复，已发送到飞书的内容不会自动撤回，若需留档应在到期前另外保存。JSON变小可降低常驻缓存占用，但进程RSS不保证即时下降，活动任务仍会使用内存。

验收：在隔离临时目录构造超过30天的已完成问题、最近问题、长任务、待登录/待发送问题，核对关联记录与文件删留一致；验证符号链接、个人worktree和待回调文件不被删除，摘要遗忘规则仍生效；随后检查新实例健康状态、清理回执和原实例进程。自动回归使用合成过期记录，不在生产制造旧问题或回拨服务器时间。macOS部署检查与文件/SQLite回归已验证；Windows按日日志与清理未实机验证。

## 源码环境与运行分级映射

源码环境ID（例如`sit`）用于选择分支和快照；运行分级仅`uat`（测试）/`prd`（生产），用于网页、数据库、配置中心授权。二者不可直接比较字符串。源码目录向对话入口提供`runtimeTier`；所有网页与数据库查询规划须核对本问题源码环境的映射，环境优先任务和环境查询后返回源码均保留真实源码ID，不把`uat`当成`sit`分支名。

配置在私有`projects.local.json`，每个项目的`analysisEnvironments`可显式指定：

```json
{"analysisSourceMode":"isolated","analysisEnvironments":{"validation":{"runtimeTier":"uat","repositories":[{"path":".","branch":"你的测试分支"}]},"live":{"runtimeTier":"prd","repositories":[{"path":".","branch":"你的生产分支"}]}}}
```

以上是映射片段，需合并项目已有的绝对源码路径、独立快照根目录和仓库清单；修改后重启对应实例。标准名`sit/uat/test/testing`默认对应测试，`prd/prod/production`对应生产；标准生产名不能被配置成测试分级。自定义ID未配置`runtimeTier`时仍可选该ID分析源码，但访问运行环境需先补映射。多个源码环境对应同一分级时必须明确源码ID；不从默认生产值或其它项目推断。本配置不合并网站、数据库或凭据，环境ID、项目、URL、机器人、原授权与只读门控照常核验。

失败卡片分别显示跨环境不一致、映射缺失、映射冲突、多候选未选择和网页参数错误；前四类需修正真实配置或目标，不能通过改写查询绕过。网页目的仍为最多200字符的非空单行文本，格式错误可在原任务内自查。第一次不可修复失败只说本次申请未通过，不再误称多次重试；停止卡保留历史事实原文，同时明确历史中的后续计划已停止，不宣称网页已经打开或仍在运行。

验收覆盖多个系统、自定义环境名、SIT→测试网页、测试任务申请生产数据库拒绝、环境优先建任务仍选择SIT源码、歧义和未知配置、查询拒绝与保留事实。真实页面正常与否仍须浏览器实测，映射通过不等于页面已登录或业务无故障。修复已受阻问题时由维护者核对原任务、发起人、环境及停止原因后接续，记录审计，不要求用户重述需求或扩展权限。

## 网页登录判定与初始化接续

独立浏览器与共享Chrome使用同一固定DOM状态探针，区分登录表单、明确拒绝、验证码、改密要求、加载/空白和可见业务页面。没有密码框本身不证明认证成功；业务页面需已可见、离开认证路由且无认证表单。独立浏览器还对认证POST响应做内存内的白名单字段分类，只保留失败类别，不保存响应正文、令牌、账号或密码。HTTP服务异常、请求错误和限流不归为密码错误。共享Chrome的判断依赖可见页面，不能声称有独立浏览器同等的认证网络证据。

提交识别常见中文/英文按钮并兼容“登 录”等间隔文字。凭据填写前检查原任务授权及当前页面origin/应用范围；不通过不填写。找不到可确认控件时不盲按回车造成原生表单刷新或重复提交。每个页面自动使用钥匙串凭据尝试一次；明确重新提供凭据才重试，失败不循环撞登录。验证码、扫码和更改密码由本人完成，程序不自动改密。

等待登录时，原来已批准的同一网页、同一查询参数/项目/发起人只读范围可重新核验有效期，并允许范围内的只读初始化请求。必须核对原scope签名、配置指纹与环境映射；配置/目标/授权变化即停止，不借登录扩大范围。过期再核验留事件；取消、状态变更和并发续验不能复活任务或创建第二份权限。独立浏览器继续限制同源、只读路径/方法/请求内容，写接口、跨域和下载等限制保留；共享Chrome复用正常浏览器网络，不宣称具备相同网络拦截。

登录状态变化时更新原卡，区分服务器拒绝、验证/改密、接口故障、受限接口、加载和授权检测失败，不能无限只显示“已提交”。页面就绪才签发一次性恢复标记，保留原问题身份和证据；不需要用户重新发问。静态图片/字体被拦截不能直接当成认证失败；界面正常也不代替后续逐页检查。

验证包含真实浏览器合成站点的空白/拒绝/改密、带空格的登录按钮、等待状态下登录后只读初始化、写接口拒绝、过期原范围重验与篡改/配置变化拒绝。新分支两种驱动均更新；旧实例不会自动加载本分支代码，也不因一个站点成功就保证所有系统登录正常。重启仅在无执行/待交付任务时操作对应实例；网页会话和等待问题保留，实际业务站点仍以当前页面与登录反馈验证。

### 非标准只读初始化接口

有些网站使用POST读取登录用户、菜单或权限，路径并非get/list/query。维护者核对后端实现确为读取后，在该网站`queries.investigate`登记`readEndpoints: [{"method":"POST","path":"/identity/context","reviewed":true}]`。仅本机可信配置可设置，不由模型临时批准；最多32项，只允许精确路径和GET/POST，拒绝通配、外域、路径跳转及含修改语义的路径。请求仍须同源、符合当前任务授权，且请求体不能带明确修改指令；登记只读POST不授权任何其它接口或写入。配置变化使旧授权失效，维护者核对原问题后重新签发同一业务目的的受控计划，留审计后仅重启对应实例。

状态中的`browserLoginDiagnostic`只保存是否尝试凭据、是否观察到认证POST、认证结果类别与最多8条被拦接口的方法/路径，不含查询字符串、请求体、响应正文和凭据。自动更新脚本、字体等静态资源失败不计为认证接口受限。旧TPM日常Chrome的网络路径与新实例独立浏览器不同，不因前者正常就证明后者不需要登记初始化读接口。


## 受控网页菜单、截图与故障恢复

独立浏览器（`AGENTOS_BROWSER_MODE=isolated`）提供菜单、查询、详情和翻页所需的 `browser_snapshot/click/search/select`。支持 ARIA 菜单及常见 Element/Ant 子菜单标题；控件用具体元素句柄绑定当前任务及页面代次，重排不会将引用指向别的输入框。输入控件只暴露可编辑、非凭据查询字段；写操作仍受控件与网络双重拒绝。每次动作有单次等待上限，不新增整个任务的截停规则。

参数缺失、旧引用、控件类型不匹配和单次动作超时，会作为工具修正提示返回同一调查。先读取新快照核对实际页面，再决定下一步；不盲目重复点击、不将工具超时认定为网站故障，不改用普通 Chrome 或调试端口绕过受控流程。网页 URL 保留 SPA 路由，剔除查询参数；未实际访问的页面必须写明未检查。未知菜单组件或真实权限拦截仍可能形成能力缺口，需要保留准确诊断。

用户在原问题明确要求截图时，`browser_screenshot` 截取当前业务页面视口（白屏也可留证，不据此声称登录成功），仅遮挡密码/口令、令牌、密钥等凭据控件及显式 `data-sensitive/data-agentos-secret` 区域，使用中性灰色；普通业务字段（包括只读或禁用的详情字段）正常显示；不截取登录表单，不将未打开页面说成已有截图。该能力目前在独立浏览器驱动验证，普通共享 Chrome 未提供截图支持。凭据遮挡不是对页面所有业务文本的自动脱敏：截图遵循原问题已授权的业务数据范围，发送前仍应核对页面目标。

截图由控制服务生成在 `data/website-evidence/<jobId>/`，目录0700、文件0600。只允许该任务目录内的 PNG，验证文件类型、大小、摘要和无符号链接；不接受 Runner 任意文件路径。控制服务将图片绑定原问题、机器人 profile、话题及私有收件人；同一文件幂等投递。发送失败只重试发送，不重新操作网站。原问题没有截图要求时拒绝发送。原卡结论不能将“截图已保存/排队”等同“已收到图片”。

待发送清单保存在状态的 `websiteEvidenceDeliveries`，重启恢复；取消任务或问题版本变化后不发送过期图片。截图与原问题一起纳入30天清理，保护活动任务和未投递证据。代码更新需重启自己的实例；配置和钥匙串不迁移或重置，旧实例不加载本次改动。维护时核验原卡状态、原话题图片回执、实际访问路径和步骤；合成回归不能证明业务网站无异常。


异步页面在导航后可能继续加载数据。快照返回 `pageStatus/ loading`，截图同时返回截图时最新的页面和控件引用；规划器应据此点击新出现的查看按钮，不能拿加载前清单认定能力缺失。后续取得明确就绪页面后，前序暂时空白不自动使整轮永久未完成；仍未就绪的页面保留未完成。每个网页工具响应中的 `screenshotDeliveries` 来自控制服务持久投递记录，按文件摘要合并最新状态；`sent`才表示已有发送回执，`pending`仅表示排队或重试，状态不会触发重复截图。


同一问题继续检查已访问应用的子页面时，网站规划优先复用该问题已有网页证据对应的应用入口，保留原先审核的初始化读接口及凭据引用；不把每个页面路径都重新登记成独立登录入口。仅同项目、同测试/生产分级、同源且在原入口路径边界内有效。其它应用路径、项目、环境或域名不能继承原接口配置，仍走各自登记与授权。


大型SPA常预渲染隐藏菜单。独立浏览器先筛选可见元素，再按可操作控件统计快照清单容量；隐藏、禁用和写操作控件不占用名额。`controlsLimited=true`表示单次清单可能截断，应通过当前已开放的查询/菜单缩小显示范围，不把未列入清单的控件直接说成账号无权限。


截图先等待当前页面的同源 document/XHR/fetch 返回、加载标志消失，并观察页面文字和非凭据字段值稳定至少600毫秒；单次截图最多等待12秒。请求失败也会结束在途计数，但不等于业务成功。随后才截取当前视口并刷新控件清单；如期间跳回登录页面，返回原登录流程，不截图登录表单。

`readiness.status=ready`表示这一观察窗口内接口与渲染稳定，不表示业务无异常。12秒仍有在途请求、加载动画或白屏时，保留有“页面加载尚未完成·现场截图”标记的证据，状态为`loading_timeout/blank_timeout`并返回部分结果，不能报成页面已加载完成；后续同页明确就绪可关闭临时加载缺口。单次截图调用等待60秒以容纳首次导航、就绪观察和截图，不改变整任务/总轮次数规则。没有加载标记且尚未发出的未来定时请求无法预知；持续轮询页面可能返回未稳定的现场截图，应按元数据解释。


## 网站凭据记忆与跨话题复用

网站账号密码保存在本机 Mac 钥匙串，通过 `credentialRef`读取，不放入模型记忆、提示词、运行结果或30天历史清理范围。先复用有效登录态；过期后自动读取同一应用的既有凭据重登。只有首次未保存、钥匙串无法读取、网站明确拒绝、验证码/扫码/改密等情况才需要相应人工配合；接口规则拦截不是密码丢失，不应让用户反复重发。

维护者在自己的 `environments.local.json`中将审核过的网站应用入口设为`applicationRoot:true`，如：

```json
{"your_application":{"kind":"website","projectId":"your_project","tier":"uat","baseUrl":"https://your-site.example/app/","applicationRoot":true,"credentialRef":"your_saved_credential"}}
```

以上仅展示相关字段，仍需本部署原有完整的owners/membersRead/queries配置。标记只能来自可信本机配置，不能由模型网站申请自行声明；设置前核实该路径确为同一应用的根入口、登录账号及审核读接口适用范围。不是仅凭域名相同就共享账号。独立新问题、子页面申请、目录路由和旧页面环境ID统一回到该应用入口，复用原凭据引用与审核配置，不复制密码或把每个页面建立成新的登录身份。限定同项目、同测试/生产分级、同协议/域名/端口及路径边界；多个根入口取最具体的匹配，歧义拒绝。未配置标记的既有部署保留原行为。

正向确认业务页就绪后重置本轮凭据尝试标记，使同一页面未来会话再次失效时仍可自动重登；同一次明确失败不会不断提交。已登录页面不额外读取凭据。钥匙串不可读时明确区分首次录入和本机解锁检查；初始化接口被限制时提示维护者核对应用配置，不归因为用户密码。

配置变更需重签受影响问题的读取范围并重载自己的实例；已等待在旧页面入口的问题由维护者保留原提问人、目标、历史证据后迁移到已审核根入口，不自动扩大跨系统权限。迁移电脑时需单独迁移或重新录入钥匙串，并登录相同账户/内网；复制普通配置不会复制密码。
