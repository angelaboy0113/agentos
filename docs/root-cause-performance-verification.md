# 原因排查与性能边界验证

## 故障复现

2026-09-24 的一张 PRD 只读分析卡耗时约 47 分钟，直接 Codex 对同一问题约 9 分钟。AgentOS 在同一开发 thread 中串行经历多轮源码分析、两轮数据库调查和网页检查；数据库工具通过多次明细抽样找到了 504 和 252 条关联记录，却漏掉两批各 252 条的重复关系。完成门接受了模型对 `original-question` 的 verified 标记，因此把现象性结论显示为绿色。

该记录用于实现定位，不能据此推断所有业务问题都有相同根因，也不表示本次发布重新查询了 PRD。

## 修复

- 原因类结果新增结构化 `causalAssessment`。程序要求直接业务错误，或至少两类独立诊断证据和明确机制；网关 504 或截图不能单独完成原问题。
- MySQL 只读工具新增参数化 `group_count`，用于重复批次、重复提交和同键多条的有界聚合，避免逐页抽样。
- 同一 Codex thread 的续轮只追加最新环境证据，不再重复传入原问题、附件、旧最终消息和完整账本。
- 环境调查默认每轮 24 次或 150 秒；首轮/续轮 Codex 默认 15 分钟/8 分钟。达到边界时停止当前阶段、保留证据并生成部分结果。
- 部分结论会在交接校验前清除上一轮遗留的退回责任，并在结论规范化后恢复前序只读查询记录，避免可靠业务事实被通用红色交接错误覆盖。
- MySQL 已开放查询工具时，规划器不能在只做连接检查后结束并误报“查询工具不可用”；它会收到明确诊断并继续使用已登记的结构化只读工具。

所有边界均为本机运行参数，不扩大数据库、网页或源码权限。环境查询仍需原授权，凭据仍不进入模型。

## 自动化验证

回归覆盖：

- “504 + 截图”不能关闭原因问题；“后端业务错误 + 重复数据库记录”可以满足因果门。
- 续轮提示只包含新增证据，不重复附件或完整旧上下文。
- `group_count` 仅使用已确认字段、参数化筛选和有界返回。
- 调查预算和分析超时保留既有证据，不把超时包装成业务结论。
- 已确认提交后业务状态、但缺少请求级日志时，结果保持橙色部分完成；核心原因未闭环不会触发通用交接错误覆盖正文。
- 数据库规划器在连接成功后立即结束会被拒绝；改用结构或数据查询后才可形成调查结论。被日志缺口降为部分结果时，前序查询的业务编号和记录仍被保留。

发布前运行 `npm run check`。部署后还需检查 `/health`、Runner 在线数量、在途任务和运行数据数量。真实耗时受问题复杂度、Codex 服务、网站和数据库响应影响，因此这些回归证明链路已去掉已知重复开销和无限延长路径，不承诺每个问题都与直接 Codex 完全同耗时。

## 2026-09-24 方案预算进度为空：关联汇总能力与跨轮上限

同一问题的新对照记录中，直接 Codex 约 13 分钟确认“10 月申请额和事业部预算均为 0，代码执行 0/0，前端未拦截后继续提交空进度”；AgentOS 约 40 分钟只得到部分结论。事件时间线显示同一 Job 串行执行了 13 次 Codex 续轮和 12 轮数据库调查。每一轮增加一个表、字段或样本，因此旧的“连续无新证据”规则没有触发；而旧工具只有单表明细、计数和重复分组，不能按源码口径完成组织子树与预算表的关联求和。

本次修复没有降低因果完成门。新增 `aggregate`、`collect_values` 和 `linked_aggregate`：表、列、数值类型、等值关联、筛选和汇总函数都由本机程序校验，值使用绑定参数，连接仍在只读事务内，模型仍不能提交任意 SQL。组织层级可先收集成仅本轮有效的完整集合引用，再用于两表关联汇总。截断集合、第三表、表达式、未知字段和非数值求和全部拒绝。

同一环境目标新增默认 3 轮总上限，不能再通过每轮新增少量证据连续启动十余轮。卡片的工具数改为整个 Job 的累计值，包含源码与环境续轮，不再只显示最后一次环境调查。回归使用虚构表结构验证 0 值预算类的单表求和、层级集合与两表关联、参数绑定、注入拒绝、数值类型检查、缺失/截断集合拒绝、三轮收敛及累计工具数。它证明已修复本次链路缺口；真实 PRD 结果仍须由用户新问题触发，历史卡不会重算。
