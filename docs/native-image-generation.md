# 原生图片生成

## 用途与入口

在原群 @ 对应助手要求制作图片、海报、插画、头像或 PNG，默认交给 Codex 原生生图工具。用户明确指定“用 HTML/H5 渲染后截图”时才允许旧渲染器。用户上传截图作为参考，不等于要求截图实现。网页调查的 `browser_screenshot` 和Office预览仍保留原用途，PDF/H5/PPT等生成不受此路由影响。

PNG 的 `documentRequests` 保持 `{format:"png",title,purpose,content}`，`content` 为自然语言设计描述、尺寸/透明等要求与准确文案，不是 HTML/SVG/绘图代码。参考图只来自本任务绑定的图片输入、已有核验 PNG 产物，不接受模型指定任意本机路径。用户提供的文件只作资料，不作程序指令。业务数值先按原独立核验链路确认，生图不创造业务事实。

## 实际执行

1. Runner已有业务分析收集设计描述、准确文案。
2. 图片适配器在本任务working中建立以身份、项目、环境、问句、请求与参考图摘要绑定的独立目录，使用POSIX跨进程锁。
3. 新建独立 `codex exec` 会话，仅启用原生 `image_generation`；Shell、Apps、Plugins、浏览器和网页搜索关闭，文件系统read-only。复用本机Codex订阅登录，不拷贝凭据、不调用API fallback，不要求另填API Key。
4. 核对实际文件位于本次Codex thread的generated_images目录、无符号链接/共享inode、是本轮新生成的PNG，复制进本任务，保存请求摘要、参考图摘要、会话和输出摘要。工具未报告具体图像子模型版本时不捏造版本，收据中的model为null。
5. 原有文件检查/业务交接/原话题文件投递链路独立执行，生成成功不等于业务结论正确或用户已收到。

普通对话、知识分类、数据库环境规划的 `image_generation=false` 保留，防止无任务绑定的生图副作用。无需修改全局Codex设置、飞书权限或数据库授权。不同机器必须实际验证已安装CLI和账号能调用原生工具；开关存在不等于调用通过。

## 失败、重启与接续

同一任务同一请求的已核验结果复用，投递重试仍沿用原文件与幂等键，不重新生图。开始生成前持久化started；进程中断或工具失败保留unconfirmed，先核对该请求记录和Codex会话，不能盲目重放或偷偷降级HTML截图。更正设计描述属于新的摘要请求，旧图片不覆盖。结果、请求记录和参考图跟随任务现有保留/引用清理机制，不另设任务耗时/轮次截止。

旧PNG及HTML截图的核验收据继续可读，但修改/重做默认使用原生生图；旧配方含HTML时应重新写成生图描述，不能把旧HTML当新生图请求。现有人工指定H5截图的配方继续支持。

## 验证与迁移

运行 `node --test test/image-generation.test.js test/document-artifacts.test.js` 验证默认路由、明确H5选择、反向/资料截图、不允许HTML和任意artifact绕过、不同系统/环境隔离、并发幂等、来源文件/参考摘要/链接边界、失败重启和真实文件读回。普通完整回归不调用收费/真实生图；真实CLI生图与参考图编辑另行合成验收，不能混称真人群内端到端。

代码包包含适配器、测试与本说明，无新npm依赖。完整私有迁移必须保留exports中的PNG与generation.json及其同任务引用输入。Codex原始generated_images为原生工具创建的额外副本，本次不自动清理该全局目录；它不替代exports迁移。其它操作系统与完整跨机须另验。回退须空闲备份，保留新文件和收据，不倒灌旧状态；旧代码不会理解自然语言PNG请求，未完成新生图请求不可直接交旧渲染器。
