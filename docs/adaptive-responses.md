# 按问题复杂度自然回答

## 行为

AgentOS 不再把所有回复统一压成 2–4 句。问候、状态、审批、接单回执和单一事实继续简短；业务分析、影响评估、方案讨论和原因解释应直接给出判断，并按需要展开主要影响、成立前提、风险、未验证项和下一步。

信息不足时，只要仍能形成有用判断，先给条件化分析，再追问真正改变结论的少量信息。例如切换日期不明确时，可以分别说明月初与月中切换的差异，不能只回复“请补充日期”。缺失信息导致任何可靠判断都不成立时，才只做澄清。

## 卡片展示

普通对话和任务摘要的主卡片可展示最多 1200 个 Unicode 字符。超过后保留一段完整、可独立阅读的主要回答，其余内容进入“详细结果与证据”分页。任务的 finalMessage 仍保存完整技术详情；历史结果仍在同一问题卡片中翻阅。

任务 summary 的 schema 上限从 360 调整为 1200。简单结果不要求写满；复杂业务结果通常 300–900 字。代码块、日志、长路径和原始技术证据继续放详情，避免主卡片重新变成日志堆积。

## 边界

本变更调整回答深度和展示，不改变问题隔离、环境审批、成员权限、只读限制或任务完成判断。直接对话仍只能使用已经注入的可信上下文；需要当前源码或实时数据时仍创建受控调查，不能用更长的回复代替核验。

## 验证

回归覆盖：超过旧 360 字的业务分析完整显示；真正超长的回答才折叠；折叠后的主回答仍超过 800 字并保留详情；任务提示和 schema 使用 1200 字上限；澄清策略要求先给条件化分析。发布测试不访问业务环境。
