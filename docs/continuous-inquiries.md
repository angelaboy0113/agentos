# 连续调查与依赖型只读计划（1.90.0）

适用于多指标、跨已接入系统的只读调查。用途是减少每个小步骤重新调用模型，以及每生成一份文件就回源码重新规划；不提供原生任意 shell、数据库写入或全机凭据访问。

## 入口与执行

原有群提问、项目/环境路由与权限不变，无需新增本机配置或重启以外的安装步骤。模型在环境工具目录看到 `execute_read_plan`，一次给出 `steps`，每步包含唯一 `id`、现有 `tool` 与原工具的 `arguments`。引用前一步真实返回值使用 `{"$result":{"step":"source","path":["datasetRef"]}}`，示例见 `config/inquiry-read-plan.example.json`。只可向前引用本计划内的实际结果；不存在路径、工具不可用、写工具、原型字段或错误参数均拒绝。不是任意程序执行语言，不可通过计划修改环境/URL/凭据/权限。

程序依次执行，每一步重新检查原授权，仍调用原受控工具；不会跳过范围、完整性、空值、精确金额或文件核验。执行失败停止该计划剩余步骤，原成功结果/数据集/失败步骤继续保留，返回模型只修失败部分。不会自动重放成功查询。大结果仍走原持久化工具结果机制。进程重启后不盲重放在途计划，凭原任务保存数据重建剩余步骤。

连续分析中，核验一份文件成功只表示该文件完成，模型可在同一会话继续其它原要求；需要另一已登记数据库时走原 `continue_environment`，关闭当前范围后重新签发票据，已有验证文件不再无条件强制回源码。最终仍有完整原问题审阅和交付验收。单次旧式调用保留核验完成立即交回的兼容行为。

没有新增整个任务的时间、轮次、调用总次数截止。结构/引用深度校验只保护单个输入，不是任务额度。

## 范围与双助手

执行契约从原问题计算文件意图和明确明细粒度。原请求需要表格仍必须交付，不能因本功能跳过文件。经营概览不默认扩大为全部门店×月份或其它历史审计明细；必要支撑可以提供，不无条件成为答复前置条件。不缩减用户明确要求的对象、期间或字段。

同一真实消息明确 @ 多个已绑定系统助手时，控制面按可信机器人 ID 生成分工提示，并随 turn/job 保存。飞书可能给每个机器人分别投影同一消息、且每份事件只保留当前机器人；控制面会短暂合流同一 messageId、群、原发送者下已实际通过路由校验的不同 profile 事件，再反向写入全部对应 turn。它不依赖显示名，也不会把同文本的另一条消息合并。各助手只创建并验收自己的系统贡献，避免都重新调查全部系统；当前系统贡献完整时可独立完成，并提示结合同伴结果，不因同伴系统字段缺失变黄。提示不合并任务、身份、私有数据或授权，也不是跨系统数据库票据；现有显式关联与每步范围核验继续适用。没有真实多助手接收、错误群、私聊、不同发送者或未知身份时不生成提示。单助手明确联合调查仍走原已授权协查链并按整题验收。不能声称已实现两个助手共享一个模型会话或自动合并业务口径。

## 失败与恢复

只读 developer 连续调查若返回 `partial + investigation.continue + 无blocker + returnTo=developer`，程序归一为继续原 developer，记录 protocolRepair；不是标记完成。后续工件/金额/必需检查仍正常校验。ready、真实blocked、权限/登录/业务异常或修改任务不作此归一。缺工件、失败的必需验收项仍拒绝，不通过改绿色掩盖。

## 验证与边界

回归覆盖依赖引用、失败保留不重放、两系统并发隔离、已核验文件接续、scope变化拒绝、结果协议、双助手完整提及、消费者本地提及投影合流、不同发送者拒绝合流和明细粒度。量化报告须同时列模型往返、工具时间和完整耗时，区分合成工具基准、历史数据离线回放、真实群消息投递与真人入站/生产新查询。

部署遵循实例原维护流程：检查活动任务、会话、投递、入站，空闲后备份与部署，核对消费者/health/旧任务/凭据和业务仓。迁移包需含本模块、契约、测试、示例和说明；无需新依赖。其它操作系统与完整私有跨机路径未经本次验证。回退需先处理在途依赖计划及新协议审计，保留后续任务数据，不倒灌旧状态。
