# 环境子步骤完成与原问题完成

## 行为

“核对实际单据”不是“找到数据库地址”。此前仅partial环境结果返回源码调查；ready会结束single_developer链路，即使只完成端点发现。本次让已配置analysisRepositories的同一问题中，ready和partial环境步骤均交回只读开发阶段，结合原问题判断下一步，再按既有流程汇总。用户不必为每个成功的中间步骤重复回复继续。

如果用户只问连接地址，后续分析可直接回答；若要求核对单据，则尚未查到单据时不能宣称完成。后续访问仍需匹配已有查询范围和审批；没有接入能力时明确待解决项，不自动扩大权限或沿用环境授权到源码执行器。

## 实现与边界

server按原环境、原问题和已有配置决定resumeInvestigation；store在原完成事务内生成只读analysis_review后续任务，保留发起人、questionId、证据上下文和原问题，删除environmentAccess。重复、旧租约事件不能再次派生。连续三次相同环境证据仍停止循环。未配置源码分析仓库的部署不自动派生源码任务，需要维护者配置对应项目的analysisRepositories。

环境子步骤ready仍表示该查询本身成功，不能单独充当业务问题已解决的标志。源码执行器检查 investigation 目标清单，负责人未完成且有可执行调查时自动交回开发；新证据可关闭旧缺口。详见 docs/autonomous-investigation.md。清单结构检查和续查调度由程序执行，但证据语义仍依赖模型复核，不能保证所有复杂问题必然解决。

## 卡片

有业务解释时优先展示该解释，即使工具结果是host/port/database。数据库坐标和原始记录放在展开详情。没有业务解释且属于直接地址查询时保留地址展示。解释要求说明真实已确认、尚未确认和下一步，不照抄无关的记录数、超时或根因提醒。

## 部署与验证

更新后空闲重启，无需新增配置。已结束历史问题不自动执行；在原话题重新要求继续后走新流程。回归通过真实HTTP事件验证ready环境子步骤派生、原身份与问题保留、不携带授权、重复事件拒绝；卡片测试验证业务解释优先、地址仍在详情、直接地址查询兼容。使用模拟数据，没有为发布验证访问生产或UAT数据库。Mac部署，Windows未实机验收。
