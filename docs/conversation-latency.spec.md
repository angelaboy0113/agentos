# 对话延迟优化（2026-09-05）

目标：保留用户配置的 Codex 模型与 ChatGPT 订阅登录；每条消息仍由 AI 理解，不以关键词代替。降低重复初始化和排队开销，真实暴露连接故障。

## 执行顺序与验收

1. T1 连接诊断（中风险）：用虚构输入测量启动、首个输出、完成及连接重试；不发送飞书测试消息，不读取业务代码或凭据内容。不把模型超时归咎于飞书。产出可复用诊断脚本与真实计时。
2. T2 常驻对话进程（中风险，依赖 T1 协议核实）：使用已安装 Codex app-server 的 stdio 协议。同群/用户/角色/项目隔离线程；复用线程；只读、禁止审批与外部动作。应用侧权限门控保持。完成事件即可交付，不等待进程退出。产出适配器、失败恢复与协议测试。
3. T3 调度及反馈（中风险，依赖 T2）：同会话有序，不同会话有界并发，开发 Runner 不占聊天队列；慢响应提示事实状态；持久化阶段耗时和消息 outbox，不因重试重复动作。
4. T4 验证与重启（中风险，依赖 T2/T3）：回归测试、同模型真实冷/热调用、核对无运行任务后重启，检查六个机器人及 Runner。记录未解决的网络问题，不承诺未经测量的秒回。

非目标：换模型、换 API Key、取消真人审批、自动重跑状态不明的开发任务、全局修改 Codex 配置。
