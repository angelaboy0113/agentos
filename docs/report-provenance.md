# 报表字段追溯与精确加权

适用版本：1.63.0，2026-11-05。Node 22.x，无新依赖或部署配置。

`summarize_dataset` 输出列可改名。程序核验现在按其聚合配方追溯真实来源列，而不是把新别名直接到原始数据查找。这个规则覆盖嵌套汇总、唯一维度查找及保存数据关联。失败信息标出 `source`、`column`、`referenceRef`、`referenceColumn`，先检查该分量及其配方，不重复查询已有正确的全部指标。

## 已分组数据的金额核验

当数据把同样金额分成若干组，并已有每组记录数时，直接用精确加权，不需要重新下载全部明细或按旧明细重复次数展开独立基准：

```json
{
  "datasetRef": "<本任务完整独立金额分组>",
  "groupColumns": ["customer_code"],
  "aggregates": [{
    "op": "weighted_sum",
    "column": "unit_amount",
    "weightColumn": "record_count",
    "as": "verified_total",
    "nulls": "error"
  }]
}
```

计算是精确的 `Σ(unit_amount × record_count)`，也可用于数量与单价等合成对象。字段必须实际存在，十进制文本不转浮点，不损失大整数。`nulls=error/empty/zero` 必须明确；empty保留未知，zero只能在业务依据允许时用。结果超出已有12位精确小数能力时明确失败，不静默舍入。真实字段名称、期间、权限及业务公式必须来自已核实依据，示例不代表业务默认规则。

数值和权重都进入原始证据追溯。关联展开所用的行数也属于依赖：从原明细复制的金额或重复次数不能变成“独立查询基准”。同源或相交的必要证据仍拒绝自证；这不是取消金额核验。

## 窗口统计

独立窗口基准可以是另一套完整窗口配方，也可以是带真实对象键的完整原始分组聚合。程序要求键唯一、覆盖完整、每个对象数值完全一致，且原始证据独立。仅一个没有对象键的总计，无法证明属于哪个对象；错值、重复键、缺对象及同源派生仍报错。工具不能自动证明业务窗口语义，应在列定义和scopeEvidence核实期间和筛选。

## 恢复与部署

compose/summarize与finalize的输入错误均保存到原任务、原环境的tool-results，隐藏凭据；诊断保存失败不覆盖最初错误。新weighted_sum配方使用原dataset_summary版本封装并明确op，恢复/定稿重算、集中刷新重放一致，需迁移所有来源、配方、行分块、文件核验与投递回执。旧版本不支持weighted_sum，不要把新在途配方盲交旧程序；先在自然空闲时备份、处理在途任务/文件，再按维护流程回退源码。

仅更新当前实例代码与说明，空闲后重启唯一服务，无新增认证权限或生产写入。回归覆盖不同系统/环境、别名追溯、精确金额/权重/空值、逐对象窗口基准与拒绝同源自证。历史全量数据的本地回放、真实群交付、全新问题端到端速度分别记录；其它操作系统及完整私有跨机迁移未实测。不设置整任务时长、轮次或调用总数截止。
