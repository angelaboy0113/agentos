# 完整分组报表与文件交付

用于“每家经销商分别是多少，并给出完整清单”等查询。实时金额不使用团队知识缓存；知识只能帮助找到已核实的计算方法。此能力不支持任意 SQL 或模型编写脚本查询数据库。

## 配置与使用

在 `config/environments.local.json` 的已审核 MySQL `mode: "investigate"` 查询中，显式添加：

```json
{
  "exportMaxRows": 10000,
  "exportTimeoutMs": 30000
}
```

这是查询对象内的两个字段，不是完整配置；保留其现有表范围、用途参数、`maxRows`、`timeoutMs`、只读账号策略及负责人配置。`exportMaxRows` 必须为 1–10000；`exportTimeoutMs` 为 1000–60000 毫秒，未填写时为 30000。未配置 `exportMaxRows` 不提供报表工具；模型不能自行开通。`maxRows` 仍限制一般抽样行数，单 SQL 超时仍使用 `timeoutMs`。配置变化使旧授权失效，应重新提问，不接着使用旧授权。

团队成员直接在原群中说明环境、统计期间、每一列的含义、计算口径以及是否需要完整文件，不需要填写 SQL 或复制数据。实际数据库访问继续使用现有查询授权，不扩大账号和表范围。

## 原问题与业务口径

用户无需更换原提问格式。数据库规划器除本轮短`purpose`外，会收到同一任务原问题和最近两段源码分析（各有界12000字符，截断明确标记）；这些是资料，不扩大环境授权。源码调查先确定对象全集、期间、状态、费用范围、每列公式、组织映射和缺失处理，再进入数据库取数。项目名含关键字只是定位线索，不能自动等同业务范围。缺少源码规则应返回补查，不以多轮单户抽样猜全量口径。

## 执行过程

1. 读取目标表结构，确认分组字段、数值类型及 InnoDB 引擎。
2. `group_dataset` 单表分组，或 `linked_group_dataset` 两个基础表按等值字段关联后分组。关联前核对一对一、一对多关系，防止重复累计。
3. 程序在同一连接的 REPEATABLE READ 只读事务内，按全部分组键排序，每页至多 500 组，直到实际结束或碰到上限。每页之前、之后重新校验原授权和配置。超时会销毁连接；新的授权事务可恢复本任务已有完整数据集，但不能称为同一事务快照。
4. 工具返回当前任务 `datasetRef`、实际组数、完整性及至多 20 行、8KB 预览。完整数据由程序保存于本轮内存，不把全表放进模型上下文。每轮内存最多 24 个数据集、总计16MB。完整数据集以0600 JSON保存到任务目录的datasets子目录，任务内累计最多24份/32MB，24小时内可在新授权下接续；不完整数据不落盘。只允许同一任务目录、相同环境配置指纹，恢复时重新检查当前授权、行数上限、文件类型、SHA-256及有效期。不能跨任务或环境复用，不接受任意文件路径。
5. 下一轮先用`list_datasets`查看已有完整数据集。两份数据覆盖范围不同，用`compare_datasets`按非空唯一主键精确比较，返回缺失数量及有限预览，不重新跑整套SQL。`inspect_dataset`查看某份数据实际SQL和参数，目录仅提供有界预览；旧数据没有查询定义时不能充当最终核验基准。`compose_report`按同一主键全外连接完整数据集，可用`population: {datasetRef, keyColumn}`限定原要求的完整主对象集合，避免无关来源扩大范围。每个来源的主键必须非空且唯一；不完整来源不能导出。缺失值默认报错；只有明确 `missing: "zero"` 或 `"empty"` 才允许补零或空值，业务上是否应该补零仍需核实。
6. 计算仅支持固定的加、减、取较小值及字段引用；使用整数定点计算，支持至多 12 位小数，拒绝浮点结果和任意表达式。生成 UTF-8 BOM CSV，Excel 可打开，转义公式样式文本。最多 12 列、10000 行、10MB、每轮4个文件。合成结果本身也保存为可接续数据集，方便后续补列而不重算全部金额。派生数据沿用最早来源取数时间，不刷新旧证据寿命。结果提供sourceSnapshots和snapshotConsistency：跨轮拼接为multiple_read_times，不能声称同一个数据库事务，也不证明当前实时余额；最终核对仍须评估时点、业务范围和金额一致性。
7. `compose_report`只返回`draftFile`，不登记可交付文件。下一步调用`finalize_report`，填写原要求摘要`requirement`、按原问题列顺序的`expectedColumns`、范围依据`scopeEvidence`、独立原始范围集`populationRef/populationKey`、每列`columnRules: [{label, definition, evidence}]`及计算分量核对`checks: [{source, column, referenceRef, referenceColumn, evidence}]`。程序要求列完全一致、对象内部主键集合相等（不要求在用户CSV额外增加主键列）；算术或数值指标列用到的每个来源分量，其合计必须与另一原始查询的完整基准集精确相等。基准可以按月份等较粗粒度分组，避免重新读取明细。不能引用同一SQL+参数或草稿自证；同样错误的业务筛选仍可能产生相同合计，业务条件需源码核实。原要求和口径依据是Agent解释的结构化资料，程序不声称已经自动理解或证明自然语言语义。
8. 所有来源、范围集、基准和草稿最早取数时点差异不得超过5分钟；超出窗口刷新受影响数据。窗口内不等于多轮同一事务。通过后保存0600的`report-<uuid>.verification.json`，绑定文件摘要、原问题、逐列依据、范围、分量合计与来源版本，并返回含`verificationHash`的`exportFile`。定稿记录不可覆盖；修改需生成新草稿。
9. 控制面核验任务目录、普通文件、大小、SHA-256和核验记录后登记文件。最终任务完成且结果为`ready`时，只回复当前问题轮次**最后一份通过核验的文件**，旧版本和中间草稿留本机。本入口目前每个问题交付一份最终文件；不自动把多份过程文件批量发群。旧版本缺核验记录的待发文件停用，避免升级后误发。
10. 文件消息使用固定幂等键及持久 outbox；失败重试发送，不重跑 Codex 和数据库查询。发送期间保留冻结的原消息和机器人身份，重启后继续重试。

CSV 完整读取只证明本次筛选数据已取完，不代表期间、来源表、状态口径、调整方向或用户全部要求已经正确。最终仍需核对经销商数量、各列合计、必要抽样与参考报表。不同数据库、不同事务之间没有全局一致性保证；MyISAM 等非事务引擎不支持此完整分页能力。

## 文件位置与排错

- `AGENTOS_DATA_DIR/exports/<JOB>/datasets/`：本任务可接续的完整结构化数据集，保留取数时间和配置范围，不属于共享知识库。
- `AGENTOS_DATA_DIR/exports/<JOB>/report-<uuid>.csv`：CSV草稿或已定稿文件，0600；目录0700。是否可交付以核验记录为准。
- 同目录`report-<uuid>.verification.json`：最终程序核验记录，0600；其摘要与CSV一同登记，不代表人工业务验收。
- `AGENTOS_DATA_DIR/lark-cli/reports/`：CLI 文件回复的本地副本。
- `data/agentos.json`：任务的 `reportFiles` 登记和 `reportDeliveries` 发送状态，包含校验值、原目标和重试时间，不保存 CSV 正文。
- 文件不进入 Git、共享知识库或公开下载站点；按团队数据保留要求清理。当前没有自动删除报表的后台任务。删除前确认已交付且不再需要重试，主副本分别清理。

遇到“不完整”不能把预览当全量清单；应核对当前授权上限及筛选范围。达到上限需要维护者评估后调整，仍不能超过10000行。缺失值、重复主键、非 InnoDB 表、数值格式和未读取字段都必须先解决，不能强行导出。多源关联复杂到两个基础表与固定公式无法表达时，仍需新增经过审核的查询能力，不能声称任意报表都已支持。

发送失败先看 `reportDeliveries`，检查文件校验、原消息可回复性，以及原机器人是否有文件上传与消息发送权限。不要通过复制到其他群、切换机器人或扩大权限来绕过失败。文件已生成但业务调查尚未完成时暂不发送是预期行为。

浏览器只读现在将空正文、加载中和仅内嵌框架区分为未取得业务内容；对空页面最多等待三次、每次 400ms，且每次重新检查授权。URL 保留当前 hash 路由供诊断。该改动不代表已经实现任意 iframe 的读取，也不能证明现场空白的具体原因；不能将空白说成报表无数据或账号无权限。

## 验证边界

回归覆盖完整分页、整页边界、上限截断、精确计算、多来源合并、空值与重复主键拒绝、授权撤销、CSV 转义、文件校验、原话题发送、断线及重启重试、旧问题轮次隔离与 Chrome 空页面识别。真实 PRD 财务报表口径、实际机器人文件权限及 Windows 交付还需要部署团队验收，不能用模拟测试代替。


## 整个任务的调查预算与中断结果

单轮工具预算之外，连续分析还受整个任务的执行预算约束：`AGENTOS_ANALYSIS_TOTAL_TIMEOUT_MS`默认1200000（20分钟，范围60000–7200000）；`AGENTOS_ANALYSIS_MAX_ENV_ROUNDS`默认8（2–30）；`AGENTOS_ANALYSIS_MAX_STAGNANT_ROUNDS`默认2（1–5）。在AgentOS启动环境设置后重启；不自动修改本机配置。执行时长累计started至completed/failed/cancelled之间的区间，等待真人登录或补充的时间不计入。达到时限会终止当前任务子进程树，确认退出后保留已有结果并停止；无法确认退出仍按原取消安全规则暂停Runner，不继续取新任务。

程序在任务状态保存独立investigationProgress，不能因最近8项上下文被裁剪而清空。有效业务结果使用去除时间、随机引用和描述的内容摘要；仅读表结构、换一句缺口描述不作为业务进展。新核实的核心目标可以重置无进展计数，整个任务预算仍不重置。同一业务数据再次出现不重复计为进展；目的改写不能绕开轮次限制。连续三次申请格式错误也会收尾，不无限修复参数。

达到预算、无进展停止或执行中断时，原问题未完成仍显示受阻，明确保留已取得的查询结果、待核实目标和中间文件数量，不伪装为完整交付。本机任务状态接口超时说明“可能已受理、未重复提交”，不直接归因数据库慢或网络断开；已有结果不会被一句英文timeout覆盖。系统无法根据旧任务单独一行timeout还原历史具体故障环节。
