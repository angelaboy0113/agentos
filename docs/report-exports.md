# 完整分组报表与文件交付

用于“每家经销商分别是多少，并给出完整清单”等查询。实时金额不使用团队知识缓存；知识只能帮助找到已核实的计算方法。此能力不支持任意 SQL 或模型编写脚本查询数据库。

## 配置与使用

在 `config/environments.local.json` 的已审核 MySQL `mode: "investigate"` 查询中，显式添加：

```json
{
  "exportMaxRows": "all",
  "exportTimeoutMs": 30000,
  "exportSnapshotWindowMs": 300000
}
```

这是查询对象内的字段，不是完整配置；保留其现有表范围、用途参数、`maxRows`、`timeoutMs`、只读账号策略及负责人配置。`exportMaxRows` 可为 `"all"`（逐页到实际结束，不预设总行数）或管理员明确的正安全整数；没有10000行程序上限。`exportTimeoutMs` 为 1000–60000 毫秒，未填写时为 30000。`exportDataBudgetBytes`可选，为管理员明确的任务中间数据磁盘预算（正安全整数字节），不再默认32MB或设置256MB天花板；未配置时不设置业务容量门槛。已配置的值继续生效，不由模型自行修改。实际磁盘/内存耗尽仍可能失败，应保留已有成果并排查机器资源。`exportSnapshotWindowMs`为多源取数允许的最大时点差，默认300000（5分钟），管理员可按业务数据变化频率配置60000–3600000。较长窗口只允许较大的时间差，不保证同一事务或同一时刻余额；需要严格一致快照的业务不能靠放宽窗口解决。未配置 `exportMaxRows` 不提供报表工具；模型不能自行开通。`maxRows` 仍限制一般抽样行数，单 SQL 超时仍使用 `timeoutMs`。配置变化使旧授权失效，应重新提问，不接着使用旧授权。

团队成员直接在原群中说明环境、统计期间、每一列的含义、计算口径以及是否需要完整文件，不需要填写 SQL 或复制数据。实际数据库访问继续使用现有查询授权，不扩大账号和表范围。

## 原问题与业务口径

用户无需更换原提问格式。数据库规划器除本轮短`purpose`外，会收到同一任务原问题和最近两段源码分析（各有界12000字符，截断明确标记）；这些是资料，不扩大环境授权。源码调查先确定对象全集、期间、状态、费用范围、每列公式、组织映射和缺失处理，再进入数据库取数。项目名含关键字只是定位线索，不能自动等同业务范围。缺少源码规则应返回补查，不以多轮单户抽样猜全量口径。

## 执行过程

1. 读取目标表结构，确认分组字段、数值类型及 InnoDB 引擎。
2. `group_dataset` 单表分组，或 `linked_group_dataset` 两个基础表按等值字段关联后分组。关联前核对一对一、一对多关系，防止重复累计。
3. 程序在同一连接的 REPEATABLE READ 只读事务内，按全部分组键排序，每页至多 500 组，直到实际结束或碰到上限。每页之前、之后重新校验原授权和配置。超时会销毁连接；新的授权事务可恢复本任务已有完整数据集，但不能称为同一事务快照。
4. 工具返回当前任务 `datasetRef`、实际组数、完整性及至多 20 行、8KB 预览。完整数据由程序保存于本轮内存，不把全表放进模型上下文。内存缓存按16MB预算释放较少使用的副本，完整数据仍可从任务目录恢复；不再设置单个数据集16MB门槛。完整数据集以0600 JSON保存到任务目录的datasets子目录，任务内累计按实际字节预算管理（仅配置时生效），没有24份数量上限，24小时内可在新授权下接续；不完整数据不落盘。只允许同一任务目录、相同环境配置指纹，恢复时重新检查当前授权、行数上限、文件类型、SHA-256及有效期。不能跨任务或环境复用，不接受任意文件路径。
5. 报表调查每轮连接后先自动调用`list_datasets`查看已有完整数据集。目录每页最多20项并受返回字节预算约束，按nextOffset继续分页；可传offset/limit。同一轮同一只读事务中的相同完整分组查询复用已有结果和原取数时间，不再执行SQL或重复落盘；新事务不自动复用旧实时数据。两份数据覆盖范围不同，用`compare_datasets`按非空唯一主键精确比较，返回缺失数量及有限预览，不重新跑整套SQL。`inspect_dataset`查看某份数据实际SQL和参数，目录仅提供有界预览；旧数据没有查询定义时不能充当最终核验基准。`compose_report`按同一主键全外连接完整数据集，可用`population: {datasetRef, keyColumn}`限定原要求的完整主对象集合，避免无关来源扩大范围。每个来源的主键必须非空且唯一；不完整来源不能导出。缺失值默认报错；只有明确 `missing: "zero"` 或 `"empty"` 才允许补零或空值，业务上是否应该补零仍需核实。
6. 计算仅支持固定的加、减、取较小值及字段引用；使用整数定点计算，支持至多 12 位小数，拒绝浮点结果和任意表达式。生成 UTF-8 BOM CSV，Excel 可打开，转义公式样式文本。最多12列、每轮4个草稿；行数按exportMaxRows配置，不设置10MB文件大小门槛。合成结果本身也保存为可接续数据集，方便后续补列而不重算全部金额。派生数据沿用最早来源取数时间，不刷新旧证据寿命。结果提供sourceSnapshots和snapshotConsistency：跨轮拼接为multiple_read_times，不能声称同一个数据库事务，也不证明当前实时余额；最终核对仍须评估时点、业务范围和金额一致性。
7. `compose_report`只返回`draftFile`，不登记可交付文件。下一步调用`finalize_report`，填写原要求摘要`requirement`、按原问题列顺序的`expectedColumns`、范围依据`scopeEvidence`、独立原始范围集`populationRef/populationKey`、每列`columnRules: [{label, definition, evidence}]`及计算分量核对`checks: [{source, column, referenceRef, referenceColumn, evidence}]`。程序要求列完全一致、对象内部主键集合相等（不要求在用户CSV额外增加主键列）；算术或数值指标列用到的每个来源分量，其合计必须与另一原始查询的完整基准集精确相等。基准可以按月份等较粗粒度分组，避免重新读取明细。不能引用同一SQL+参数或草稿自证；同样错误的业务筛选仍可能产生相同合计，业务条件需源码核实。原要求和口径依据是Agent解释的结构化资料，程序不声称已经自动理解或证明自然语言语义。
8. 所有来源（含派生链最晚取数时点）、范围集、基准和草稿的取数差异按exportSnapshotWindowMs核验；超出窗口集中刷新受影响来源和独立基准，重做草稿。窗口内不等于多轮同一事务。通过后保存0600的`report-<uuid>.verification.json`，绑定文件摘要、原问题、逐列依据、范围、分量合计、来源版本及readWindow实际起止时间/差值/允许窗口，并返回含`verificationHash`的`exportFile`。定稿记录不可覆盖；修改需生成新草稿。
9. 控制面核验任务目录、普通文件、实际大小与登记一致、SHA-256和核验记录后登记文件，不因文件超过5MiB或10MB拒绝。程序核验后还需对照原问题完成交付审阅；最终任务完成且结果为`ready`时，只回复当前问题轮次**最后一份通过程序核验且交付审阅已接受的文件**，旧版本和中间草稿留本机。本入口目前每个问题交付一份最终文件；不自动把多份过程文件批量发群。旧版本缺核验记录的待发文件停用，避免升级后误发。
10. 文件消息使用固定幂等键及持久outbox；飞书IM上传单文件平台容量为30MB，程序以29000000字节为传输分卷大小，不作为报表总大小上限。大CSV按完整记录分卷，每卷重复表头，保留引号、单元格换行和全部行，附原文件摘要/分卷清单。单条记录连同表头已超过平台容量时按字节分卷为.bin并附macOS/Linux与Windows PowerShell还原说明，不能把.bin称为可独立打开的CSV。每卷分别保存SHA-256、幂等键和消息回执；重启/失败只续发未完成卷，不重跑Codex或数据库。原私有接收人、原群/话题和机器人不改变；每卷发送前复查当前轮次和审阅状态。发送期间保留冻结的原消息和机器人身份，重启后继续重试。

CSV 完整读取只证明本次筛选数据已取完，不代表期间、来源表、状态口径、调整方向或用户全部要求已经正确。最终仍需核对经销商数量、各列合计、必要抽样与参考报表。不同数据库、不同事务之间没有全局一致性保证；MyISAM 等非事务引擎不支持此完整分页能力。

## 文件位置与排错

- `AGENTOS_DATA_DIR/exports/<JOB>/datasets/`：本任务可接续的完整结构化数据集，保留取数时间和配置范围，不属于共享知识库。
- `AGENTOS_DATA_DIR/exports/<JOB>/report-<uuid>.csv`：CSV草稿或已定稿文件，0600；目录0700。是否可交付以核验记录为准。
- 同目录`report-<uuid>.verification.json`：最终程序核验记录，0600；其摘要与CSV一同登记，不代表人工业务验收。
- `AGENTOS_DATA_DIR/lark-cli/reports/`：CLI 文件回复的本地副本。
- `data/agentos.json`：任务的 `reportFiles` 登记和 `reportDeliveries` 发送状态，包含校验值、原目标和重试时间，不保存 CSV 正文。
- 文件不进入 Git、共享知识库或公开下载站点；按团队数据保留要求清理。默认滚动30天本机保留；每小时及启动时清理已过期且无保留任务引用的主报表、数据集和CLI副本，待处理/执行中的任务与必要引用受保护。过期问题的未发送文件不再重试，详见docs/retention.md。

遇到“不完整”不能把预览当全量清单；应核对当前授权上限及筛选范围。达到上限需要维护者评估后调整，或改为all，不得把抽样或截断结果作为完整交付。缺失值、重复主键、非 InnoDB 表、数值格式和未读取字段都必须先解决，不能强行导出。多源关联复杂到两个基础表与固定公式无法表达时，仍需新增经过审核的查询能力，不能声称任意报表都已支持。

发送失败先看 `reportDeliveries`，检查文件校验、原消息可回复性，以及原机器人是否有文件上传与消息发送权限。不要通过复制到其他群、切换机器人或扩大权限来绕过失败。文件已生成但业务调查尚未完成时暂不发送是预期行为。

浏览器只读现在将空正文、加载中和仅内嵌框架区分为未取得业务内容；对空页面最多等待三次、每次 400ms，且每次重新检查授权。URL 保留当前 hash 路由供诊断。该改动不代表已经实现任意 iframe 的读取，也不能证明现场空白的具体原因；不能将空白说成报表无数据或账号无权限。

## 验证边界

回归覆盖完整分页、整页边界、上限截断、精确计算、多来源合并、空值与重复主键拒绝、授权撤销、CSV 转义、文件校验、原话题发送、断线及重启重试、旧问题轮次隔离与 Chrome 空页面识别。真实 PRD 财务报表口径、实际机器人文件权限及 Windows 交付还需要部署团队验收，不能用模拟测试代替。


## 长任务与中断结果

连续分析没有整个任务/整个问题的固定总耗时或总调查轮次上限。有新增证据、明确可执行目标且权限有效时允许长时间继续；`AGENTOS_ANALYSIS_TOTAL_TIMEOUT_MS`与`AGENTOS_ANALYSIS_MAX_ENV_ROUNDS`旧变量不再生效，不会通过保留旧启动配置恢复截停。源码分析的首轮/续轮也不设墙钟截止时间，旧`AGENTOS_ANALYSIS_TURN_TIMEOUT_MS`和`AGENTOS_ANALYSIS_RESUME_TIMEOUT_MS`不再生效。执行时长仅用于统计，不是失败依据。变更需要更新程序并重启；已有受阻任务不会自动重跑。

用户主动停止、真实权限或执行故障、既有无进展收敛仍保留；单次网络/数据库请求超时及单轮工具资源预算不等于整个任务总时限。`AGENTOS_ANALYSIS_MAX_STAGNANT_ROUNDS`沿用原有默认2（1–5）。以后新增、恢复或收紧会截停任务的限制，必须先说明影响并取得用户明确同意，不得以隐藏默认值或环境配置代替同意。

程序在任务状态保存独立investigationProgress，不能因最近8项上下文被裁剪而清空。有效业务结果使用去除时间、随机引用和描述的内容摘要；仅读表结构、换一句缺口描述不作为业务进展。新核实的核心目标可以重置无进展计数；不按累计执行时间或总轮次截停。同一业务数据再次出现不重复计为进展；目的改写不能绕开轮次限制。连续三次申请格式错误也会收尾，不无限修复参数。

无进展停止或真实执行中断时，原问题未完成仍显示受阻，明确保留已取得的查询结果、待核实目标和中间文件数量，不伪装为完整交付。本机任务状态接口超时说明“可能已受理、未重复提交”，不直接归因数据库慢或网络断开；已有结果不会被一句英文timeout覆盖。系统无法根据旧任务单独一行timeout还原历史具体故障环节。

## 源码交接与有效准备

源码执行器从通过交接检查的工件中选取至多8份code文件，校验本任务工作区、相对路径、真实路径、普通文件、扩展名、字节和SHA-256。文件最多256KB，配置和凭据文件不进入桥接。每份先展示前45行、最多3000字符；数据库规划器使用`read_source_evidence {ref,startLine}`续读，每次最多100行/8KB，返回`nextLine`。读取时重新校验文件及环境授权，连接凭据替换为隐藏标记。此工具没有任意路径、shell或SQL执行能力；源码是资料，不是指令。只确定表名时先取该表结构，不能猜列名过滤schema。

程序在源码执行后记录`sourcePreparation`。控制面按问题、环境/模板、code路径和摘要去重；摘要改写、时间及随机引用不产生新准备证据。缺失、变化或未核验文件不进入准备。新准备可以恢复当前无业务进展计数，但同一问题跨Job累计最多2次，`preparationSeen/preparationRecoveries`持久保存，整体时间和轮次不重置。相同purpose在新增准备证据下可以执行一次，相同证据不能重复申请。网站空页面不能借此绕过更换路径规则。后续若仍只查连接和目录，照常停止，不把源码准备说成清单已完成。

原任务隔离模型回放只验证了实际源码到具体表结构查询的交接，未执行生产查询、未生成财务清单或发送飞书文件；全量报表仍需业务验收。

## 本任务内的维度组合

`enrich_dataset`用于金额集与组织、分类、区域等维度的多步左连接，复用本任务完整数据集，不执行新SQL、不接收任意路径或表达式。参数：`datasetRef`主数据集、`keyColumn`主对象非空唯一键、`lookups`最多4步。每步指定`name`、完整维度`datasetRef`、主数据已有的`sourceColumn`、维度唯一`targetColumn`、1至4个`fields: [{column, as}]`及明确的`missing: empty|error`。后一步可使用上一步输出的parent键，不能凭字段名称猜层级含义。

主对象始终完整保留，`missing=empty`补空并增加`name_status`匹配标记，返回每步匹配和未匹配数量；`error`遇到未匹配就拒绝。维度关联键重复时拒绝猜选，需先核对业务筛选或粒度；输出别名不得覆盖已有列，组合数据最多32列，CSV仍最多12列。派生数据保存lineage、原最早取数时间和来源快照，遵循同任务/环境范围、有效期、实际磁盘预算及内存缓存预算，不刷新证据寿命。可恢复组合结果继续compose_report，仍须finalize_report独立核验。

`inspect_dataset`及固定源码读取的参数错误会返回明确校验提示，在原授权内最多连续修正3次；错误不会伪装成数据库执行失败。授权、文件摘要变化及范围失败不通过参数重试绕过。结果保存`toolInputErrors`及终止时的固定`environmentFailure`工具名/错误码，不向群里输出原始异常或凭据。历史任务未保留的原始失败参数不能事后断言；恢复已有数据集不等于重新查询生产库。

## 校验修正与空间不足

工具输入错误的具体说明（隐藏凭据、有界长度）随toolInputErrors保留，包含是否已修正；下一轮investigationContext.corrections和源码调查记录能看到缺口。inspect_dataset为草稿提供实际expectedColumns和requiredChecks来源/数值列，缺少独立基准时直接列出缺项。不因为REPORT_INPUT重新读取整套数据。

磁盘预算包含目录内实际文件，过期/无效文件也占空间；不自动删除被引用的证据。达到预算返回明确DATASET_CAPACITY，保留已有成果并停止新增取数，维护者评估后调整配置或按保留要求清理，不显示为数据库未知故障。内存释放不修改文件引用或证据时间。目录、授权、摘要和独立金额核验仍保留。以上能力适用于不同业务对象的多源清单，不绑定具体报表或项目。

## 交付审阅、版本与补查

程序核验与原问题交付审阅分别保存。任务reportFiles登记verificationHash、原生成任务sourceJobId和问题轮次；reportReviews按文件保存awaiting_review（待审阅）、accepted（原要求已满足）或revision_required（发现影响结果的问题）。草稿不进入可投递状态；旧记录没有新状态时沿用原有最终任务与核验门控，不自动给旧受阻任务补发。

源码Agent收到文件目录与审阅状态，填写task-result.schema.json的reportAssessment（其他任务为null）：fileId、coverage（complete/incomplete）、decision（deliver/revise/needs_review）、issues（kind及具体evidence）。current_formula/current_scope/current_coverage/current_source以及required_output属于影响交付的问题；historical_difference、optional_followup单独说明。用户明确要求历史对账时，未解释的差额属于required_output。coverage仍需Agent对照全部原要求判断，程序不能自动证明财务业务语义。

已声明原要求完整满足、文件程序核验有效，且没有当前实质问题时，归一为ready，关闭original-question，清除额外环境查询；不能因另一时点历史金额不同无限追查。还需通过既有源码/工件交接门控才记accepted。发现具体当前问题则保存revision_required及依据，禁止该版本投递；修正后生成、核验并审阅新版本，不覆盖旧核验记录。历史差异本身不能推翻已接受版本。

超时或自动调查停止时，已有accepted且未被具体问题推翻的版本可保留原ready结论；只有程序核验但尚未完成审阅的文件不会因此自动变为正式成果。实际发送仍检查文件、核验摘要、当前问题轮次、原机器人和投递状态，旧目录与状态故障不触发重新查库。

## 集中刷新报表

当前口径修正或多源取数超窗时，refresh_report接收与finalize_report相同的草稿、范围、列定义及独立基准参数。程序先检查依赖图，再结束当前只读事务并开启新的READ ONLY事务，统一重放原始分组来源、独立基准、对象范围和左连接派生链，重做草稿并执行原有最终核验。共享依赖只刷新一次，仍逐页检查授权、行数、表范围、InnoDB与时间/空间预算；一个工具的时限仍受exportTimeoutMs约束，失败保留原成果。

新取得的分组数据保存固定工具recipe（group_dataset/linked_group_dataset及已验证参数）。刷新通过当前工具重新校验结构与范围，绝不执行文件里保存的SQL文本。旧数据没有recipe、参数被脱敏改变或依赖临时in_set集合时，预检阶段拒绝自动重放；应在当前授权内重新取得可重放来源。它不支持任意脚本或SQL，不能跨任务/环境恢复，也不表示已实现任意复杂报表。通过刷新后的文件依然需要原问题审阅和真实业务验收。

## 按文件核对实际内容

源码审阅会自动收到最新已核验文件的绑定资料：fileId、CSV SHA-256、verificationHash、实际表头、完整固定公式、来源摘要、少量预览，以及程序对全部行逐列重算的结果。不会要求用户重新上传本机已登记的CSV。用户明确提出的公式、期间和输出要求优先于参考报表的默认口径。

需要更多细节时，通过已有授权查询的`inspect_report`读取；不连接数据库，不执行任意路径，也不重新生成文件。参数为`fileId`，可选`section`（summary/columns/sources/checks/scope）、`offset`和`limit`（1–4）。仅允许当前任务登记的文件；继承文件按登记的原任务定位。未启用exportMaxRows的入口不提供该工具。现有数据集的授权范围、摘要及有效期仍参与验证。

程序核对文件、核验记录、计算草稿和来源之间的绑定，使用精确十进制重算所有单元格并与实际CSV字节比较。旧核验记录可通过绑定的草稿恢复公式；缺失、过期、修改或超限时明确返回REPORT_INSPECTION，保留成果供维护者核查。读取缺口属于review_access，不能冒充已经证实的公式错误；重新查询数据库不能替代对指定文件的核对。重算通过只证明文件执行了绑定公式，业务范围和公式本身仍需对照原问题及源码证据审阅。

文件审阅同时提供`populationAudit`：实际选定范围、其查询条件/业务依据，以及来源里按同一业务主键直接关联的完整集合，逐键列出两边缺失数量和少量样本。多层组织并不天然等于客户全集，数据源里有记录的对象也不天然等于全部有效对象；这些差异由Agent对照原问题、来源和源码判断。

出现范围差异时，交付审阅须填写`scopeReview`：`populationRef`、范围依据`evidence`，以及逐项`comparisons`（`datasetRef`、`keyColumn`、`decision`、`evidence`）。确属原问题范围遗漏时应标记`current_coverage`并修订；用户明确指定的子集或其他类型维度可以按实际依据记`out_of_scope`。程序不允许未审阅差异、错误范围引用或把非零差集直接标为`covered`后宣告完整。无差异或无报表时该字段可为null。不能因没有交易、金额为零而自行缩减用户未限定的有效对象范围，也不能无条件把所有维度记录加入清单。

## Excel 可读清单与默认配置

日常“整理成Excel/发个Excel表格/导出清单”默认允许交付已核验CSV，明确说明“CSV，Excel可直接打开”，不为换后缀重新取数或索取新工具。不能改后缀冒充XLSX。用户明确要求原生.xls/.xlsx、多个工作表、保留公式或特定工作簿功能时，继续尊重格式要求；当前工具不支持的部分应如实说明。纯格式问题使用current_format，与缺行、缺列、计算错误等真实required_output/current_formula分开。宽泛Excel需求的格式异议会回到正常内容审阅，不直接把未核实内容变为可交付。

已核实“专属配置优先、没有专属时继承通用配置”的业务，可在enrich_dataset的lookup里显式传fallbackKey（字符串，指向同一完整维度数据中实际存在且唯一的默认行）。程序优先精确匹配，缺失时才用该行填入真实生效值；状态列标记“沿用默认配置”，lookupChecks记录fallbackCount和fallbackKey。默认键、默认值必须由项目源码及查询结果核实，平台不写死“all”或“财月”。未传参数时保持原行为；默认键不存在/重复时拒绝猜测。数据集保留派生关系、来源范围与取数时间，集中刷新仍按已保存的参数重建。类别编码不应当金额相加，可关联实际字典名称输出。

## 交接文件命名空间

源码/规格按项目工作区相对路径检查。已登记报表在handoff.artifacts中使用kind=report及原filename或ID，Runner按reportFiles.sourceJobId定位任务导出目录，检查普通文件、原SHA-256和verificationHash，不去源码目录寻找CSV；未登记、跨轮、篡改或符号链接仍拒绝。源码工件也取消5MiB大小拒绝，改为流式计算摘要，敏感路径和工作区隔离保留。报表登记与投递同样流式计算摘要；源数据合成/公式审阅目前仍会载入完整数据，因此取消人为容量上限不代表机器物理资源无限或已经验证GB级报表。分卷临时目录为exports/<JOB>/.delivery-*，每次投递结束或正常异常清理，进程强制退出可能残留，可在确认不在投递后清理；主报表和核验记录保留。

专项验收使用合成17001行、超过16MB完整数据及超过30MB文件，验证分卷可还原、失败后续发和私有路由；没有向飞书实际发送大文件，跨平台和实际网络吞吐仍需部署团队验收。
