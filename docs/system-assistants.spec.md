# 同群多系统助手

## 范围与验收

同一话题群可配置多个系统机器人。每个 profile 绑定独立项目、规范入口、环境源码分支和数据连接；普通成员可分析文件、只读查询生产/测试并导出。非只读任务沿用管理员门禁。跨系统问题提示用户重新 @ 对应助手，不创建转交任务。

`chatProfileProjectMap[chatId][profile]` 优先于旧 `chatProjectMap`。存在按 profile 的群配置时，未登记 profile 拒绝匹配，不降级至群默认项目。会话、问题卡片、环境接入、源码任务使用相同解析函数。系统助手通过 `agents` 条目的 `systemAssistant: true`、`role: developer`、`allowedChatIds` 配置；执行阶段继续使用原接单 profile，其他岗位无需配置。

项目的 `assistantInstructionsFile` 是管理员配置的本地 MD 路径，聊天和执行器均读取。模型只看到当前系统的路径/连接，其他助手仅提供名称和系统标识以便提示用户。规范中的开发写入要求不能扩大只读任务权限。

## 环境与隔离

测试与生产使用现有 isolated 源码快照；规范总仓分支固定，微服务分支按系统配置。未指定环境先询问，不设置生产默认。远端分支缺失不回退其它分支。

程序部署使用专用 Git 分支与独立 clone；配置、data、快照、worktree、lark-cli 配置和 LaunchAgent 名称与原实例分开。新实例默认独立浏览器会话，避免操作原实例的 Chrome 标签。共享的账号订阅/操作系统权限仍是同一台电脑的资源，不宣称操作系统级隔离。

## 验证与边界

测试同群两个 profile、未知 profile 拒绝、旧群兼容、源码及环境接入作用域、执行器身份、错系统项目拒绝、成员写入拒绝。启动前核对机器人发布、群主身份、各仓分支、网络/凭据。模拟测试不等于真实业务验收。新飞书实施说明只同步新实例，不改旧部署手册。
