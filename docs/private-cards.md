# 按需私有卡片

在已启用实时卡片的群中，把开关放在原问题开头：

```text
@项目负责人 仅我可见：帮我核对这个字段的含义。
@项目负责人 /private 帮我查工号00110036，给我联系人信息图。
```

机器人提及由飞书事件解析移除后，正文以“仅我可见：”或“/private ”开头。不是每次都默认私有，不支持把已公开的卡片追溯改为私有。已经发在群里的原提问仍对群成员可见；问题本身有敏感信息时应直接私聊机器人。

普通群使用飞书 `/ephemeral/v1/send`，仅指定提问者可见；不转发、不通知、仅在线客户端可见。临时卡片无法普通PATCH更新，因此发送新私有卡片，保存新消息ID，再删除旧私有卡片；删除失败持久重试，不重做模型调查。API没有uuid幂等字段，超时且响应丢失时可能出现重复私有卡片，不能保证恰好一次。

话题群不支持临时卡片。在飞书明确返回18053且错误原因为`chat can not be thread`时，卡片通过同一机器人私聊给提问者；后续更新保持该私聊消息。权限不足、断网等其他错误不会切换为公开消息。文件和联系人图片走同一机器人私聊；若提问者不在应用可用范围内或私聊失败，保留投递重试，不公开降级。普通私聊会产生相应的飞书通知并保留普通消息记录，不能把它说成群内临时卡片。

开关写入conversation/question/job和卡片outbox，服务重启及任务阶段推进后保持；回复自己原问题时继承，其他人及新公开问题不混入私有历史。私有结果不自动加入共享知识或普通跨问题摘要；卡片按钮、详情页仅允许指定收件者。它是群消息可见性，不是本地数据加密/管理员隔离，已有生产访问、角色审批与环境权限不变。

无需新增配置；默认实时卡片配置`conversation.local.json`中`questionCards=true`建议保留。私有请求会独立建立问题卡片，即使普通问题没有启用questionCards。需启用机器人及其在群内，使用应用身份，具备消息发送/更新等官方任一所需权限；不借用个人token。源码升级需在任务与对话空闲时备份并重启，Windows同样使用Node22+和既有启动方式；Windows实机未验收。

验收：普通群由A发送仅我可见问题，A在线看到卡片，B确认看不到；A补充、翻详情与任务结束均保持私有；不加开关的B问题仍公开。话题群应由同一机器人私聊A；附件同样只发给A。模拟权限错误、更新失败、重启、另一人点击按钮均不能发公开结果。仅API成功不能代替第二名成员的可见性确认。

话题群转私聊后，可回复机器人发给你的最新私有卡片继续补充；只有精确匹配收件者、机器人profile、消息ID和真实私聊会话ID，才关联回原项目和问题。不是把任意私聊内容绑定到部署者的项目。
