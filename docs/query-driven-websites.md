# 按问题发现网站与本机登录接续

## 用途与入口

群成员直接提出问题，例如“核对 UAT 报表定时任务最近是否成功”。不需要维护网站白名单，也不必先提供 URL。负责人创建原环境的源码分析，开发从问题、当前环境源码和文档查找实际入口，返回 `websiteQuery: {url,tier,purpose}`。找不到可信入口或存在环境歧义时才需要补充线索，禁止猜地址。业务网页优先使用本环境域名，用户确认的旧入口更正保存方式见 [域名入口更正](canonical-websites.md)。

若入口位于 Nacos，使用 [调度入口发现](scheduler-discovery.md) 的 `read_runtime_config` 获取非敏感 XXL-JOB 配置，并将 `runtimeDiscoveries` 交给后续源码阶段提出 `websiteQuery`，无需用户重复提供已经发现的网址。

控制面建立 `kind=website` 环境，复用原问题、原发起人和当前审批规则；网页步骤成功或证据不足都会返回源码调查，结合原问题判断是否完成；见 [原问题完成判断](investigation-completion.md)。此次接入没有给源码 Codex 开放任意联网、桌面控制或个人浏览器 Cookie 读取权限。

## 部署

macOS 默认复用日常 Google Chrome，启用 Apple Events JavaScript 后按问题接管对应应用页；详见 [日常 Chrome 复用](shared-chrome.md)。可用 AGENTOS_BROWSER_MODE=isolated 恢复下述独立浏览器模式。其他平台默认独立模式。依赖仍为 Node 22、`npm ci`、`npx playwright install chromium`。更新后在空闲时重启 AgentOS。使用当前登录桌面的操作系统账号运行；无图形会话的服务器不能弹出可见浏览器。网页不需要逐个填写配置。

系统在私有 `config/environments.local.json` 自动登记：项目、UAT/PRD、站点入口、`kind: website`、查询目的模板和当前管理员映射。入口必须是无账号密码、无查询参数的 HTTP(S) 地址；不允许 localhost、回环或链路本地地址。自动登记不表示已连接或已登录。PRD 成员查询仍需环境负责人批准；UAT 成员按成员只读规则执行。首次发现入口保存在当前项目，不能跨项目借用授权。同源不同应用按完整入口路径分别登记，登录会话仍按origin复用；入口匹配与纠偏见 [网站目标识别](website-target.md)。

独立模式下，`data/website-sessions/<项目+环境+origin的哈希>/` 保存独立 Chromium 用户配置（Cookie、站点存储）。目录权限 0700，不进 Git，不发群、不送给模型；这不是 Keychain 加密文件承诺。不要共享整个 data 目录。删除对应目录可清除会话，需先停止 AgentOS/浏览器。不同项目、环境、origin 使用不同配置；同一站点的各问题使用不同页面和随机操作引用。

## 登录与自动恢复

1. Mac 默认复用日常 Chrome 的已登录应用页，找不到时新建同浏览器标签；独立模式才打开单独 Chromium。
2. 检测到密码框或登录 URL，卡片显示“等待本机登录”，不要求群成员复制 Token 或输入长确认词。
3. Runner 释放当前任务，其他问题继续。页面由控制面维护，不因 Worker 退出而关闭。
4. 登录恢复使用绑定原授权的一次性接续记录，新租约消费后继续原任务，重复领取仍拒绝；见 [登录接续实现与排障](login-resume.md)。运维人员在运行 AgentOS 的电脑登录。检测到离开登录页后自动恢复原任务、原问题、原发起人和已收集证据，无需回复“继续”。
5. 登录期间原查询授权过期或配置变更时，重新展示审批卡；登录成功不等于延长 PRD 授权。取消的任务不会恢复。
6. 控制面重启后可从持久会话恢复等待中的任务。会话被服务端撤销或过期仍需重新登录。

登录状态以常见密码框及 login/signin 路径识别，并非每个网站都支持；二维码、跨域 SSO、复杂 MFA 页面可能需要额外适配。日常 Chrome 模式复用其现有登录；独立模式不复用个人 Chrome/Safari 登录。

## 查看与操作边界

模型只能选择页面实际返回的引用：打开、读取页面、查看链接/详情/日志、翻页、填写查询条件、选择筛选项。不接收任意 JavaScript、任意 URL 跳转或坐标点击。页面文字按凭据模式脱敏；不能保证任意网站自定义字段全部可识别，因此仍需按项目控制群内信息展示。

独立模式按同源、请求方法、路由和动作特征限制请求，阻止已识别的保存、删除、执行、启动/停止及未知 POST；允许常见 pageList/query/logDetailCat 等查询请求。跨域请求、WebSocket、Service Worker、下载和弹窗默认阻断。**这些是通用保守规则，不是对所有网站“绝对只读”的形式化保证**：非标准 GET 副作用、同名接口语义仍需站点核验。未知接口受阻会作为缺口反馈，不能自动放开所有 POST 或把点击文字当充分依据。修改操作本次没有新增执行器；应走独立管理员审批的实施流程，不能借查看权限执行。

## 实现与观测

- `website-policy.js`：入口验证、项目/环境/站点键、请求规则、文本脱敏。
- `website-query.js`：源码发现入口落盘、等待登录轮询、原身份恢复、过期再审批。
- `website-browser.js`：可见持久会话、每问题页面、请求授权复核、页面引用。
- `POST /api/v1/jobs/:id/website-tool`：仅 Runner 令牌、当前运行租约和有效环境批准可调用。
- `environment-investigator.js`：规划调用、证据收集、登录检查点；没有固定总调用次数。
- `browserLoginRequired`、`browserCheckpoint`、`browser_login_resumed`：等待与恢复证据。原始凭据不写入这些字段。

排障先看卡片的等待/审批/受阻状态，再检查本机是否有图形桌面、Chromium、网络/VPN，以及详情的 `blockedRequests`（方法和路径，不含查询串）。登录成功后仍没有数据，可能是账号权限、跨域接口或页面适配问题，不能声称用户只需登录即可解决所有情况。

## 验证范围

自动化测试使用本机模拟网站与真实 Chromium：登录等待、重启复用 Cookie、页面隔离、变更请求阻断、动态入口、PRD 成员审批、授权过期再审批、等待卡片不出现文字补充表单。没有通过测试访问真实生产网站，也未证明任意业务网站兼容。macOS 为当前实施目标；Windows/Linux 图形会话未做实机验收。

日常 Chrome 模式不安装网络拦截，不具备独立模式的请求级隔离；仅按批准应用范围、任务授权及可见控件筛选执行，具体边界和验收见 shared-chrome.md。
