# MongoDB 任务记录的受控只读取证

调查可能已有事件明细却缺少主记录、逐图结果或审核前快照。应明确报告缺少的集合和字段；管理员核实业务来源、系统和环境并授权后，可新增一个独立 MongoDB 入口，复用已登记 SSH 传输与凭据，保留原入口和既有授权指纹。

当仅授权具体记录时，在 reviewed investigate 查询中配置 `requiredFilters`。它是管理员固定条件，不由模型填写或移除；本机和 SSH 远端执行器都会与模型筛选条件 AND 合并。冲突条件自然返回空结果，不能覆盖固定范围。原有数据库/集合、字段敏感检查、只读命令及项目/环境/机器人授权仍适用。

```json
{
  "mode": "investigate",
  "reviewed": true,
  "description": "已授权的父记录、逐项结果和审核快照",
  "collections": ["ReviewedTaskRecords"],
  "requiredFilters": [
    {"column": "parentId", "op": "=", "type": "string", "value": "REVIEWED_PARENT_ID"}
  ],
  "parameters": [{"name": "purpose", "type": "string"}],
  "maxRows": 20,
  "timeoutMs": 10000,
  "exportMaxRows": "all"
}
```

固定条件支持 string/objectId/int64 等值。schema 也在固定范围内抽样，read/count/group_dataset/explain 及数据集配方重放沿用固定条件；索引与集合工具仍只读元数据。配置进入授权指纹，改变范围后旧授权不能继续使用。说明和工具目录应提示固定范围。部署后先用受控只读探测核对精确记录，再恢复原问题；保留原身份、环境、源码和已有证据，记录维护介入。成功状态取决于业务问题是否真正回答。

这属于已知来源的范围补齐，不能自动授权模型发现的任何集合。完整数据集保留实际查询条件、来源和时间；跨记录、跨环境或跨系统须各自获准。迁移需包含私有配置和数据集；公开包只含以上占位示例。

回退到不认识 requiredFilters 的版本时，必须先停用整个新增记录入口，待该入口的在途任务自然完成或审核后再切换程序；不能只删除 requiredFilters 字段，否则会扩大读取范围。旧状态、已取得证据和工件仍保留，不能用旧整库备份覆盖新任务。

## 后台轮询的内存使用

容量恢复和截图投递轮询使用 stateView 先筛选待办、再复制返回值，避免空轮询反复复制所有历史任务。读取副本仍相互隔离，状态事务保持串行和原子写入。此改动减少指定轮询路径的内存与复制成本，不代表所有整库事务均已消除，也不改变任务并发或添加任务截止。

排查内存要分别看系统内存压力、服务 RSS、Node heapUsed/heapTotal、实际 OOM 堆栈及在途任务。Mac 有空闲内存不代表单个 V8 堆不会耗尽；退出信号本身也不能证明 OOM。大业务结果优先保存为任务数据集/工件，查询使用精确投影与完整分页；无待办时只读轻量投影。提高 Node 堆上限不能替代减少重复对象，不能未经验证降低并发或中断长任务。
