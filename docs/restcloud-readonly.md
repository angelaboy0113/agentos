# RestCloud 接口详情和日志定义的只读适配（1.69.1）

用途：在已有 ESB 登录和原任务授权内读取接口目录对应的配置、输入输出定义及日志字段，继续原流水调查。不是调用业务接口、API测试、重推、保存、发布或改配。

入口是既有 website 环境的 `queries.investigate.readEndpoints` 与 `readNavigationSelectors`。参考 [脱敏示例](../config/restcloud-read.example.json)，按自己平台实际前端、版本与方法审核后并入已有环境；保留原 bootstrap 读取、登录配置和管理员，不用示例覆盖已有完整配置。示例只列本次补充项，不包含所有版本的完整登录依赖。

经前端和实际页面核实的补充项：

| 方法 | 固定路径 | 读取内容 |
| --- | --- | --- |
| GET | `/restcloud/rest/core/services/showdetails` | 接口说明及当前配置 |
| GET | `/restcloud/rest/apiportal/apis/showdetails` | API管理中心详情 |
| GET | `/restcloud/rest/businesslog/fieldCode/list/all` | 日志查询字段定义 |
| GET | `/restcloud/rest/apiportal/apis/apm` | 接口依赖关系元数据 |
| GET | `/restcloud/rest/core/monitor/apilogs` | 平台调用日志列表；沿实际页面的接口、日期、分页筛选，不执行接口 |
| GET | `/restcloud/rest/core/monitor/logs/{objectId}` | 指定接口的调用日志；仍需原问题时间和分页筛选 |

API目录标题在部分版本使用 `.api-list-right-home-card-header-name` 的 div，不是原生链接。审核确认为打开说明详情后，通过 `readNavigationSelectors` 暴露为模型可见的 read-action，不能把整个页面或任意 div 都设成可点击。该配置接入现有控件目录和浏览器请求门控，无须新增绕过工具。

接口内部 `id` 与展示的接口编号 `configId` 不同；必须沿真实目录点击使用内部标识。用展示编号代替 id 时，“API已经被删除”响应不能作为接口已删除的结论。`backendUrl` 是当前配置，不证明历史流水实际命中。配置更新时间、文档发布状态不能当应用部署时间。

字段定义目录为空，只说明该查询入口没有自定义字段定义；不代表没有调用日志。继续检查原平台已提供的监控/调用日志，按原流水、时间和接口关联；不能将接收成功回执或累计调用次数当本流水处理证据。日志不可读取时保留具体路径/方法及缺口，不重复请求已有密码，不伪造根因。

权限：只允许同 origin 的审核后固定 GET；其它方法、写操作、跨站请求仍走原门控。不要用通配路径或允许整个 POST 来解决单个详情页受阻。日志与业务报文可能包含凭据，沿现有清理规则，不把令牌/密码发给模型或提交Git。新增其它端点须独立确认读取语义。

配置在网站工具调用时重新读取；修改会改变环境指纹。旧票据不能自动冒用新配置，维护者复核同身份、系统、环境、原问题和只读范围后重新签发、接续同卡；保留旧票据/结果审计、固定源码与已取数，不重跑整项调查。仅这类已支持字段的配置补充不需要重启控制服务。模型、身份或源码切换仍按各自维护规则。

验收分别记录：schema/请求边界回归；真实页面详情读取；原任务的流水日志与最终结论；卡片交付。前两项成功不能冒充业务根因已确认。打包包含示例、本文及回归，完整私有迁移仍须保留实际配置、凭据和取证。其它平台版本和操作系统需另行验证。

动态资源日志路径使用经过审核的完整路径模板。仅GET可用，整段`{objectId}`接受24位十六进制、`{uuid}`接受标准UUID、`{integerId}`接受1—20位十进制字符串，数字不转浮点。无通配符、自定义正则或任意动作名；静态前缀、路径段数量、同源与固定筛选仍核验。既有固定路径兼容，不为每张业务卡把接口ID写进OS核心。

1.69.0补齐实际前端声明且观察为GET的apilogs路径，不能以通用路径名推断所有平台版本相同。示例及本机登记仅追加此固定只读方法；其它统计/未知详情路径仍独立审核。浏览器已登录与日志接口可读、返回空集合与目标业务从未执行分别判断。真实调用日志是否保留请求/响应、是否覆盖目标时间仍取决于平台配置，不能将HTTP200宣称已取得SAP报文。

旧Ant Design日志查询页常用无name/id/placeholder的输入框与列内文本标签，并使用ant-calendar-picker。1.69.1的通用DOM适配从仅含一个可见字段的Ant/Element列容器提取短标签，暴露实际元素句柄引用；未知/多字段容器不猜业务含义。旧日期控件优先实际input而非不可点击包装层，日历保留年月日和禁用单元格边界；支持“高级搜索”只读展开。凭据标签字段即便没有name/type=password仍不提供模型填写或明文读取，业务重发/replay保持禁止；模型仍不能传JS/任意选择器。以实际页面的requestUrl/startDate/endDate等筛选参数为证据，不把搜索框填上就称日志已匹配或库存已确诊。
