# 留空金额与本机异常退出恢复

适用于原始金额可能为空的清单、历史状态较多的部署，以及本机控制进程异常退出。与业务根因、任务总耗时、通讯录或知识命中无关。

## 空值核验

原始金额没有值时，按已核实业务规则使用`missing=empty`保留空白。`finalize_report`核对已知金额与独立查询基准，并在totals记录`knownCount`、`missingCount`、`referenceMissingCount`、`missingPolicy`和说明。所有金额未知时total为null，不称合计为零。

数据粒度不同导致来源与基准空值数量可能不同，因此不简单比较空值行数；完整对象/组合行键覆盖和独立同口径金额基准仍必须通过，业务依据须由Agent确认。不得把不同范围的“已知合计碰巧相同”当同口径证明。CSV仍保留所有行和空白。最终文件及绑定配方逐行复算仍执行。

`missing=zero`仍须有业务依据；基准本身的null不能猜成零。算术运算中留空金额仍不允许参与加减/取较小值，真正格式/精度错误按列与行号报告，不泄漏原值，不靠补零/丢行或放宽精度绕过。

## 状态读取与内存

`JsonStore.select`仅接受程序内部选择函数，先选记录再复制，返回内容与缓存隔离；不是开放给模型的查询表达式。冷读按store实例合并，文件变更仍按签名失效；仍要求单个控制面写者。完整事务依旧串行，不通过共享可变状态省内存。

卡片重试目录、单卡读取、相关问题展示、待处理对话和后台环境检查不再每次复制所有历史任务。完整历史在管理/审计入口保留，不为省内存删除记录。

`/health`新增`stateProjectionPolicy=detached-select-singleflight-v1`、`stateReads`（full/selected/loads）与`processMemory`（rssBytes/heapUsedBytes/heapTotalBytes）。这些是当前诊断计数，不是完整内存保留链跟踪或后台报警服务。没有调整Node堆上限或添加任务耗时/调用截停。排查其他泄漏仍需按证据继续。

## 本机执行进程登记

入口为`npm run start:local`。目录自动位于`<数据目录>/local-executions/`，不新增权限或外部服务。每次fork的实际工作进程启动业务前，私有记录本机/平台、控制父PID、工作进程组PID、jobId和租约；不接受用户或模型指定PID。记录文件为摘要文件名，权限600，目录700，不入Git或共享知识。

POSIX工作进程与子进程处于独立任务组。IPC父连接意外丢失时，工作进程结束自己的组；正常完成正常退出。这不是对执行久的任务添加超时。

local启动器在监听与领取任务前核验登记：同主机/平台、原父进程不存在、原任务的整个进程组不存在、当前job和原租约匹配，才把遗留执行标为中断（已有用户停止则为停止），保留证据和文件、清除旧授权，不自动重跑业务操作。仍有进程、PID已被复用、探测失败时保持隔离。终态/旧租约记录只清理登记，不修改任务。

不支持的边界：Windows未实现等价的整个进程树退出证明；远程Runner、旧版本无登记，以及主机身份改变时不会凭显示名称猜PID或自动收尾，需要管理员确认。旧任务不能靠新登记倒推安全性。该能力不会将历史红卡改绿。

## 升级与验证

无新依赖。先确认无真实在途工作，停稳后备份程序、agentos.json、control-receipts、exports、local-executions及本机配置，再升级重启。旧卡状态修复仍由既有权限和交付路径处理；隔离测试不应给真实用户发测试消息。

验证包括留空/全部未知/精确大金额、独立基准、文件逐行复算、投影隔离、并发冷读合并、热重试禁止全库read、同机租约与进程组门控，以及实际独立测试工作进程断连和正常退出。保存的真实任务数据仅本机离线回放，通过176行、保留88空值，没有生产查询或文件原地修改。

同一冻结约44MB状态的三波模拟投递，峰值约446MB降至383MB、GC后均约129MB；模拟不连接飞书、不写生产状态。这仅是该输入的对照，不是稳定内存上限、生产压力验收或所有泄漏已根治的承诺。Windows/Linux部署另行验收。
