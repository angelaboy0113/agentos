# 报表核验修复与证据接续

版本 1.65.0，更新于 2026-11-05。适用于多对象、多个窗口/期间和分量合并的通用报表，不含业务客户或公式硬编码。

窗口基准核验的 `checks` 支持可选 `referenceKey`。未指定时，如果来源 `sources[].keyColumn` 在基准实际列中存在，优先使用该同名列；否则沿基准配方声明的 rowKey 或 group_key。不同名、不同编码体系或不同类型不能猜测转换，应按真实字段显式指定。错误会显示 source、column、sourceKey、referenceKey；真实数量差异附对象和两个数值。

每个来源分量按它在当前报告主对象范围内实际覆盖的业务键核对基准，禁止重复基准键、遗漏该分量对象或金额不一致。允许两个分别覆盖不同对象的分量组合成一张完整报表；原始主对象集合仍独立核验，不能拿单户分量冒充完整报告。保持不同原始查询要求、逐对象核验、精确十进制、列/金额/实际文件核验，不能关闭校验换取绿色。

`finalize_report`、`refresh_report`、`enrich_dataset` 的输入失败会把本次原始结构化参数和错误分类保存到当前任务、当前环境 `tool-results`，返回 resultRef。用 `list_tool_results` 定位，`read_tool_result` 读取，再只修失败分量；不要反复检查已证实一致的数据，或因历史参数不见而重跑业务查询。证据沿已有授权/目录边界及凭据脱敏规则保存，不能跨系统/环境借用。诊断存储失败保留原始错误，不让第二个异常掩盖第一故障。

维度左关联未匹配时，`lookupChecks[].joinDiagnostic` 返回实际 sourceColumn、targetColumn 与有限值样例。先比较编码和名称列、类型及空值，不将未匹配补零、不自动交换业务列或改写源数据。样例仅为定位，完整范围仍以数据集和核验为准。

迁移保留整个任务 datasets、tool-results 和核验文件。无新增依赖或任务总耗时/调用数上限。测试覆盖独立窗口的业务键、显式错误键、真实差额拒绝、分户分量合并完整范围、失败参数跨重启/跨scope拒绝和维度编码/名称未匹配。macOS 实例原数据隔离回放与正式部署分别记录；不把本地计算毫秒数当成新问题端到端性能。


`finalize_report` 在对象覆盖及来源完整性通过后，一次检查全部声明的独立分量。正确性输入错误汇总为带 checkIndex、source、column 的清单；未知金额与已知基准不相容时还给出双方已知/缺失计数。只要有一项失败，仍不产生最终核验回执。权限、磁盘和非输入错误立即中止，不批量吞掉。缺少必需检查、真实差额、同源自证和空值补零规则保持。

规划状态保留更长的当前诊断摘要，完整错误及原参数继续通过本任务 resultRef 恢复；这不是扩大任务时长或查询授权。修正后使用原完整来源复核，无需重新取得已正确数据。大量分量的诊断超过摘要时应续读 resultRef，不能只处理可见的第一项。


草稿生成结果新增`finalization`，包括保持兼容的requiredChecks、populationCandidates和checkCandidates。候选仅来自当前任务已授权范围的已核验目录/内存数据：范围候选具有相同业务键集合，数值基准候选排除共享同一原始查询的来源。它们不是原始需求完整范围或业务筛选正确的证明，不自动选择/换口径或通过核验；别名不同、派生基准等原有显式调用继续兼容。候选列表为有标注的展示子集，更多来源可用list_datasets分页；工具复用目录元信息，不为了建议重复扫描所有大明细。

当finalize_report的REPORT_INPUT错误需要在另一个已配置、同系统同分级、无需新增审批的数据源补齐独立证据时，可以调用continue_environment并传repairResultRef，必须引用本环境最新持久化的真实失败。程序核验工具类型、错误分类、当前未解决项、同任务有效草稿、原始失败参数、目标范围与实际授权，再发起新环境领取。普通查询/权限/认证/超时错误不能借此跳过；测试生产或其它系统不会自动开放。

失败仍持久化为未通过。下一阶段携带原草稿/核验参数和错误，不能以补查/切换成功当作完整任务完成。只有实际finalize成功、文件ID和verificationHash绑定后，才登记reportRepairResolution并清除相应参数修正标记；最终业务范围、实际文件内容和发送仍按原独立审阅。重启依据同一已保存交接恢复，失效范围、改权限或缺少真实失败引用会回原修复流程。此为执行器实际能力，不仅是提示词。
