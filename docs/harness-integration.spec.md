# AgentOS 工程规范接入与角色交接

## 目标与来源
以用户《AI 开发规范》v1.1.0（读取revision334）为工程基线，原规范只读不修改。来源：https://weilongmeiwei.feishu.cn/wiki/MDHbwEZSKi1kifk8zKvcm18Dnpg 。AgentOS手册只承载适配、角色职责、执行机制和部署验收，不创建第二套STO定义。

## 本次交付
- STO按来源指SDD/TDD/ODD组合；ODD为Observability-Driven Development。结果导向不是ODD的替代定义。
- config/harness.json登记来源版本，common.md承载适配规则，角色文件定义输入/步骤/产物/退出/权限/返工。
- Runner任务前加载共同规范和角色，缺失时失败关闭，不退化为短提示词；计算规范及角色包指纹。前序带指纹且不一致时阻断任务，不静默中途换标准。
- 新结果增加handoff：工件、验收项、风险与返工责任。Runner校验工件真实存在于工作区且非敏感路径，计算指纹；必需验收失败/未执行不能ready。PM需要PRD/Spec，实施开发需要Spec和通过证据，QA需要独立验证证据；只读及受理不强制写文档。
- 前序上下文限量且按角色投影；审计/QA不接收完整开发聊天或自评正文，以原始工件/检查引用为线索重新核验。历史聊天按项目筛选，兼容未知旧项目历史时不注入。
- 保留审批、取消、幂等、只读限制、原工作区策略和模型；不新增机器人、不自动安装依赖、不修改AI规范。

## 强制与软约束
工件路径/存在性/哈希、结构完整、必需验收状态、规范包变化是程序检查。PRD内容质量、AI自报测试真实性、PM/QA是否严格按岗位操作仍需实际独立验证和宿主机安全控制，不能以JSON或提示词冒充证明。verifyCommands执行失败继续阻断；未配置不宣称CI通过。

## 非目标
本次不取消人工审批，不启用无限自动返修、不新增数据库/向量库，不改多仓写入隔离策略，不承诺分布式或严格多租户隔离。返工先产出责任人与证据，由负责人及真人授权发起后续工作。
