# 撤回原提问后停止执行

版本：1.115.0。适用于所有使用飞书消息读取接口的助手，无需新增撤回事件订阅或扩大权限。

控制面启动撤回观察器，每10秒尝试一次。仅检查运行、排队、等待接续的任务、正在处理的对话和待投递结果所关联的原消息/话题；同一机器人、群、消息去重，最多4路消息读取并行。消息读取失败、超时、无返回、身份/群不匹配不视为撤回。只有同机器人身份读取到精确消息ID、原会话ID且 `deleted=true` 才执行撤回处理。传输耗时与平台可见延迟可能使实际发现晚于10秒，不承诺严格实时。

- 撤回原问题：停止该问题的任务和对话。撤回整个根话题：停止绑定该话题的子问题。不同机器人分别使用自己的身份处理，跨群/项目不串用。
- 只撤回普通补充消息：仅取消该条未完成的理解/投递，不取消原问题已经执行的调查。已经被任务接收的补充不做猜测式反向修改；要停止整项任务，应撤回原问题/话题或使用停止按钮。
- 排队及等待任务直接取消；运行任务先 `cancelling`，沿原租约控制轮询发出 AbortSignal，必须取得工作进程退出确认后才为 `cancelled`。无法确认退出时保留停止异常，不假称停止，也不强行杀其他任务。
- 理解问题的模型调用使用独立对话 AbortController，不中断其他用户。迟到结果不得重新创建任务、领取任务或发布卡片。
- 原卡、文件、截图、完成提醒、表情及接待/自动恢复待办停止后续投递；已送达消息、证据、素材、凭据和审计保留，不伪造已发送回执。

已发出的远端请求可能已开始计算或计费，撤回无法撤销已消耗token；收到取消后停止后续工作，并尽快结束可取消的本机进程/请求。业务数据库无写入或回滚。观察器只读消息；不需要给模型添加工具或让模型判断是否撤回。

验收：运行中、排队、等待、理解阶段、跨机器人/群、只撤回补充、重复/重启、API故障以及待投递抑制回归；部署后需用本人账号真实发题、运行中撤回并核对原消息deleted、cancel_requested及processesExited/取消终态，不把单元回归当作原生端到端验收。测试话题成败均撤回。

配置和迁移：此为控制面内置行为，无私有配置/凭据/新依赖；迁移必须携带新增模块、测试、本文档及完整现有运行数据。只验证当前Mac，不宣称其他操作系统或完整跨机迁移通过。回退需空闲并保留新产生的withdrawnAt及cancelled审计，不能倒灌旧state使已撤回任务复活。

已确认撤回卡片保留原revision/投递回执，并记录绑定问题、身份与原payload摘要的停止投递凭据。维护空闲判断仅对该精确内容识别为已退役；payload或身份变化重新保护，真实在途worker仍阻止发布。不会通过把未发消息标已发来清空队列。
