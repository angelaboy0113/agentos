# 飞书群 PRD 需求工作台

## 使用

在启用的群中 @ 对应系统助手说「我要做 PRD」「我想做个需求」「我需要写一份需求文档」等日常表达即可开卡。可正文描述，也可只贴飞书在线文档链接作为初稿。助手用原应用身份核验群共享和读取权限，读取正文与表格内容。已在消息或初稿明确的参考环境可直接使用；未指定时默认参考正式环境。生产映射缺失或确认范围有矛盾时在卡片说明。初稿内的图片通过飞书原生素材预览读取，以原助手身份绑定为当前需求的视觉附件，在同一 Codex 会话分析。没有预览权限或素材无法解析时保留正文、表格和缺图位置。文档无法读取时，卡片保留需求并提示怎样补齐。

初稿或后续说明缺少会影响范围、角色权限、数据含义、计算规则、状态流转或关键交互的业务决定时，助手在原话题 @ 发起人。发起人在卡片输入框填写需求或粘贴初稿链接，点「提交补充，继续整理」。交付后原卡保留「提交改版」入口。执行中或部分完成时也可以填写，补充将在当前轮结束后沿用同一会话处理。需要补图时，可以将图片插入已共享的初稿，再在卡片中提交更新后的链接。多个助手接收同一根消息时，由先取得需求归属的助手接续。其它成员可直接编辑已经共享的评审稿。

Assistant 使用现有只读调查能力，按需核对本系统固定源码与授权入口；相关系统沿已有跨系统授权读取，未登记的对方源码或网页标明待确认。已确认规则、建议和技术证据分别记录。本阶段输出评审稿，既有业务写权限、应用发布和正式审批均与 PRD 隔离。

提交补充成功后撤回同一轮助手的补充提醒。信息齐备后自动生成并交付飞书评审稿。Runner 复用同一任务和原生 Codex 调查线程，生成具有标题、强调文字和表格的 Markdown，以及以真实页面截图为底图的 PNG。原型必须取得对应系统和环境的真实目标界面截图。需求工作台使用受控浏览器打开目标页面，确认当前地址及可见详情标题，再保存脱敏像素截图。程序核对截图所属的任务和环境。补充业务口径后，已核验且适用的现场截图可以在同一需求继续使用。新建或改版的 PRD 将真实脱敏截图作为 Codex 原生图片编辑的输入，提交业务改动说明及其截图区域。程序只取生图结果中指定区域的像素，识别出的品牌区域和其余区域沿用原截图。只有产物具备原生编辑和真实截图的绑定记录，才可交付。Codex 原生工具可选图像模型时请求 Image 2，返回具体模型时核验其版本，未返回时记录原生工具及图片出处。截图保留已识别的静态文字、安全的同源品牌图片及导航图标，继续脱敏业务内容。原型不通过时，在原卡显示「原型正在修订」，自动修订需要调整的图片，重新核验后交付。PRD 的自动恢复和受阻只更新原卡；需要确认业务口径或定稿送达时才发送对应通知。重复验收没有进展或存在无法继续的阻碍时，卡片保留已有工件并展示具体问题。多张图各自核对当前轮的截图凭据，并在对应需求段落下插入；确认位置和图片回读后再分享。源码和用户参考图用于定位与说明。只修图的轮次可在完成本轮正文回读核验后，使用同一需求既有正文。没有截图时保留需求及取证缺口，暂不生成原型或交付完整评审稿。主需求会话保留。结果核验后，以已核实的授权用户身份建立飞书新版文档，回读标题、原生表格和图片，给这一个群授予编辑并回读权限，然后在原需求卡更新链接。改版沿用同一需求卡和会话，每一版单独交付飞书文档，保留既有版本。新版正文在原段落或表格单元格中用浅黄色标出新增或改写的文字。原卡保留上一版链接，可核对已删除的内容。群成员在飞书里的手工编辑通过原卡说明后纳入下一版。涉及界面改动时，在该需求章节紧邻原型说明截图来源和拟议改动。正式同版审批、只读快照与结构化差异合并属于后续。

## 业务定稿

群里可以只发「我要做一个 PRD」并贴一条共享给本群、助手可读的飞书在线文档链接。工作台读取链接正文、表格和可用图片。机器人能读初稿但无法列出共享成员时，可由本群同助手已配置的文档发布账号只读核验共享名单；初稿正文仍通过机器人读取。遇到冲突、候选口径或未定项，在原卡逐条提问。发起人提交部分答案后，未回答的业务决定继续留在卡上，不交付定稿。初稿已经说清的口径可直接沿用。

正文以「摘要」开篇，用一段大白话讲清使用人、遇到的问题和改完能做什么。定稿固定依次保留八章：摘要、用户和使用场景、业务范围、操作流程、功能与业务规则、业务口径对齐、跨系统分工、页面设计与原型。没有适用内容的章节写「无」。业务口径对齐逐项写明已确认的结论及其业务来源。页面原型放在对应功能小节；没有界面变更的需求只交付正文。测试用例、验收标准、测试边界、版本记录与研发实现放在独立工作里，最终 PRD 正文不包含这些内容。卡片保留确认记录和技术证据。卡片保留新版和上一版链接，正文仍在改动处标黄。既有已交付的文档保留，后续提交改版按新的正文结构处理。

## 配置

现有实例 data 目录的同级目录放私有 `prd-workspace.local.json`，参考 `config/prd-workspace.example.json`。chatIds 只列获准启用的群。在 publishers 中按发起助手的 CLI profile 分别登记用户 OAuth、该应用下的所有者 open_id 和允许共享的群。每个应用单独授权，交付和恢复使用原卡的应用。旧 publisher 配置继续支持它自身的助手及已有文档接续。OAuth 由飞书 CLI 持有，配置不包含令牌。缺用户授权时，仍可继续分析并保留已核验文件。授权完成后，程序从原卡自动续投已核验稿件。超时导致创建、插入或分享结果未知时保留阶段，维护者核对回执后接续，避免重复创建。

新任务使用本实例现有 `native-tools-v1`。同一需求跨补充保留原任务、问题和工作区检查点；Codex 读工具仍核对原项目、环境、群和身份。不同需求分别拥有自己的线程。普通任务沿原流程运行。

## 验收与回退

检查澄清 @ 的接收者、卡片提交、旧按钮拒绝、同话题同会话继续、多助手同事件去重、同系统同环境的视觉证据绑定与无导出指令时的交付。真实交付需回读用户身份、原生样式和表格、图片、群协作者编辑权限及卡片链接。回退先等待空闲，保留正在进行的 PRD 任务、文档链接和投递阶段记录，再关闭 pilot 配置并按原部署守卫回退代码。
