# 环境工具排查规格与实现记录

2026-09-15。兼容固定模板；新增明确 opt-in 的 `queries.<id>.mode=investigate`。实现与使用说明以 environment-access.md 为准。

## 问题与结果

旧解析器仅匹配字面 JDBC，含同文件变量的真实配置被误报零条且阶段成功。新解析器使用 YAML 数据解析/Properties键值、受限引用展开，提取主机、端口、库名；零端点或未解析引用为 partial。

固定模板不允许模型跟进结果。新模式把已批准的整个有限排查范围绑定为一个 Job，独立临时 Codex 以结构化 JSON 选择工具，Node连接器执行。用户目的绑定在既有 parameters[0] 中，配置指纹绑定工具类型、命名空间/表范围与限额；不改状态文件结构、审批回调或历史记录。

## 执行约束

- 受理仍不执行环境工具；Runner领取后才启动连接器。
- 每步工具执行前、模型返回后均复核批准有效性；原有取消通过任务进程组结束，未创建额外脱离进程。
- 首步固定连接检查，之后模型选择已列明的工具。工具结果不是指令。
- `conversationServerArgs` 禁用shell、浏览器、计算机、插件、应用、联网搜索与多Agent能力；模型不通过这些原生能力执行环境访问。
- 不读取或返回Nacos配置中的数据库凭据，不自动跨环境，不把环境结果注入群共享记忆。
- Nacos只支持批准namespace内的列表/固定引用读取；缺失跨文件引用不会自动扩大读取。
- MySQL工具用本库BASE TABLE普通列元数据构造SQL，不接受原始SQL；不支持任意联表、SQL函数或浏览器自动化。
- 生产审批是一次有限范围的多步排查，不是逐SQL批准；卡片显示范围与调用次数。
