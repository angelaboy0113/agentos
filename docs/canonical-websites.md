# 用户确认的业务域名与旧入口更正

业务网页优先采用对应项目、UAT/PRD下用户确认的域名，不用DNS解析结果、后端API地址或旧联调IP代替浏览器地址。源码Agent仍先搜索配置、部署和文档，找不到可靠入口才询问。IP页面资源加载不完整不能直接证明前端故障。已确认域名不代表已登录或业务数据已核实。

## 本机配置

在私有 config/environments.local.json 顶层可保存 websiteAliases 数组：

```json
{"websiteAliases":[{"projectId":"your-project","tier":"uat","from":"http://192.0.2.10/mp-runtime/","to":"https://uat.example.com/"}]}
```

示例地址必须替换为该团队确认的真实入口。只进行项目、环境和完整入口路径的匹配（末尾斜杠等价），不将一个IP上的全部应用重定向；Nacos、数据库和XXL-JOB地址不随业务站点更正。禁止含凭据/查询串的网址、重复、循环或链式映射。

目标网站应按既有website环境结构登记。新websiteQuery可按更正后的URL自动登记；已有环境ID生成新计划时，目标尚未登记会明确拒绝，不能回退到旧IP。目录隐藏已被更正的旧入口，展示目标域名。目标网站的成员策略与审批人用于新计划，不能继承旧网站的批准。

旧环境记录及其配置指纹保持不变，不改写已批准/运行中的任务；旧任务需停止后重新发起才能改用域名。更新程序和本机配置后空闲重启。域名与IP是不同origin，原IP登录Cookie不会复制给域名，首次使用域名可能需要登录；后续有效域名会话可复用。

## 维护与验证

真实域名和映射保存在部署电脑的私有配置，不硬编码到公开代码。配置应在无运行任务时备份后修改。发现域名有误，核实后更正私有映射与目标登记，不通过关闭TLS验证解决。

回归覆盖精确路径、不同项目/环境、其他服务不受影响、目录、新计划使用目标权限、旧批准不被静默重定向以及非法映射。模拟测试不证明真实业务网站可登录。Mac实机可额外检查根地址HTTP响应；302仅表示重定向，不是业务查询成功。Windows本次未实机验收。
